# 判定器的公开数据和附带网页 SDK（2026-10-29 用户定方向和四件事；第 11 节怎么做和文案待用户看）

代码判定红包现在的玩法都比较“孤独”：每个人各自打一行字、各自拿结果，看不到红包现在是什么样，判定器也影响不了红包本身，形成不了人和人之间的互动（别的红包站的刮刮乐就做得到）。用户要的是最基础、最通用的能力，不是一个个做组件（2026-10-29：“我们穷举不完所有的功能”）。

这份文档的思路：**判定器管规则，附带网页管界面，本站管身份和钱**。判定器多两样能力（公开数据、对红包的两种影响），附带网页多一个 SDK（读公开数据、替用户提交），界面完全由红包作者自己做，放在哪儿托管都行。

相关文档：[代码判定红包](programmable-hongbao-design.md)（协议第 1、2 版）、[判定器广场](judge-square-design.md)（协议第 3 版、判定器复用）、[附带网页](attached-page-design.md)、[红包页](redesign/05-hongbao.md)、[指令框](redesign/02-shell.md) 第 4 节。

## 0 说法

| 说法 | 意思 |
|---|---|
| 公开数据 | 判定器每次判定后交出来的一份数据，所有人都看得到（游客也是），比如“安全区间 23–67”、刮开了哪些格子。判定器自己的 state 照旧只有代码看得到 |
| 动态 | 判定器写给所有人看的一句话，比如“@某人 踩中了炸弹”，按时间排在红包页上 |
| SDK | 本站给附带网页的一小段脚本，网页靠它读公开数据、替用户提交 |
| 协议第 4 版 | 第 3 版加上公开数据、动态和提前结束；旧版本的判定器照旧 |

附带网页就是现有的[附带网页](attached-page-design.md)，不是新东西：显示位置照旧（宽屏在红包窗口旁边，窄屏是底部抽屉，能全屏），不点“加载网页”不加载。这份文档只给它加一个 SDK，再让判定器能带一个附带网页的地址（第 4 节）。

## 1 分工

- **判定器 = 规则**：在沙箱里跑，决定发多少，读写共享的 state，决定公开什么、写什么动态、要不要提前结束。钱和规则只认它。
- **附带网页 = 界面**：画玩法，读公开数据、订阅变化，替用户提交、拿回结果。它是第三方的代码，本站不信任它：它能做的只是用户自己本来能做的事。
- **本站 = 身份和钱**：登录、提交前的确认、冷却、人机验证、领取范围、发放，全部照旧在本站这边。

三条边界：

1. 网页**改不了红包**：改红包的只有判定器的判定结果。
2. 网页**拿不到身份**：没有本站的 Cookie、登录凭证，不能转账、不能发红包、看不到别人的输入。
3. **没有网页也能玩**：指令框照样能打字提交，红包页照样显示公开数据的文字摘要（第 2 节）。

## 2 判定器协议第 4 版

在第 3 版上加，`judge()` 的返回（Verdict）多三项，都可选：

```js
return {
  ok: false,
  message: "安全！",
  state,                                  // 照旧：共享的，只有代码看得到
  view: {                                 // 新：公开数据，整个换掉
    summary: "安全区间 23–67，还剩 3 颗炸弹",   // 给没有网页的人看的一句话
    data: { low: 23, high: 67, bombs: 3 },     // 给网页的，什么结构都行
  },
  announce: "@lafish 猜了 50，安全",       // 新：一条动态
  end: false,                             // 新：true 就在这次判定后提前结束
};
```

- **view（公开数据）**：
  - 写了就整个换掉，不写不变；所有人都看得到，游客也是。
  - `summary` 最多 200 个字，纯文字，本站自己画（指令框和红包页）。`data` 是任意 JSON，给网页用，最大 16 KB，嵌套最多 100 层（同 state）。
  - 每次判定后存下来，通过红包页的实时推送发给所有在看的人（和“已判定 N 次”一起，最多一秒一次）。
  - 开放时的初始样子：新增一个可选导出 `setup(params, hongbao)`，开放时跑一次（同 `check()` 算一次沙箱使用），可以返回初始的 `state` 和 `view`。不写就是空的。
  - 秘密照旧放在 state 里。放进 view 的东西就是公开的，开发包的检查会在 view 里出现保密参数的值时报警告。
- **announce（动态）**：
  - 一句纯文字，最多 100 个字，每次判定最多一条。
  - 红包页加一块“动态”，最新的在上面，实时推送；只留最近 100 条在页面上。
  - 判定的人是谁，由本站在前面写上头像和昵称，代码不能冒充别人。
- **end（提前结束）**：
  - 只在真的判定了的提交里有效（出错、超时不算）；这次判定先照常结算，再结束红包。
  - 结束以后和红包作者手动“提前结束”一样：没发出的钱照现有规则退回，红包页写“已结束”，原因写“判定器结束了这个红包”。
  - 用途：刮刮乐刮完了、炸弹全踩中了、接龙接不下去了。
- **不变的**：钱只发给提交的这个人，奖池和份数不能改，保底封顶照旧，第 1–3 版的红包照旧。
- **记录和核对**：view、announce、end 都进判定记录；`npm run replay` 能重放出每一步的公开数据，结束后公开代码时核对得上。

## 3 附带网页 SDK

### 3.1 怎么接

网页里加一行：

```html
<script src="https://hb.lafi.sh/sdk/v1.js"></script>
```

文件跟着版本走，`v1` 不改行为，只修错。SDK 用浏览器的跨窗口消息（postMessage）和红包页说话；本站只接收来自这个附带网页那个 iframe 的消息，并且核对它的来源是填的那个网址。

### 3.2 能做的

| 能力 | 说明 |
|---|---|
| `hb.ready()` | 等红包页接上，拿到：红包的公开信息（标题、状态、剩余份数和奖池、截止时间、已判定几次）、看的人登录没有（登录了给昵称，不给编号）、浅色或深色 |
| `hb.view()` / `hb.on("view", fn)` | 读判定器的公开数据，变了就通知 |
| `hb.on("hongbao", fn)` / `hb.on("announce", fn)` | 红包公开信息变了、来了新动态就通知 |
| `hb.submit(input)` | 替用户提交一次（经过本站确认，见 3.3），拿回结果：判定了没有、领到没有、多少、代码的回复；没判定的写原因（冷却还剩几秒、要登录、不在领取范围、代码出错等） |
| `hb.mine()` | 读这个人自己在这个红包里的提交记录（同“我的提交”） |

做不到的：读本站的 Cookie 和登录凭证、看别人的输入、转账、发红包、改红包、绕过冷却和人机验证。

### 3.3 提交前的确认

`hb.submit()` 不会直接发出去，要用户同意。三种做法：

1. **每次都确认**：红包页这边弹一下“替你提交「50」？”，最安全，但玩起来每点一下都要多按一次。
2. **第一次问，之后不问**：同一个红包第一次提交时问“允许这个网页替你提交吗？它提交的内容会出现在你的提交记录里。”，答应以后这个红包里不再问；每次提交照样出现在“我的提交”里（判定中的那张卡）。
3. **只在指令框里填好**：网页只能把内容填进指令框，按提交的还是用户自己。

**定了 2**（2026-10-29 用户定）：玩法流畅，提交照样有记录、有冷却、有人机验证，最坏也只是替你多试几次，钱不会少。

### 3.4 没登录的人

网页照样加载、照样读公开数据；`hb.submit()` 由本站弹出登录卡片，登录回来以后网页再提交一次。

## 4 判定器带一个附带网页的地址

为了判定器广场里的复用：别人用你的判定器发红包，界面也要能跟着过去。

- 判定器的 `meta` 多一项 `page`：附带网页的地址，规则同附带网页（https，不能带用户名和端口，不能写 IP 和 localhost，不能是 linux.do 和本站，最多 500 个字）。
- 用这个判定器发红包（自己的、广场上别人的、站长精选）时，附带网页一项替你填好，可以改，可以删。
- 判定器广场的卡片和判定器页写“带附带网页”，能点开看。
- **谁能用**（2026-10-29 用户定）：附带网页原来只给 🐟额 PLUS（和站长）。判定器带的附带网页，用在代码判定红包上时人人都能用；自己另填网页的，仍然只给 PLUS。总开关照旧管所有附带网页。

## 5 指令框和红包页

- 指令框的代码判定作用域整理成三段（另见 [02](redesign/02-shell.md) 第 4 节，做的时候改）：
  1. **红包状态**：公开数据的一句话（`view.summary`）和最新一条动态；
  2. **输入**：输入框；“原样提交：……”的规则收进 ⓘ 提示，字数放进框里；
  3. **我的提交 · N 次**：统一的一种排法（第几次和时间、结果；代码的回复；你的输入），判定中也是这一行。
- 标签只写红包标题，不再“代码判定 · 代码判定 · 5 份”。
- 红包页红包皮下面：公开数据的一句话（`view.summary`），再下面是“动态”。

## 6 托管：不做

- 不替红包作者托管网页：要做就是一个独立的静态网页托管项目（独立域名、防钓鱼、下架、证书），不划算。
- 推荐 [Cloudflare Drop](https://www.cloudflare.com/drop/)（2026-07 上线，[更新记录](https://developers.cloudflare.com/changelog/post/2026-07-08-cloudflare-drag-and-drop/)），也可以用 GitHub Pages、Vercel、Netlify 等：
  - 把文件夹、zip 或一个 HTML 文件拖进去，几秒后得到一个 `workers.dev` 地址；只能放静态文件（HTML、CSS、JS、图片、字体），最多 1000 个文件、单个 25 MiB。
  - **不认领只活 60 分钟**：60 分钟内点“Claim”登录或注册一个免费的 Cloudflare 账号，才变成永久的；不认领就删掉。接入说明要把这一步写在最前面。
  - **文档上默认能被嵌入**：Cloudflare 的静态资源默认只加 `Content-Type`、`Cache-Control`、`ETag`、`CF-Cache-Status`，不加 `X-Frame-Options`，也没有 CSP 的 `frame-ancestors`（[Workers 静态资源的 headers 文档](https://developers.cloudflare.com/workers/static-assets/headers/)，Pages 同样）。想只让本站嵌入，在文件夹里放一个 `_headers` 文件，写 `Content-Security-Policy: frame-ancestors https://hb.lafi.sh`。
  - **实测（2026-10-29，用户刚拖上去、还没认领的一个页面）**：命令行请求和浏览器直接打开，都先被 Cloudflare 的安全验证拦下（“正在进行安全验证”，要点“请验证您是真人”）；这张验证页带 `X-Frame-Options: SAMEORIGIN`，**嵌在别的网站里显示不出来**。在 iframe 里过了验证也未必有用：验证通过记在那个网站自己的 Cookie 上，浏览器会把它当第三方 Cookie 拦掉或分开存。
  - 还不知道的：这个验证是只对没认领的临时页面（防钓鱼），还是认领以后也有；是对所有人都弹，还是只对像自动程序的访问（我们这边的浏览器）弹。要用户在自己的浏览器打开看看，认领以后再测一次。**测清楚之前，接入说明不能推荐 Drop。** GitHub Pages、Netlify 平时没有这种拦截（Vercel 的预览部署默认要登录才能看，正式部署才公开），也都要先实测能不能嵌入再写进接入说明。
- 网页不受版本锁定：判定器的代码有指纹、开放后不能换，外部网页作者随时能改。公平靠判定器，网页最坏只能“显示得不对”；对策是本站自己显示公开数据的一句话（权威版本），替你提交时本站这边看得到真正提交的内容。

- `kit/page/`：网页模板（一个 HTML 文件，接好 SDK），SDK 的类型定义，本地的“假红包页”（在浏览器里打开，模拟红包页给网页发数据、收提交，提交交给本地的判定器跑），教程写清楚“改完拖进 Cloudflare Drop，认领，把地址填到 `meta.page`”。
- 给 AI 的说明（AGENTS.md、`/help/code`、`/help/page`）同步更新。
- 两个完整样例，判定器加网页：
  - **数字炸弹**：1–100 里藏一个炸弹，大家轮流猜，公开数据是当前的安全区间和猜过的数；踩中的领一份，自动埋下一颗；份数发完结束。
  - **刮刮乐**：一张 5×5 的卡，每格背后是一个金额或“谢谢参与”（开放时封存，结束公开），每人刮一格；公开数据是刮开了哪些格子、刮出了什么；刮完 `end`。

## 10 不做

- 替红包作者托管网页（第 6 节）。

## 11 怎么做和每一句新文案（2026-10-29 用户看过，11.5 也看过）

### 11.1 分几次做

1. **协议第 4 版**：
   - 先把第 3 版的运行时冻结（和第 1、2 版一样，放进 `kit/runtime/frozen/v3.json`，哈希测试守着），已经开放的第 3 版红包照旧跑它。
   - 新运行时：判定结果读 `view`、`announce`、`end`，导出 `setup()` 开放时跑一次；`tests.json` 能断言这三样；`npm run check` 在公开数据里出现保密参数的值时报警告；`simulate`、`replay` 打出每一步的公开数据和动态。
   - 接口：存公开数据和动态，`end` 走提前结束。部署和重新运行都在第 4 版上跑；第 3 版的判定器照样能用（怎么开放见 11.5）。
2. **红包页和实时推送**：红包皮下面的“红包状态”和“动态”，实时推送多两种消息，判定器结束的红包怎么写。
3. **指令框整理**：代码判定作用域分三段（第 5 节）。
4. **附带网页 SDK**：`/sdk/v1.js`，红包页这一侧的消息处理，第一次提交前的确认；`/help/page` 加一节“接上 SDK”。
5. **判定器带附带网页**：`meta.page`，发红包表单替你填好，没有 PLUS 也能用判定器带的这一个，广场和判定器页写出来。
6. **开发包**：网页模板、SDK 类型、本地的“假红包页”、数字炸弹和刮刮乐两个样例；实测附带网页常用的几个托管（第 6 节）。

每一部分做完先在本地给你看，第 1、2 部分一起发（第 2 部分要用第 1 部分的数据），其余每部分单独发。

### 11.2 存什么

迁移 0051：

- `activity_code` 加 `view_summary`（文字，≤ 200 字）、`view_data`（JSON 文本，≤ 16 KB）、`view_at`，和 `setup_ciphertext`（setup() 开放时的回答，加密，给完整记录和重放）。
- `code_judgments` 加 `view`（这次写的公开数据，没写是空）和 `ends`（这次结束了红包）。
- 新表 `activity_announcements`：红包、第几条、谁（提交的人）、哪次判定、文字（≤ 100 字）、时间；只能加不能改。
- 第 4 版要 `activity_code`、`judge_versions`、用量三张表的协议检查多一个 4：SQLite 只能重建这三张表，表上和引用它们的触发器原样重建，多管 view、setup 几列。
- `activities.end_reason` 多一种 `judge`（判定器结束）。
- 判定器的 `meta.page` 存在版本的声明里（已有的 `declarations`），不加列。

### 11.3 新文案

**红包页**（红包皮下面，印章那句话下面；有公开数据才有）：

- 一块浅色的面板，小标题“红包状态”，下面是判定器写的那句话（`view.summary`），变了就淡入换掉。
- 再下面“动态”：每行头像、昵称、时间（今天的写“18:47”），下面一行判定器写的话；页面上放最近 5 条，多了标题右边“全部 N 条 ›”，打开“动态 · N 条”弹窗，滚到底自动再读 20 条，读完写“已全部加载”。新的一条从上面滑进来。没有动态时没有这一块。
- 判定器结束的红包：状态同“已提前结束”（印章“完”），印章下面那句写“判定器结束了这个红包”；红包记录的行里写“判定器结束”。没领的钱照提前结束的规则退回或不再发。

**指令框**（代码判定作用域，第 5 节）：

- 标签只写红包标题，前面照旧是花括号。
- 输入框下面：
  - 有公开数据时，“红包状态”和那句话（同红包页），下面一行最新一条动态（“@昵称：……”）；
  - “我的提交 · N 次”和每一次（第几次 · 时间，右边结果；下一行代码的回复；再下一行你的输入，等宽小字）；最新一次只在底色上和别的不一样。

**网页替你提交**：

### 11.8 第 4 部分做时定的（2026-10-29，待用户看）

**接法**：`<script src="https://hb.lafi.sh/sdk/v1.js"></script>`，网页里多一个全局的 `hb`。SDK 只和加载它的那个网站（脚本的来源）说话，红包页只听这个附带网页的 iframe、并且来源是填的那个网址。文件缓存一小时，任何网站都能引用。

**能力**（细化 3.2）：

| 写法 | 拿到的 |
|---|---|
| `hb.ready()` | `{ hongbao, viewer, theme }`。不在红包页里打开（直接打开、嵌在别处）时报错“没有接上红包页”。 |
| `hongbao` | `id`、`title`、`url`（红包页地址）、`code`（是不是代码判定红包）、`status`（`draft` 未开放、`active` 进行中、`ended` 已结束）、`endedByCode`、`unit`（`LDC` 或 `🐟`）、`shares`（`{ total, claimed, remaining }`，红包没公开份数时是 null）、`pool`（奖池总额，没有时 null）、`deadlineAt`、`judged`（已判定几次） |
| `viewer` | 登录了 `{ signedIn: true, name }`（昵称），没登录 `{ signedIn: false }` |
| `theme` | 现在总是 `light`：本站只有浅色 |
| `hb.view()` | 判定器的公开数据 `{ summary, data, at }`，没有时 null |
| `hb.on(名字, fn)` | `view`（公开数据变了）、`hongbao`（红包公开信息变了）、`announce`（新的一条动态 `{ n, at, user: { name, avatar }, text }`，几条同时来时从旧到新一条一条给）；返回取消订阅的函数 |
| `hb.submit(input)` | 判定了：`{ judged: true, claimed: true, amount: "0.30", unit: "LDC", reply }` 或 `{ judged: true, claimed: false, reply }`（`reply` 是代码的回复，没有就不带）；没判定：`{ judged: false, reason, seconds?, message? }` |
| `hb.mine(next?)` | 自己的提交，新的在前，一次 20 条：`{ total, items: [{ n, at, input, claimed, amount?, reply? }], next }`，再读传 `next`；没登录时 null |

**没判定的原因**（`reason`）：

| reason | 意思 |
|---|---|
| `denied` | 看的人没允许网页替他提交（领自己的红包时点了返回也是） |
| `login` | 没登录：红包页弹出了登录卡片，登录回来以后网页再提交 |
| `cooldown` | 冷却中，`seconds` 是还剩几秒 |
| `busy` | 上一次提交还没有结果 |
| `human_check` | 没完成或没通过人机验证 |
| `not_in_scope` | 不在领取范围 |
| `already_claimed` | 已经领到过（每人领一次） |
| `not_open` | 还没开放 |
| `ended` | 红包已结束 |
| `paused` | 代码连续出错，暂停领取 |
| `judge_failed` | 这次代码出错了，不算次数 |
| `try_later` | 提交的人太多、太频繁，或判定暂时不可用 |
| `invalid_input` | 输入不合规则（空、超过 200 字、有换行），`message` 是原因 |
| `unconfirmed` | 没收到回应，可能已经提交了，用 `hb.mine()` 看 |
| `away` | 看的人不在这个红包页上（网页还开着，但没在显示） |
| `not_code` | 不是代码判定红包 |
| `error` | 其他错误，`message` 是原因 |

**确认**：答应记在这个浏览器里，按账号、红包和网页的网站记；换了账号或换了网站要再问。

**两个样例**：

- 数字炸弹：参数“最大”（默认 100）。1 到最大里埋一颗炸弹，大家轮流猜；猜过的数和安全区间公开。踩中的领一份（剩下的平均分），接着埋下一颗、区间重来；份数领完红包就结束。动态“@小明 猜了 50，安全”“@小红 踩中了炸弹，领到一份，第 2 颗已经埋好”。网页是一排数字格子：猜过的划掉，区间外的变灰，点一格就是猜它。
- 刮刮乐：一张 5×5 的卡，份数（最多 25 份）个格子有奖，金额开放时随机分好、封存，其余是“谢谢参与”；每人刮一格；公开数据是刮开了哪些格子、刮出了什么；奖刮完或格子刮完 `end`。网页是那张卡，点一格刮开。
