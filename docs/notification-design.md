# 私信通知（设计草案，2026-11-15）

状态：第 3 节要发的都定了（2026-11-15）；做完了，2026-11-15 上 Stage。

用户 2026-11-15 提的，前后说法以后面的为准：

- 用社区的隐私邮箱发通知：往这个邮箱发信，就等于在社区里发私信。社区会转成私信，HTML 用不了，要专门设计格式和文案。不是人人都有隐私邮箱，这不要紧：通知有特定目的，不会有发给所有人的。
- 看了第一版：太严了。每人每天不设上限，有必要就发；一次一件事，不合并。按类别关通知可以，要一个单独的页面，个人信息的隐私邮箱那里放一个入口，头像菜单里也要有。
- 发信用社区的邮箱服务器（webmail.linux.do），用户试过 SMTP 能发、次数不限。
- 领红包的人不用知道领了没发出去，也不用知道谁指定了他能领；限时开奖要通知，报了名就可能不再打开、忘了，时间上有跨度。发红包的人付不出钱要通知，分清是余额不够还是每日限额超了；一个红包只提醒一次，第二天还付不出也不再提醒，跟着红包走。站长改🐟额、转出没成功不用通知（转出当场就看到了）；收到打赏、收到转账要，不合并。站长自己收不到（社区不能自己给自己发私信），要处理好，站长也不需要。
- 看了第二版：问定时开放为什么会开不成；红包被站长停用、判定器被撤下可以有；等的红包开放了是面向所有人的，也可以有；三方积分比较特殊，应该有更多，比如审核通过、熔断。
- 看了第三版：定时开放没开成、三方积分的几类都加上。
- 用户：同一个人可能有限制，不同的人可能可以短间隔；单人 20 秒，多人提醒应该更短；做成管理后台的配置。
- 看了 Stage 的试信：文案里不要“钱”：“红包付不出钱”改叫“红包分发暂停”（用户：应该是“分发”，分发失败、积分分发之类），开关分组“钱”改叫“打赏和转账”；三方积分写“积分分发”。
- 做的时候又提：红包广场也加一个“下一次有红包开放时提醒我”，文案我来定；只提醒一次，下一次要回红包广场再打开。

## 0 社区的隐私邮箱怎么回事

2026-11-15 在社区和 IDC Flare 上查的（只读）：

- Connect 登录返回的 `email` 是隐私邮箱，后缀 `@privaterelay.linux.do`，前缀是加密串。每个接入方拿到的同一个人的地址都不一样，只有本站知道这个人在本站的地址。
- 往这个地址发信，社区就生成一条私信：发信人是本站 Connect 应用的所有者，也就是站长的社区账号，收信人是这个用户。私信是锁定的，双方都不能回复；收信人可以举报。社区的说法：隐私邮箱只用来联系、通知，不要用来营销。
- 私信长什么样（用户 2026-11-13 试过）：标题是“【邮件】”加邮件标题；正文从上到下是发件邮箱、邮件标识、邮件标题、正文 HTML（在代码块里原样显示源码）、正文文本（也在代码块里），最后是社区加的“邮件内容仅作通知，请勿回复！……”。
- 本站登录时已经把它加密存在 `users.email_ciphertext`，每次登录更新。正式站 7540 个用户里 6754 个有（2026-11-15）。

由此：

- 正文是纯文本，另附一句话的 HTML（“正文在下面的‘正文文本’里。”）：只有纯文本或者 HTML 是空的，社区都会把正文包进 `<pre>` 当“正文HTML”，同样的内容显示两遍（Stage 2026-11-15）。
- 正文在代码块里：不会自动换行，手机上一行太长要横着滑；链接点不了，只能复制。
- 社区的通知列表、私信列表里只显示标题，看标题就该知道发生了什么。
- 读的人看到的发信人是站长，标题要说明是红包站自动发的。
- 站长自己收不到：私信不能发给自己。

## 1 原则

1. **有时间跨度、本人不在场、又需要知道的事才发。** 当场就能看到的不发。
2. **一次一件事，不合并，不设每天上限。**
3. **跟着事情走，同一件事只发一次。** 每条通知有一个去重键，比如“红包分发暂停”是一个红包一个键，这个红包以后再付不出也不再发。
4. **每类都能关**，在“私信通知”页面上；默认都开。
5. **站长不发。** 站长的账号（`ADMIN_LINUX_DO_IDS`）不生成通知；“私信通知”页面对站长说明原因。
6. **只发到 `@privaterelay.linux.do`。** 存的地址不是这个后缀（很早以前 Connect 给的可能是真实邮箱）就不发。
7. 没有隐私邮箱的人不发，也不到处催他补。

## 2 发信

### 2.1 用社区的邮箱服务器

- 服务器：`mail.linux.do`，465 端口（直接 TLS）。DNS 里 465 优先，587（STARTTLS）次之。
- 发件人：站长的 LINUX DO 邮箱（`名字@linux.do`），私信里“发件邮箱”一行显示它。地址和令牌都是 Worker 机密，不进仓库。
- 登录：用户名是完整的邮箱地址，密码用令牌。
- Worker 用 `cloudflare:sockets` 的 `connect()` 连 465 端口，`secureTransport: "on"`。Worker 连不了 25 端口，465 没限制。SMTP 只用到几条命令（EHLO、AUTH、MAIL FROM、RCPT TO、DATA、QUIT），一次连接可以连着发好几封。

### 2.2 令牌

webmail.linux.do 是 Mailu。Mailu 的“认证令牌”（Authentication tokens）是给某个应用单独用的强密码：它以这个邮箱的身份登录，用在 SMTP、IMAP 这些协议上，代替邮箱密码。它不是 HTTP 接口；Mailu 的 HTTP 接口要服务器管理员配的 `API_TOKEN`，用户拿不到。所以令牌的用法就是**当作 SMTP 的密码**，好处是不用交出邮箱密码，不用了随时删掉。

- “Authorized IP”留空：Worker 发出去的 IP 不固定，填了就连不上。
- 令牌只在创建时显示一次。站长自己存进 Worker 的机密 `NOTICE_SMTP_TOKEN`，不进仓库，不经过对话。
- 社区的说明里写过 LINUX DO 邮箱每天发 50 封；用户试过不限次数。服务器要是回临时错误（4xx），等一会再发；回永久错误（5xx）就记为失败。

### 2.3 队列

要。理由：

- 连 SMTP、握手、发信要一两秒，还可能失败，不能拖慢领取、开奖、付款这些地方。
- 失败要重试，要有记录可查。
- 能控制同时发几封，别把邮箱服务器打满。

做法：

- 表 `notifications` 是发信记录：用户、类别、去重键（唯一）、标题、正文、状态（待发、已发、跳过、失败）、跳过或失败的原因、创建和发出的时间。正文留 30 天，过期删掉。
- 发生事情的地方只做一件事：插一行（去重键冲突就忽略），插进去了就往新队列 `hb-notices-<环境>` 里放一条消息。
- 队列的消费者一次取一批，连一次 SMTP 把这批发完，逐条改状态；失败的按间隔重试，最多 5 次，再不行进死信队列，记为失败。
- 发信排开：社区收到同一秒里连着来的几封，只把第一封变成私信，其余的没了，也没有退信（Stage 2026-11-15）；隔 20 秒发给同一个人的 3 封都到了。所以任意两封之间隔“任意两封之间”，发给同一个人的两封之间隔“同一个人的两封之间”，都默认 20 秒：给同一个人隔 3 秒发 3 封，也只到了第一封（Stage 2026-11-15），不丢的间隔在 3.4 到 20 秒之间。分不清社区是按发信人还是按收信人限，Discourse 默认同一个账号 15 秒才能新建一个话题、每天最多 20 条私信，要问社区；同一批里先发每个人的第一封，再发第二封，谁都不排在别人后面。上次给这个人发信的时间从发信表里查。两个间隔是站长在“网站管理 → 设置 → 私信通知的间隔”里改的（迁移 0067 的 `notice_settings`，带版本号），保存后下一批就用新的（用户：为什么不能做成一个管理后台的配置）。
- 定时任务每次看一眼：待发超过 10 分钟的重新放进队列。
- 发之前再查一遍：这一类他关了没有、地址还在不在、是不是站长。
- 站长页面加一块“私信通知”：今天发了几封、跳过几封（没有邮箱、关掉了）、失败几封，失败的能看到原因。

## 3 发什么

### 3.1 定了的

| | 收信人 | 什么时候 | 去重键 |
|---|---|---|---|
| 限时开奖中了 | 报名的人 | 他报名的限时开奖开奖了，而且他中了 | 红包 + 人 |
| 红包分发暂停 | 发红包的人 | 有人领了，付款因为余额不够或每日限额停下 | 红包 |
| 收到打赏 | 打赏卡的主人 | 每收到一笔 | 打赏 |
| 收到转账 | 收款的人 | 每收到一笔🐟额转账 | 转账 |

“红包分发暂停”只看分发用的是**发红包的人自己的商户**的：🐟额红包是站里的🐟额应用在付，余额和限额是站长的事，不发给发红包的人。余额不够、每日限额超了分开写（第 6 节）；一个红包只发一次，先碰到哪种就写哪种。

第二轮又定了三类：

| | 收信人 | 什么时候 | 去重键 |
|---|---|---|---|
| 红包被站长停用 | 发红包的人 | 站长停用了他的代码判定红包，剩下的退回了🐟额 | 红包 |
| 判定器被撤下 | 判定器的作者 | 站长把他的判定器从判定器广场撤下，带上撤下的原因 | 判定器 + 这次撤下 |
| 等的红包开放了 | 点了“开放时提醒我”的人 | 定时开放的红包到点开了 | 红包 + 人 |

再加一类，也是谁都能要：

| | 收信人 | 什么时候 | 去重键 |
|---|---|---|---|
| 红包广场有新红包 | 在红包广场点了“下一个红包开放时提醒我”的人 | 下一个加入红包广场的红包开放 | 红包 + 人 |

- 红包广场顶上一个按钮“下一个红包开放时提醒我”。点了变成“已设提醒，下一个红包开放时私信你”，旁边“取消”。说法用“设提醒”（用户 2026-11-15 从几个说法里选的）：“在等”不准确，“预约”怪，“订阅”听着会一直收。
- 只提醒一次：提醒发出去，这个人就从名单上划掉，按钮回到原样；想再收到，回红包广场再点。
- 领取范围不包括他的红包不算“下一个”，他接着等下一个他能领的。他自己发的红包也不算。
- 两个红包同时开放，只提醒一次：先把人从名单上划掉，划掉了的才发。
- 没有隐私邮箱的人、站长看不到这个按钮。
- 按钮旁边写“N 人设了提醒”，所有人都看得到（没登录的也是），只有人数，没有名单；没人设时不写（用户问的：红包广场能不能看到多少人订阅了下一个红包）。
- 发红包的“更多设置”里，“加入红包广场”的说明加一句“现在有 N 人设了下一个红包的提醒，开放后能领的人会收到私信。”发红包的人自己设的不算；没人设时不写（用户问的：编辑设置里加入红包广场的说明能不能也展示人数）。

“等的红包开放了”谁都能要：定时开放的红包在开放前对所有人可见（左上角“N 人在看”），登录的人在那里点“开放时提醒我”，就记下他。点了以后按钮变成“开放时会私信提醒你”，再点一下取消。没有隐私邮箱的人、关了这一类的人不显示这个按钮。红包取消定时、删掉或开放没成功，记下的人都不发。

### 3.2 定时开放没开成

到点开放时，跟点“保存并开放”做的是同一套检查，任何一项没过就开不成（[定时开放](scheduled-opening-design.md)第 5 节）：

- 站长关了开关：🐟额红包、代码判定、限时开奖的开关，或者暂停了新开放超过 10 分钟（维护、发布时会暂停，10 分钟内每分钟再试）。
- 用 Credit 商户付的：商户的凭证到点时检查没通过，比如在 Credit 那边改了或删了应用的密钥。
- 三方积分：到点时再查一次余额，不够这个红包的总额加上同一把密钥下其他开放中红包没发出的部分。
- 网络或服务出了问题，10 分钟内重试都没成。

🐟额红包定时的时候🐟就锁下了，不会因为🐟不够开不成。开不成的红包退回草稿，原因写在他自己的红包页上。正式站到 2026-11-15 一次都没发生过。原因多半不在发红包的人那边，到点时他也多半不在。收信人是发红包的人，去重键是红包 + 这次定时。

### 3.3 三方积分

有两种人要知道，领的人不发（同第 3.4 节）：

**添加这个积分的人（接入人）：**

| | 什么时候 | 去重键 |
|---|---|---|
| 审核通过，上线了 | 站长审核通过 | 积分 + 这次审核 |
| 审核退回 | 站长退回，带上理由 | 积分 + 这次审核 |
| 被站长暂停、恢复、下架 | 站长在后台操作 | 积分 + 这次操作 |
| 接口连不上，积分分发暂停 | 熔断：连续 5 次没拿到回复，积分分发暂停 10 分钟 | 积分 + 这次故障 |

熔断“一次故障只发一次”：熔断以后，要等到有一次调用拿到了回复，才算这次故障结束；接口一直连不上，每 10 分钟熔断一次，也只发第一次那封。

**用它发红包的人：**

| | 什么时候 | 去重键 |
|---|---|---|
| 红包提前结束了 | 开放中的三方积分红包因为余额不够、密钥失效、这个积分被下架而结束；限时开奖开奖前余额不够，没开奖就结束 | 红包 |

自己删了密钥让红包结束的，当场就知道，不发。定时开放到点余额不够，算“定时开放没开成”。

不发的：

- 领的人领了没发出去（同 LDC 的，第 3.4 节）。
- 接口测试（当场看到）、文案改动（站长看的）。
- 分发结果不明：站长在后台处理。

### 3.4 不发

- 领红包的人：领了没发出去，有人指定你能领。
- 🐟额：站长改了你的🐟额，转出没成功。
- 站长自己的任何事。
- 当场就看到的：发红包成功、自领、转账成功、转出成功。
- 限时开奖没中。
- 发给所有人的：公告、新功能、活动、排行榜。

## 4 私信通知页面

- 地址 `/notifications`，标题“私信通知”。
- 入口：
  - 头像菜单里一项“私信通知”。
  - 个人信息页上“Connect 邮箱”那一行改叫“隐私邮箱”，旁边放一个“私信通知设置”的链接。
- 顶上一句说明：“和你有关的事，红包站会通过社区私信告诉你。私信标题以【邮件】开头，从站长的账号发出，不能回复。”
- 下面每一类一个开关，开关下面一行小字说什么时候发，按收信人分组：
  - 领红包：限时开奖中了。
  - 发红包：红包分发暂停、定时开放没开成、红包被站长停用、三方积分红包提前结束。
  - 打赏和转账：收到打赏、收到转账。
  - 判定器：判定器被撤下。只有写过判定器的人看到这一组。
  - 三方积分：审核结果；被暂停、恢复、下架；接口连不上。只有添加过积分的人看到这一组。
- “等的红包开放了”“红包广场有新红包”不在这里：红包上的“开放时提醒我”、红包广场上的“下一个红包开放时提醒我”就是它们的开关。
- 最下面是“最近发给你的”：30 天内发给他的私信，标题和时间，发失败的写“没发出去”。
- 本站没有他的隐私邮箱时，开关都灰掉，说“本站还没有你的隐私邮箱，在网站上用 LINUX DO 登录一次就有了”。
- 站长打开这一页：说“站长收不到私信通知：社区不能自己给自己发私信。”开关不显示。

## 5 格式

**标题**（社区里显示为“【邮件】”加标题）：

- 以“红包站：”开头，后面一句完整的话，带上数字和红包标题。
- 红包标题超过 12 个字的截掉，加“…”。
- 整个标题最多 40 个字。

**正文**（纯文本）：

- 每行最多 20 个汉字（手机上代码块大约这么宽），手动换行；英文和数字按半个字算。
- 第一段把事说清楚。
- 第二段一个链接，单独一行，前一行说去哪（链接点不了，要复制）。
- 最后一段说在哪关掉这类通知。社区已经说了请勿回复，正文里不再说。
- 金额带单位（LDC、🐟，三方积分写它的单位）；时间写“11月15日 20:00”，北京时间。
- 用户写“@用户名”。

**发之前要在 Stage 试的：**

- ~~只有纯文本时，社区还显示不显示“正文 HTML”那一段~~：显示，见第 0 节；附一句话的 HTML 以后，那一段只剩这一句（Stage 2026-11-15）。
- 代码块在手机上多宽，20 个字一行合不合适。
- 红包页的地址 `https://hb.lafi.sh/🧧/编号` 从代码块里复制出来，在网页和 iOS 客户端上能不能打开（社区帖子里的链接因为 iOS 客户端的问题已经改成了百分号编码）。

## 6 文案

《》里是红包标题，数字是例子。

**限时开奖中了**

```
标题：红包站：你在《周五摸鱼》中了 5.00 LDC

《周五摸鱼》开奖了，
你中了 5.00 LDC，
会分发到你的 Credit。

开奖结果：
https://hb.lafi.sh/🧧/AbC123

不想收这类通知，在这里关：
https://hb.lafi.sh/notifications
```

🐟额红包写“会存进你的🐟额”，三方积分写它自己的单位和去处。开奖时多半还在分发，所以写“会”。

**红包分发暂停：余额不够**

**三方积分**（标题，正文同样是一段说明、一个链接、怎么关）

- 审核通过：“红包站：你添加的「星星」审核通过，上线了”。
- 审核退回：“红包站：你添加的「星星」被退回了”，正文写站长的理由，链接到设置页。
- 暂停、恢复、下架：“红包站：「星星」被站长暂停了”，有理由就写；下架的写“开放中的红包已经结束”。
- 接口连不上：“红包站：「星星」的接口连不上，积分分发暂停了”，正文写“连续 5 次没有回复，积分分发暂停 10 分钟，之后会再试。接口恢复前不再提醒。”链接到调用记录。
- 红包提前结束：“红包站：《周五摸鱼》提前结束了：星星余额不够”，原因换成密钥失效、「星星」被下架、没开奖（限时开奖开奖前余额不够）；有发行方写的说明就放在正文里。

## 7 要做的

1. 发信：SMTP 客户端、队列、`notifications` 表（迁移）、定时任务里的补发、站长页面的统计。
2. 各处插通知：开奖、付款停下（只看发红包的人自己的商户）、打赏到账、转账到账、站长停用红包、站长撤下判定器、红包开放（等它的人、红包广场等下一个的人）、定时开放没开成、三方积分的审核和站长操作、熔断、三方积分红包提前结束。
3. “开放时提醒我”：定时开放的红包页上的按钮；红包广场的“下一个红包开放时提醒我”；记下谁在等的两张表（迁移）。
4. “私信通知”页面、头像菜单的入口、个人信息页的入口。
5. Stage 用站长的第二个账号试格式（第 5 节），再定细节。

## 8 站长要做的

- 在 webmail.linux.do 建一个令牌（Authorized IP 留空）。
- 运行 `bun scripts/notice-secrets.ts --env staging --execute`：它在终端里问邮箱地址和令牌（令牌不显示），先登录 mail.linux.do 检查一次（不发信），再存成 API 的机密 `NOTICE_SMTP_USER`、`NOTICE_SMTP_TOKEN`；Stage 还问只发给哪些 LINUX DO 数字 ID（`NOTICE_ALLOWED_LINUX_DO_IDS`）。不加 `--execute` 只说要做什么。
- 正式站用 `--env production`。存机密会让 API 重新部署一次、红包的 Durable Object 重启，放在发布的暂停里或者人少的时候。
