# “代码”和“判定器”的说法（2026-10-30，第 14 条，待用户看）

用户 2026-10-30 定：

- 玩法名不改：“代码判定”“代码判定红包”（领的人不一定知道判定器，“代码”好懂）。
- 别的地方都说“判定器”，领的人看到的也一样。
- “代码”只用在代码本身：查看代码、复制代码、代码公开、代码指纹。
- 开发包和 `/help/code` 讲怎么写 `judge.js` 时照旧说“代码”。
- “这次不算”说不清楚，改成直说：判定器出错了，这次没有判定，可以再提交一次。

下面是逐条的改前和改后，按谁看得到分组。只列要改的；最后一节写不改的和为什么。看过以后一起改，测试跟着改。

## 7 不改的

- 玩法名和它的各种叫法：代码判定、代码判定红包、代码判定联网（开关名）、“本红包由代码判定”（论坛分享文字，玩法名当说法用）、`hb.ready()` 的 `code`、原因 `not_code` 和它的“不是代码判定红包”。
- 说代码本身的：查看代码、复制代码、展开代码、粘贴代码、改代码、用这份代码、新代码、代码公开、代码指纹、“只有你看得到：别人要等红包结束后才看得到代码。”、指纹的说明（“代码一直公开，谁都能核对它没有换过”）、“开放后由判定器 第 3 版 判定每次提交，不能再换；结束后所有人都能看到代码。”、参数保密的说明（“要看判定器的代码”）、判定器页和 `/judges/new` 的“代码公开”“代码会一直公开”。
- 写判定器的人看的：`/help/code` 和开发包讲写法的地方（“代码里 Date.now()”“只有代码看得到”“联网的代码”“没接住就算代码出错”等）、部署结果（“代码能加载、导出了 judge”“代码加载不了”“代码一直没有返回”“代码超过 64 KB”“代码换了”“换回的代码和第 3 版不一样”）。
- 公平性验证页“不想相信本站页面上的代码”、开放接口说明“可以拿它生成代码”：说的是程序代码，不是判定器。
