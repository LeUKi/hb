# 判定器的地址参数

2026-11-01 用户提出：有的判定器要发红包的人自己部署一个服务（比如 Cloudflare Worker），判定器在判定时请求这个服务，附带网页也要用到这个服务。现在做不到：判定器能请求的地址（`network`）写死在代码里，密钥的 `to` 也是写死的。想让大家共用一个判定器，就只能每个发红包的人复制一份、改掉地址再部署。

同一天，一位判定器开发者的 Agent 给了一个具体玩法，这份设计按它来检验：判定器大家共用；作者提供一个服务模板，发红包的人部署到自己的 Cloudflare 账号，用自己的 Workers AI 给玩家上传的图片打分，图片存不存、存在哪也由他自己的服务定。它建议附带网页也大家共用；用户更想让附带网页和服务一起放在发红包的人那里，共用的网页也留着能用（第 1 节）。

相关文档：[密钥参数](judge-key-design.md)、[联网](programmable-hongbao-design.md) 第 9 节、[判定器带附带网页](judge-page-design.md) 第 4 节、[认出看的人](page-identity-design.md)、开发包 `AGENTS.md` 的“自有后端”。

## 1 一个玩法怎么搭

| 部分 | 谁提供 | 在哪运行 | 做什么 |
| --- | --- | --- | --- |
| 判定器 | 判定器作者 | 红包站，大家共用 | 读玩法参数，向发红包的人的服务核对结果，决定发多少 |
| 服务 | 作者给模板，发红包的人部署 | 发红包的人的 Cloudflare 账号 | 放附带网页；认出玩家，限次数，调 AI，存结果 |

附带网页在模板里，和服务一起部署，是同一个网站：网页在 `https://他的地址/`，接口在 `https://他的地址/api/`。一次提交这样走：

```text
玩家打开附带网页（在他的服务上）
  → 网页要一个身份令牌，带着它把图片传给同一个网站的接口
  → 服务认出玩家和红包，调自己的 Workers AI，存下结果，回一个结果编号
  → 网页用 hb.submit() 把结果编号交给红包站
  → 判定器带着服务密钥问这个服务：这个编号算不算、多少分
  → 判定器决定发多少
```

AI 在上传时由服务调用，不在判定里：判定只是一次很快的查询，不受“整次判定 15 秒”的限制。发红包的人的 Cloudflare 凭据和 AI 账号都只在他自己的服务里，红包站和判定器作者都拿不到。

网页和服务放在一起，是因为：

- **版本对得上**：红包开放时判定器的版本就定下了，网页是他部署的那一份，也不会再变。大家共用的网页由作者随时更新，要同时兼容所有进行中的红包用的旧版判定器。
- **作者改不了进行中的红包**：网页只在发红包的人重新部署时才变。
- **同一个网站**：不用配跨域，身份令牌的 `aud` 就是他自己的服务。
- **一次部署全有**：从“Deploy to Cloudflare”按钮部署一次，网页和服务都在他自己的账号里。

代价是作者修了网页，每个人要自己重新部署才用得上。部署按钮会在他的 GitHub 上建一份仓库、接上自动部署，作者更新模板后，他在 GitHub 上同步一下就重新部署（要实测）。

大家共用一个网页也能做：`meta.page` 照旧写一个固定地址，网页从 SDK 读服务地址（第 5 节），向服务的接口传图片（服务的跨域只放行这个网页的来源）。`AGENTS.md` 里写成“也可以”，样例只做放在一起的。

红包站要补的就是三件事：发红包的人能填服务地址（第 2–4 节）；附带网页跟着这个地址填好，网页也读得到公开的参数（第 2、5 节）；他的服务能认出请求来自他自己的红包（第 6 节）。图片不经过红包站，红包站什么都不用加。

## 2 地址参数

一种新的参数类型“地址”（`type: "url"`）：发红包的人填一个 https 地址。它和普通参数一样公开、代码读得到、开放后不能改；判定器能在三个地方写 `{ param: "server" }` 用它：

- **`network` 里**：开放时，他填的地址就成了这个红包能请求的地址之一。
- **密钥的 `to`**：服务密钥只发给他自己的服务。
- **`meta.page`**：`{ param: "server" }`，附带网页一栏跟着他填的地址填好；网页不在根路径时加 `path`，比如 `{ param: "server", path: "play/" }`。

联网的其他规则都不变：每次判定最多 3 个请求，单个 10 秒，整次 15 秒，请求体 16 KB，返回 64 KB，只许 GET 和 POST，不跟随跳转。请求照旧带 `x-hb-hongbao: 红包编号`。

```js
export const params = [
  {
    key: "server",
    label: "服务地址",
    hint: "按部署说明部署一份，把得到的地址填在这里",
    type: "url",
    guide: "https://github.com/someone/photo-judge-server#readme",
  },
  {
    key: "token",
    label: "服务密钥",
    hint: "部署时设的那串密钥",
    type: "key",
    to: { param: "server" },
  },
  // …挑战说明、多少分算过、每人几次等玩法参数
];

export const network = [{ param: "server" }];

export const meta = {
  name: "拍照挑战",
  description: "按要求拍一张照片，AI 打分，过线就发",
  page: { param: "server" },
};

export async function judge(submission, tools) {
  // params.server 是规范后的地址，以 / 结尾，比如 https://a.workers.dev/
  const address = new URL(`api/results/${submission.input}`, submission.params.server);
  // 不写密钥：网站转发时加上 Authorization: Bearer <服务密钥>
  const response = await fetch(address);
  // …核对这个结果是这个红包、这个人、这套挑战的，再决定加多少
}
```

## 3 规则

**地址参数**：`{ key, label, hint, type: "url", required, guide }`。

- 地址的规则同 `network` 的地址：https，完整域名，不带端口、用户名、`?` 和 `#`，不能是 IP、localhost、linux.do 和本站，最多 200 个字。
- 网站把它规范成以 `/` 结尾：填 `https://A.workers.dev` 存成 `https://a.workers.dev/`，填 `https://a.workers.dev/api` 存成 `https://a.workers.dev/api/`。代码收到的是规范后的，用 `new URL("路径", params.server)` 拼就不会出错。
- 不能写 `default`：地址要发红包的人自己填。判定器作者有公用的服务，就在 `hint` 或部署说明里写出它的地址，让发红包的人自己填。
- 不能写 `revealAtEnd`：判定器会请求哪里，领的人要看得到。
- 可以 `required: false`。没填时值是 `null`，指向它的 `network` 那一项、密钥和附带网页都不算数；`network` 只有这一项时，这个红包就是不联网的。
- 一个判定器最多 3 项地址参数。

**引用它的地方**：

- `network` 里每项是地址字符串或 `{ param }`，加起来最多 3 个。`{ param }` 要指向一项地址参数。开放时两个填成一样的地址，只算一个。
- 密钥的 `to` 是地址字符串或 `{ param }`。`{ param }` 要指向一项地址参数，并且这一项写进了 `network`。
- `meta.page` 是地址字符串或 `{ param, path }`。`path` 选填，是接在地址后面的相对路径（不以 `/` 开头，不带 `..`、`?` 和 `#`），接好以后要符合附带网页的规则。

**部署时把关**（网站和 `npm run check` 一样）：

- `{ param }` 指向的不是地址参数：不通过，比如“network 第 1 个：server 要是地址参数（type: "url"）”。
- 地址参数写了 `default` 或 `revealAtEnd`：不通过，写明原因（同上面两条）。
- 地址参数哪里都没用上（不在 `network`、密钥的 `to`、`meta.page` 里）：提醒“地址参数 server 没用上：判定器请求它会被拦下”。共用的网页从 SDK 读它的，可以不管这条提醒。
- 地址参数写进了 `network`，却没有密钥的 `to` 指向它：提醒“建议加一项密钥（to: { param: "server" }），让 server 认得出请求来自这个红包”。

**`guide`**（新的，所有参数都能写）：一个 https 链接，表单和判定器页在这一项旁边显示“怎么填 ↗”，在新标签页打开。地址参数用它放部署说明，密钥用它放“去哪拿密钥”。规则同附带网页的地址。

不升协议：第 5 版里多一种参数类型和这几种写法；之前部署的版本不受影响。

## 4 发红包的人看到的

- **挑判定器时**：判定器卡、广场、判定器页的参数里写“服务地址（地址，发红包的人自己填，判定器会请求它）”。附带网页放在这个地址下的，写“附带网页：放在发红包的人填的地址下”。
- **“这个判定器会联网”的确认**（用广场上别人的判定器时）：只问写死在代码里的地址。全部地址都是他自己填的，就不问；一部分是他自己填的，确认里写“它会把领的人提交的内容发到 api.example.com，和你自己填的服务地址。”
- **参数表单**：一个地址输入框，下面一行“判定器会请求这个地址，领的人看得到它。开放后不能改。”；写了 `guide` 时旁边有“怎么填 ↗”。离开输入框时规范成存下的样子，不对就在下面写原因（“只能用 https:// 开头的地址”“不能写 IP 地址”“不能带端口”）。
- **他自己的数字 ID**：地址参数下面再写一行“你的 LINUX DO 数字 ID 是 12345，部署说明要你填时用它。”部署服务时要用（第 6 节）。
- **附带网页一栏**：判定器的 `meta.page` 指向这项地址时，跟着他填的地址填好，提示写“判定器带的网页，放在你填的服务地址下，可以改成别的，也可以删掉。开放后不能改。”他自己改过就不再跟着。“这个网站不允许被嵌入”的检查在地址填好时跑。
- **密钥**：`to` 指向地址参数时，那一行写“只会发给你填的服务地址，判定器代码看不到……”；地址还没填时写“只会发给上面的服务地址”。
- **试一试**（判定器页和表单里）：本来就不真的联网。判定器页的试一试里，地址参数先填好 `https://example.com/`，能改。

## 5 附带网页读到参数

SDK 的红包信息（`hb.ready()` 和 `hb.on("hongbao")` 给的 `hongbao`）多一项 `params`：这个红包现在公开的参数，同红包页代码一节列出的那些。结束后公开的参数结束后才有，密钥永远没有。没有参数的红包是 `{}`。

```js
const { hongbao } = await hb.ready();
hongbao.params.prompt; // 挑战说明，网页直接显示，不用问后端
hongbao.params.server; // https://a.workers.dev/，共用的网页拿它决定把图片传到哪
```

这些值本来就公开在红包页上，给网页读不多透露什么。

## 6 服务认出自己的红包

别人也能用同一个判定器发红包、填上他的服务地址，附带网页也就跟着指到他的服务上。来自判定器的请求，他的服务看服务密钥就能拒掉；可网页传图片时带的只有身份令牌，令牌里有红包编号，但不知道这个红包是谁发的。不分开的话，别人的红包也能用他的 AI 额度。

所以身份令牌（`hb.identity()`）多一项：

- `sender`：发这个红包的人的 LINUX DO 数字 ID（字符串）。

服务部署时设一个 `OWNER_ID`（发红包的人自己的数字 ID，表单上写着，第 4 节），验令牌时核对 `sender` 是它，不是就拒绝。其他核对照旧（签名、`iss`、`aud` 是网页的来源、没过期、`nonce`）。

`/help/page` 的“认出看的人”和 `AGENTS.md` 的“令牌”同步加上 `sender`；模拟器签的令牌里 `sender` 来自 `simulate.json`，没写时是模拟的发红包的人。

## 7 领红包的人看到的

- 红包页代码一节的参数里照常列出地址。
- “联网”一栏照常列出这个红包能请求的地址（开放时定下的），发红包的人填的后面写“发红包的人填的”。下面原有的那句照旧：“判定结果取决于对方的回答，开放后对方的回答可能变化，本站无法核对。”
- 附带网页照旧：第一次打开某个网站先确认。网页把图片传到哪，是网页和那个服务的事，不经过红包站。

## 8 开发包

- **`npm run check`**：参数预览写“服务地址（地址，发红包的人填，判定器会请求它）”；`network`、密钥的 `to`、`meta.page` 里的 `{ param }` 按第 3 节检查。写对了的 `meta.page` 写“✓ 附带网页：放在 server 填的地址下的 play/”。
- **`tests.json`**：参数里给地址参数写一个地址（比如 `https://example.com/`），`fetch` 的返回按这个地址写。每条测试按自己的参数算出能请求的地址。
- **`npm run simulate -- --live`、`npm run page -- --live`**：请求 `simulate.json` 里填的地址。只在开发包里，地址参数还能写 `http://localhost:8787/` 或 `http://127.0.0.1:端口/`，对着本地 `wrangler dev` 起的服务开发，开头提醒“地址参数 server 用的是本地地址，网站上要填 https 地址”。模拟器给网页的 `hongbao.params` 也是这一份；`meta.page` 指向地址参数时，模拟器右边打开那个地址下的网页，不用 `page/`。
- **样例**：不在开发包里做（用户 2026-11-01：另一个 Agent 照文档做一份，顺便检验文档够不够）；`AGENTS.md` 里写一个简短的实践例子（第 11 节）。
- **`AGENTS.md`**：参数一节加地址这种类型；“自有后端”下面加一节“发红包的人自己部署的服务”：
  - 什么时候用：每个发红包的人要有自己的数据、AI 账号或存储，费用也归他；
  - 第 1 节的分工和数据怎么走，网页和服务放在一起；大家共用一个网页也可以，网页从 `hongbao.params` 读地址；
  - 地址参数的三种用法；
  - 服务验令牌时核对 `sender` 是 `OWNER_ID`；判定器和服务之间用 `to: { param }` 的密钥；
  - 慢的事（调 AI）放在上传时由服务做，判定只查结果；
  - 判定器不信网页交来的分数，只信服务核对的结果：服务存下的结果要带红包编号、玩家（令牌的 `sub`）和这次用的挑战，判定器核对三样都对得上，再在 `state` 里记下用过的结果编号，同一个结果不能领两次；核对接口照旧要幂等；
  - 部署说明写进 `guide`；服务挂了判定器要接住（“服务连不上，稍后再试”）。
- `judge.d.ts`、`page/hb.d.ts`（`params`、令牌的 `sender`）、Skill 的要点、`/help/code` 的参数和联网两节、`/help/page` 第 5 节同步。

## 9 存放和运行

- 版本的声明（`declarations`）和 `judge_checks.network` 里照写判定器写的样子，`{ param }` 原样存。
- **开放时**：把 `network` 按这个红包的参数换成地址，存进 `activity_code.network`（原来是从部署结果原样拷过来）。网关、判定、记录和红包页读的都是这一份，不用改；换完是空的就存 null，这个红包不联网。
- **密钥**：网关加请求头时，`to` 是 `{ param }` 的，按这个红包的参数换成地址再比。
- **附带网页**：照旧存在红包自己的附带网页一栏里，由表单跟着地址填好。服务器只按附带网页的规则查，不另外认。
- **SDK 的 `params`**：红包页本来就拿到公开的参数，跟着红包信息发给网页。
- **令牌的 `sender`**：签发时按红包的发红包的人填。
- 不加表，不用迁移：`network` 那两列的约束只要求是 1–3 项的数组。

## 10 要注意的

- **结果取决于发红包的人的服务**：他的服务想让谁赢就让谁赢。领的人在“联网”一栏看得到地址，也看得到“判定结果取决于对方的回答”。这和他发红包时选“指定的人”一样，是发红包的人自己的事，不另外拦。
- **开放后不能改地址**：地址在公开的参数里，判定器代码也读它。服务要换地址，只能结束这个红包另发一个。`AGENTS.md` 和部署说明里建议发红包的人用固定的地址（比如自己的域名），服务更新时地址不变。
- **服务挂了**：判定器没接住 `fetch()` 的错，连续 5 次出错红包就暂停领取（已有的规则）。样例和 `AGENTS.md` 都写接住它。
- **部署要他自己来**：登录 Cloudflare、点部署、设 `OWNER_ID` 和服务密钥都要发红包的人自己做。样例的部署说明要实测一遍再写进文档。

## 11 做的时候补的（2026-11-01）

- **怎么改的**：开放时 `activity_code.network` 不再从部署结果原样拷，按这个红包的参数换成地址再存；网关、判定、记录读的都是这一份。密钥 `to` 是 `{ param }` 的，网关按开放时公开的参数（`params_public`）换成地址。部署时每条测试按自己的参数换。
- **地址的说法**：表单上不对时写“服务地址只能用 https:// 开头的地址”“服务地址不能带端口”“服务地址不能带 ? 和 #”，其余同 `network`（“不能写 IP 地址”等）。
- **自己的数字 ID**：会话里多一项 `linuxDoId`，只给本人；表单上地址参数下面写“你的 LINUX DO 数字 ID 是 …，部署说明要你填时用它。”试一试里不写。
- **“这个判定器会联网”的确认**：写死的地址和他自己填的都有时，正文是“它会把领的人提交的内容发到 api.example.com。那不是本站，也不是你的服务器。也会发到你自己填的服务地址。”记下的确认只有写死的地址。
- **判定器页的试一试**：地址参数先填好 `https://example.com/`；附带网页那一行跟着它。
- **判定器页、广场**：`meta.page` 是 `{ param }` 的，判定器页写“附带网页：放在发红包的人填的服务地址下”，不是链接。
- **SDK 的 `params`**：红包页从公开的参数（红包页代码一节的那些）拼成 `{ key: 值 }`。
- **`AGENTS.md` 的实践例子**：“发红包的人自己部署的服务”一节写了分工、一次提交怎么走、判定器（地址、服务密钥、挑战、过线分数，核对结果、记下用过的编号）和服务（Worker：静态网页，`/api/upload` 验令牌和 `sender`、调 AI、存结果，`/api/results/:id` 验服务密钥和 `X-Hb-Hongbao`）两段代码，和本地怎么对着 `wrangler dev` 开发。
- **模拟器**：`meta.page` 是 `{ param }` 的，模拟器把 `simulate.json` 里填的那个地址整个转到网页那个端口（换上模拟器的 SDK），网页和它的接口照样是同一个网站；这时令牌的 `aud` 是那个服务自己的来源（和线上一样），`sender` 固定是 `10000`。本地地址（`http://localhost:…`、`http://127.0.0.1:…`）只在 `simulate.json` 里认，开头提醒“地址参数 server 用的是本地地址 …，网站上要填 https 地址”。
- **不加表，不用迁移**：同第 9 节。
