# 判定器的密钥参数

2026-11-01 用户提出：判定器要接 AI 服务，需要填密钥，但密钥不能被别人看到，也不能被别人拿去用。现在的保密参数结束后会公开，判定器代码也读得到全部参数，都不适合放密钥。

用户定：每个发红包的人填自己的密钥（谁发红包谁付 AI 的钱）。判定器作者想用自己的密钥，现在就能做，不用改网站：判定器联网请求作者自己的服务器，作者在那里保管密钥、再去调 AI（开发包 `AGENTS.md` 的“自有后端”）。

## 0 三种参数和叫法（2026-11-01 用户定）

原来的“保密参数”和新的“密钥”叫法太像，用户不要“保密参数”，也不要“封存参数”：界面上不给它起名字，每项参数只标什么时候公开。

| | 判定器代码读得到 | 红包进行中 | 结束后 | 用来放 | 界面上标 | 代码里写 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通参数 | 能 | 公开 | 公开 | 范围、次数 | 不标 | — |
| 结束后公开的参数（原来的保密参数） | 能 | 不公开，只公布参数封存值 | 公开，能核对没换过 | 答案、谜底 | “结束后公开” | `revealAtEnd: true` |
| 密钥 | 不能 | 不公开 | 不公开，删掉 | AI 等服务的密钥 | “不公开” | `type: "key"` |

- 旧写法 `secret: true` 照样认，同 `revealAtEnd: true`；已部署的判定器、已开放的红包都不受影响。开发包样例、文档、给 AI 的说明都改成 `revealAtEnd`。
- 网站上原来写“保密”的地方都改：参数后的标签写“结束后公开”，提示“红包进行中不公开，结束后公开；开放时公布的参数封存值能核对它没被换过。”；红包页写“另有 2 项参数结束后公开”；参数封存值的说明写“这几项参数结束后和盐一起公开……”；`npm run check` 的参数预览写“答案（整数，结束后公开）”；`npm run replay` 写“✓ 结束后公开的参数和封存值对得上”。
- 部署时把关（网站和 `npm run check` 一样）：
  - 密钥上写了 `revealAtEnd` 或 `secret`：不通过，“密钥本来就不公开，不用写 revealAtEnd”；
  - 判定器会联网，又有一项文字参数的 key 或名字像密钥（key、token、secret、密钥、令牌）：提醒“这一项像是密钥：放密钥用 type: "key"，判定器代码读不到，也不会公开”。

## 1 做法

一种新的参数类型“密钥”。它和别的参数不同在三处：

- **判定器代码拿不到**：`submission.params` 和 `setup(params)`、`check(params)` 里都没有这一项。判定器联网请求密钥指定的地址时，网站转发请求的那一刻把密钥加进请求头；请求别的地址不加。
- **永远不公开**：不进参数封存值，结束后不公开，下载的完整记录里没有（记录里的请求本来就不带请求头）。红包结束后删掉。
- **只属于这一个红包**：别人用同一个判定器发红包，填他自己的。

判定器代码写不出“读密钥”的办法，所以不管代码怎么写，都没法把密钥写进回复、公开数据，也发不到别的网站。

能看到密钥的只有密钥指定的那个地址（AI 服务商）。网站本身和代码、保密参数一样加密存放。

## 2 判定器怎么写

```js
export const network = ["https://api.openai.com/v1/"];

export const params = [
  {
    key: "ai",
    label: "AI 密钥",
    hint: "在 OpenAI 后台建一个，建议设消费上限",
    type: "key",
    to: "https://api.openai.com/v1/",
    header: "Authorization",
    prefix: "Bearer ",
  },
];

export async function judge(submission, tools) {
  // 不写密钥：网站转发时加上 Authorization: Bearer <密钥>
  const response = await fetch("https://api.openai.com/v1/chat/completions", {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ /* … */ }),
  });
  // …
}
```

- `to`：密钥只发给这个地址开头的请求；要是 https，并且在 `network` 里（是其中一项，或者在其中一项下面）。
- `header`：放进哪个请求头，默认 `Authorization`；`prefix`：值前面加什么，默认 `Bearer `。比如 Anthropic 是 `header: "x-api-key", prefix: ""`。
- 代码自己写了同名的请求头，转发时以密钥为准。
- 默认必填。一个判定器最多 3 项密钥。密钥本身一行、最多 500 个字。
- 部署时检查：`to` 不是 https、不在 `network` 里、`header` 不是合法的请求头名，部署结果里写出来，不通过。
- 不升协议：第 5 版里多一种参数类型；之前部署的版本不受影响。

## 3 发红包的人看到的

- **判定器卡、广场、判定器页**：参数里这一项写“AI 密钥（密钥，发红包的人自己填，只发给 https://api.openai.com/v1/）”，挑之前就知道要准备密钥。
- **参数表单**：一个密码样式的输入框，名字后面标“不公开”，下面一行：“只会发给 https://api.openai.com/v1/，判定器代码看不到；保存后不再显示，红包结束后删除。调用的费用从这个密钥扣。”
- **保存以后**：输入框换成“已填写”和一个按钮“换一个”；按了重新输入，没输入就还是原来的。
- **没填就按“保存并开放”**：那一项下面写“还没填 AI 密钥”。
- **开放以后**：编辑红包里照样能“换一个”（密钥被限额、要换新的时），下一次请求起用新的；判定器代码拿不到它，换了也不影响公平。
- **试一试**：本来就不真的联网，用不到密钥，照旧。

## 4 领红包的人看到的

- 红包页代码一节的参数里写“AI 密钥：发红包的人自己的，不公开”。
- 结束后公开保密参数时不包括它。

## 5 开发包

- `npm test`：测试里的联网回复照旧写在 `tests.json`，用不到密钥。
- `npm run simulate -- --live`、`npm run page -- --live`：真的联网时，密钥从开发包根目录的 `keys.local.json` 读（`{ "ai": "sk-…" }`），这个文件写进 `.gitignore`，不提交。没有这个文件时，请求照样发出去，只是不带密钥。
- `npm run check`：参数表单预览写“AI 密钥（密钥，只发给 https://api.openai.com/v1/）”；`to` 不对时同网站的部署检查。
- `judge.d.ts`、`AGENTS.md` 的“参数”、Skill 的要点、`/help/code` 的参数一节加上这种类型；“联网”一节加一句：要用发红包的人的密钥，就用密钥参数，不要让他们填进普通参数。

## 6 要注意的

- 领的人每提交一次，判定器就可能调用一次 AI，费用从发红包的人的密钥扣。表单那行提示写了；`AGENTS.md` 里写：判定器要限制每人能试几次，并提醒发红包的人在服务商那边设消费上限。
- `to` 是判定器作者写的。作者要是写成自己的网站，表单上那行“只会发给 …”就写着那个网站，发红包的人看得到。

## 7 做的时候补的（2026-11-01）

- **部署结果**：网站部署结果里原来不显示“参数声明写得不对”（只有开发包显示，网站上测试全过却部署不通过），这次补上这一行；“像是密钥”的提醒也写在部署结果里，琥珀色。
- **标签**：表单里结束后公开的参数名字后面是“结束后公开”标签，密钥是“不公开”标签，悬停（手机上点）看说明：“红包进行中不公开，结束后公开；开放时公布的参数封存值能核对它没被换过。回复里会不会透露它，要看判定器的代码。”“判定器代码看不到，也不会公开；只会发给 …，红包结束后删除。”判定器页的参数行本来就写着“结束后公开”“不公开，只发给 …”，不再另加图标。
- **判定器页的“参数和试一试”**：试一试不填密钥，下面写一句“AI 密钥是密钥，发红包的人自己填。试一试不真的联网，用不到它。”
- **服务器拦下时的话**：没填就开放：“判定器要的密钥还没填，草稿已保存。”；填了判定器没有的密钥：“这个判定器没有要填的密钥，刷新页面后再试。”；密钥超过 500 个字或有换行：“AI 密钥最多 500 个字”“AI 密钥只能是一行”。
- **开发包 `--live`**：密钥从 judge.js 旁边的 `keys.local.json` 读，开头写“密钥 ai：从 keys.local.json 读，只发给 …”；没有这个文件或没写这一项时提醒“keys.local.json 里没有密钥 ai，请求 … 时不带它”。
- **删除**：维护任务“judge_keys”每次删掉已结束或已删除红包的密钥；红包结束后第一次有人读红包页（公开代码和种子时）也一起删。
- **存放**：迁移 0057 加一张表 `activity_keys`，每个红包一行：填了哪几项（名字），和加密的 `{ key: 值 }`。
