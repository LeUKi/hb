# 本地模拟付款与故障恢复

当前运行入口只执行本地模拟，没有真实 LDC 分发或查单调用。商户可选择 `simulation` 或 `real`，模式保存后锁定；真实商户只支持配置维护和活动草稿，不能开放或付款。模拟收款标识以 `simulation:` 开头，不代表已经验证 Connect 与 LDC 的身份映射。

## 可复现的本地操作

```sh
bun install --frozen-lockfile
bun run db:migrate:local
bun run dev
```

使用已配置的 Connect 登录 `http://127.0.0.1:5173`。在“商户配置”中填写虚拟 Client ID 和虚拟密钥，再创建固定、自定义或随机金额的 LDC 活动。金额填写发放金额；固定模式必须精确均分，自定义逐行一份，最多 1,000 份。

作者不能领取自己的 LDC 活动。需要在单个真实登录账号下验收领取时，可运行：

```sh
bun run dev:seed
```

此开发脚本只向本仓库本地 D1 新增独立虚拟作者、模拟商户、四份已开放的活动（固定、自定义、二倍均值、波动均值），不创建登录会话、不更改现有用户或活动。终端输出虚拟口令和本地链接。重跑沿用相同 ID，不重置期限或已有领取；样例到期后不会自动重开。它与应用登录能力分离，不存在生产登录旁路。

脚本只解析本地加密配置来生成有效密文，虚拟商户密钥固定为无外部用途的测试字符串；通过 Node 运行 Wrangler，并固定 `--local`。SQL 临时文件限制为当前用户读取，执行后删除。

## 状态含义

| 状态 | 系统正在做什么 | 作者可执行的操作 |
|---|---|---|
| 待发放 | 等待对应商户调度 | 一般无需操作 |
| 发送中 | 发送意图与占用已落库，正在请求模拟上游 | 等待结果；租约过期会先核对 |
| 核对中 | 发送结果未知，自动查询原业务号 | 只读刷新查看；不能解除未知订单保护 |
| 等待恢复 | 已知的资金、额度或凭证问题 | 更新模拟情形或虚拟密钥后等待自动恢复 |
| 模拟发放已确认 | 模拟订单的商户、业务号、收款标识和金额全部吻合 | 不再重发；这不是实际 LDC 到账 |
| 异常待处理 | 模拟订单发生金额等信息冲突 | 查看原因；本轮没有强行解除保护入口 |

每笔领取只有一笔付款任务。业务号、商户应用、收款标识和整数金额在分配时固定；更换同一商户的密钥只增加凭证版本。活动结束或归档不取消付款任务。

## 故障场景

外层商户配置页可设置下列模拟情形。场景变更影响后续模拟请求；已经生成的订单保留，切换情形不会删除或重建它。

| 情形 | 可验证的结果 |
|---|---|
| 正常 | 一个订单，最终确认 |
| 发放成功但响应丢失 | 先核对，查到原订单后确认，不生成第二笔 |
| 查单延迟 | 最初查不到；仅模拟器已保证唯一原子业务号，因此可原号原参数重试 |
| 查单暂不可用 | 持续退避核对，该商户的新付款暂停，其他商户继续 |
| 余额不足 | 不生成订单，保留待付奖励，30 秒后再次检查 |
| 每日额度不足 | 本地模拟等待 60 秒；这不是对真实 LDC 重置时间的承诺 |
| 凭证失效 | 保留任务，30 秒后检查；轮换模拟密钥可触发同一调度入口 |
| 订单冲突 | 进入保护状态，密钥更新和自动重试均不能绕过 |

领取事务提交后立即投递对应 Outbox。Queue 仅负责唤醒，重复投递不会重复分配或付款。DO Alarm 提供及时重试；Cron 每五分钟补偿未投递事件、未完成付款及生命周期。未知结果的退避带抖动，单次上限约五分钟。

每次付款补偿最多投递 20 项 Outbox、唤醒 20 个到期商户，单批付款维护最多 23 次 D1 查询；商户 DO 内部另执行自己的数据库操作。持久保存最近扫描时间，失败或暂停的商户不会一直占住队首。较大积压分多轮继续处理，已经成功投递 Outbox 的未完成任务仍在扫描范围内。Alarm 只提前已有唤醒时间，空的旧快照不会取消其他请求刚安排的任务。

## 本地触发与排查

统一开发服务运行时，手动触发 API Worker 的定时入口：

```sh
curl --fail -X POST \
  'http://127.0.0.1:5173/cdn-cgi/local/explorer/api/local/scheduled?worker=hb-api' \
  -H 'Content-Type: application/json' \
  --data '{"cron":"*/5 * * * *"}'
```

商户与付款弹窗只提供只读刷新，不提供手动恢复或凭证检查；本地需要加速验证时使用上述隔离开发 Cron 命令。自动调度不更换业务号、不释放未知订单或冲突占用。

在 `apps/api` 目录可只读查看任务概要（不读取密钥、口令或私有文本）：

```sh
node ../../node_modules/wrangler/bin/wrangler.js d1 execute hb-local \
  --local --persist-to ../../.wrangler/state \
  --command 'SELECT status,reason,COUNT(*) AS tasks FROM payment_tasks GROUP BY status,reason' \
  --json
```

进一步核对 `payment_attempts` 中的发送／查单结果、`merchants.active_task_id` 与 `lease_until`、`payment_outbox.delivered_at`。Outbox 已投递只证明唤醒成功，不证明付款完成。发送占用过期后先查单，不能手工将未知任务改回待发放或清除商户占用。

日志仅打印预定义错误类别和内部任务／商户 ID，不打印 SQL 参数、密钥、口令或兑换码。重启开发服务保留 `.wrangler/state`，不要删除状态目录来修复付款；本地测试数据库与该目录独立。

## 真实 LDC 接入前仍须验证

已完成的公开源码核对及对应固定版本链接见 LDC 接入证据。公开源码证据与线上验证分开记录，以下事项仍不能由模拟测试代替。

- 成功响应与商户查单字段、订单状态及结算语义。
- 同一商户与业务号重复提交的线上行为、原子性和查询延迟。
- Connect 稳定账号 ID 到实际收款标识的可靠对应，不能直接使用用户名推断。
- 商户应用与付款账号的关系、共享额度、拒绝语义及重置时区。
- 真实资金、额度、凭证拒绝后的恢复规则；未知结果不得被后续拒绝覆盖。
- 受控验收的明确测试商户、收款人和金额授权。

模拟验收不替代这些线上条件。现有模拟任务不能通过切换环境变量变成真实付款；真实协议已有本地 HTTP 测试，真实通道仍需受控线上验证及新建任务，当前没有可开启真实出口的环境变量。
