# 判定器复用与判定器广场（2026-10-28 定）

用户提出（2026-10-28）：做好的判定器应该能再用，自己用，也给别人用；判定器带一份参数表单，发红包时填参数，运行时传给代码，同一份代码就能发出不同的红包。会写代码的人做判定器，不碰代码的人挑一个、填一张表就能发。这是[代码判定红包](programmable-hongbao-design.md)的协议第三版，加上一个新页面“判定器广场”。

本文的写法和代码判定的设计文档一样：定了的写“用户定”，还没定的写“建议”。

## 0 说法

| 说法 | 意思 |
|---|---|
| 判定器 | 一份能反复用的判定代码，有名字、说明、作者和各个版本；原来只是草稿里部署出来的一版，现在单独成一样东西 |
| 版本 | 判定器每部署一份新代码就是新的一版，“第 1 版”“第 2 版”，同现在 |
| 参数 | 判定器声明、发红包时填的值，运行时传给代码（第 3 节） |
| 保密参数 | 开放时只公布封存值、结束后公开的参数，比如谜底 |
| 平台字段 | 总奖池、份数、截止、领取范围这些本站的字段；判定器只能给它们设默认值、收窄范围（第 4 节） |
| 我的判定器 | 自己做的判定器 |
| 判定器广场 | 独立页面，列出站长精选和大家做的判定器（第 8 节） |
| 站长精选 | 站长挑选或改进过的判定器 |

## 1 判定器单独成一样东西

- 原来判定器长在草稿里：每个草稿存最近 10 版，别的草稿用不了。现在判定器有自己的名字、说明、作者、版本，以及用它开放过的红包。
- **名字和说明**（2026-10-28 用户指出：现在自定义创建没有写名字的地方，认不出来）：
  - 判定器卡最上面两项：名字（必填，最多 20 个字，比如“猜数字”）和一句说明（选填，最多 60 个字）。
  - 第一次部署前要填名字：部署就生成了这个判定器，没名字在“我的判定器”和广场里认不出来。名字没填时，部署按钮灰掉，旁边写“先给判定器起个名字”。
  - 不用红包标题当默认值：标题常是一次性的（“周五猜数字”），判定器的名字要能反复用。
  - 代码可以导出 `export const meta = { name, description }`，贴代码时自动填进这两项，AI 写的代码就自带名字（用户定）。它只当默认值：之后在本站改不影响代码，代码里的 meta 改了也不覆盖本站已经改过的名字。
  - 名字和说明在判定器页随时能改，不算新版本。
- **认得出来**：“我的判定器”每一行写名字、说明、最新的第几版和部署时间、开放过几个红包。
- 部署还是现在那一套（贴代码、跑测试、版本、换回、次数）。它出现在两处，用的是同一个组件：
  - 判定器页；
  - 发红包第 2 步的“自己写一个”。部署出来的版本记在这个判定器上，不再只记在草稿上。
- 已经有的草稿和红包：每个用过代码的草稿或红包迁成一个判定器，名字先用红包的标题（以前没有地方写名字），作者自己改；已部署的版本跟过去，已开放的红包照旧绑着开放时那一版。
- 用别人的判定器不用部署，也不扣次数，用的是那一版已经部署、测试全过的判定器。

## 2 代码什么时候公开

用户定（2026-10-28）：由判定器上的开关决定，不写在代码里。它是发布上的决定，不是代码的行为；写进代码会改变指纹，只为换个公开方式就要重新部署。

- 两档：“结束后公开”（默认，同现在）和“一直公开”。只能从“结束后”改成“一直”，改不回去：已经被看过了。
- 加入判定器广场的必须一直公开：别人要拿自己的奖池交给这段代码，得看得到它。
- 公开的是代码；测试照旧不公开。

## 3 参数

- **声明**：代码导出 `export const params = [...]`，部署时读出来（和读 `network` 白名单同一个办法：部署时向判定器要一次描述），跟着这一版存下。由本站按声明画表单，代码不在运行时生成表单，原因有三：
  - 画表单不用先启动沙箱；
  - 开发包不联网也能显示同一个表单；
  - 本站能检查每一项，样式、校验和无障碍也和别的表单一致。
- **每一项**：`key`（字母、数字和下划线）、`label`（最多 20 个字）、`hint`（最多 60 个字）、`type`、`default`、`required`（默认 true）、`secret`（默认 false），以及各个类型自己的限制。
- **类型**（第一版八种都做，用户定，2026-10-28：答题要表格，限时口令要列表，少了它们第一批精选做不出来）：

| 类型 | 表单里 | 限制 |
|---|---|---|
| `text` | 单行输入框 | `minLength`、`maxLength`（≤ 200） |
| `textarea` | 多行输入框 | `maxLength`（≤ 2000） |
| `integer` | 数字框 | `min`、`max`、`step` |
| `money` | 金额框（LDC，代码收到的是整数分） | `min`（≥ 1）、`max` |
| `switch` | 开关 | — |
| `choice` | 选项卡片，多了是下拉 | `options`：`{ value, label }`，2–20 个 |
| `list` | 一行一个，能加能删 | 每项是 `text`；`minItems`、`maxItems`（≤ 100） |
| `table` | 每行几格，能加能删 | `columns`：每格 `text` / `integer` / `money`；最多 100 行 |

- **校验**：本站按声明校验。判定器还可以导出 `check(params, hongbao)`，做跨项的检查（比如“最小值不能大于最大值”），返回 `[{ key, message }]`；它在同一个判定器里跑，不多算份，计入每人每天 50 次的隐藏上限。
- **传给代码**：`submission.params`，就是填好、校验过的那份。整份最大 16 KB（同状态）。
- **保密参数**（用户定，2026-10-28：结束后公开）：
  - 和代码一样加密存放。开放时公布参数封存值：保密参数按键排序后的 JSON、一行换行和一个随机盐，取 SHA-256；结束后和代码、种子一起公开参数和盐，谁都能核对。
  - 红包作者自己当然知道。回复里会不会漏出来是代码的事，参数表单上的锁旁边写明这一点。
- **公开参数**：开放时就写在红包页的代码一节里（“范围 1–100 · 每人最多猜 5 次”）。

## 4 平台字段：判定器只设默认值和范围

用户定（2026-10-28）：不是整个发红包表单都由代码声明。平台字段背后有本站的规则：锁定、退回、付款队列、范围校验。每个红包的表单长得一样，用的人也只用学一套。

- 判定器可以导出 `export const hongbao = {…}`，只能是下面这几项，都在平台允许的范围里：
  - `count`：份数 `{ min, max, default }`；
  - `total`：总奖池；
  - `minEach`：每份至少，`{ min, default }`；
  - `deadline`：截止，默认时长；
  - `prompt`：领取提示的默认值；
  - `humanCheck`：建议打开领取前人机验证（默认打开，红包作者能关）。
- 表单在第 3 步“发多少”按这些设默认值，超出范围的提示“这个判定器要求 1–10 份”。
- 拼手气、限时开奖这些经典玩法不改成判定器，原因有三：
  - 它们不用沙箱，不花钱；
  - 首页口令匹配只对它们有效，代码判定只能在红包页领；
  - 开奖证明、限时开奖的开奖都是平台自己做的。

## 5 协议第三版

- 第三版 = 第二版加上 `params`、`hongbao` 两个导出，可选的 `check` 和 `meta`，以及 `submission.params`。第一版、第二版的运行时都不动（第一版冻结，第二版已有红包在用）。
- 不声明参数的代码在第三版上照样跑，`submission.params` 是 `{}`。
- 开发包：
  - `tests.json` 每条测试能写 `params`，顶层能写默认的一份；
  - `simulate.json` 一样；
  - `npm run check` 检查参数声明，并按声明画出表单的纯文字预览；
  - `AGENTS.md` 和 `/help/code` 加一节“参数”。
- 判定器作者的测试要覆盖几组参数：部署时就证明“这些参数下代码是对的”。用的人填的参数没被测过，靠第 6 节的“试一试”，以及连续 5 次出错自动暂停兜底。

## 6 发红包表单

- **第 1 步“玩法”**：代码判定和经典玩法并列（用户定；2026-10-28 起五种玩法平铺，[07](redesign/07-pages.md) 第 5 节）。
- 代码判定的步骤变成：玩法 → **判定器** → 发多少 → 起个标题。判定器放在发多少前面，因为它会设发多少的默认值和范围（第 4 节）。
- **第 2 步“判定器”**（用户定，2026-10-28 看过两个状态的示意）。排法同第 1 步：横排卡，灰色小标题分组。
  - **挑之前**：
    - “站长精选”：最多 6 张，一行三张，窄了两张、一张；
    - “我的判定器”：只在做过判定器时有，放最近用过的 3 个，卡上写第几版、开放过几个；其余的在选择弹窗的“我的”页签里；
    - 最下面两个链接：“去判定器广场挑一个 ›”在表单里打开一个选择弹窗，内容同广场，填了一半的内容不会丢，弹窗里也有“在新页面看判定器广场 ↗”；“自己写一个”就地展开判定器卡，上面先是名字和说明，下面是现在的贴代码、部署那一套（第 1 节）。
    - 挑了不自动进下一步：接着要填参数。
  - **挑好以后**：
    - 选择区收起成一张卡：名字、来源（站长精选、@作者或“我的”）、第几版、一句说明，右边“查看代码”“换一个”；
    - 下面是它的参数表单，短的两项并一行；保密的项带锁，写“开放后保密，结束后公开”；
    - 再下面是领取提示；
    - **试一试**默认折起，点开才有输入框：输入一段，看这组参数下的判定（发多少、回复），不发钱，不记录。在同一个判定器里跑，计入每人每天 50 次的隐藏上限。
  - 判定器第一版没有自己的图标，都用代码判定的花括号：名字够认，作者也少一件要选的事。
- **从判定器广场来**：“用它发红包”打开 `/new?judge=<编号>`，第 1 步已选好代码判定、第 2 步已选好这个判定器（广场上的那一版），焦点在参数表单的第一项。
- **版本**：草稿记住选的是哪一版。判定器出了新的能用的版本时，判定器卡上写“有第 4 版”，换不换由红包作者决定；开放时锁住那一版和参数。

## 7 联网的判定器

- 白名单写在代码里，用的人改不了，只能看到“会请求这些地址”。
- 用别人做的联网判定器风险大得多：领的人提交的内容会发给对方的服务器，由对方决定发不发、发多少；对方随时能改回答，可能让奖池被某几个人领光，也可能谁都领不到。所以（用户定，2026-10-28：要有充分的风险提示）：
  - 在表单里选中时，先叠一个确认弹窗，标题“这个判定器会联网”，正文三句：
    - “它会把领的人提交的内容发到 xxx。那不是本站，也不是你的服务器。”
    - “判定结果由对方的服务器决定，对方随时能改，可能让奖池被领走，或者谁都领不到。”
    - “只在你信任 @作者 时使用。”
  - 按钮是“返回”和“我知道，继续用”。草稿记住已经确认过，换了版本、白名单变了再问一次。
  - 广场卡片和判定器页上的“联网”标签，点开是这段的短版。
- 用自己做的联网判定器不弹这个，照现在的提示。

## 8 判定器广场 `/judges`

- 独立页面（用户定），游客也能看。顶上是“自己写一个”。
- **三个页签**：站长精选、大家做的、我的（登录后才有）。大家做的能按“最近”“用得最多”排。
- **大家做的只列真的发过红包的**（用户定，2026-10-28：做判定器时会部署出很多版本）：
  - 只列有某一版开放过红包的判定器，站长停用的红包不算；
  - 判定器页上也只列开放过红包的版本，“用它发红包”用的是其中最新的一版；
  - 作者开发时部署的版本，别人看不到。
- **加入广场**：判定器作者自己决定，在判定器页上打开“加入判定器广场”。
  - 打开时确认一次：代码会一直公开（第 2 节）；别人能看代码、用它发红包。
  - 下面一项“允许站长选入精选”，默认勾上（用户定），说明“站长可以原样选入，或者改进后选入，署名保留。”。
  - 退出广场：新的红包不能再选它；已经开放的照旧；已经选进草稿的照样能开放，判定器卡上写“作者已经不在广场提供它”（用户定，免得别人填好的草稿突然开不了）。
- **站长撤下**（用户定，2026-10-28）：站长能把一个判定器从广场撤下，写原因，记进操作记录，同“停用代码判定红包”“停用附带网页”。撤下后新红包选不到它，已经选进草稿的也不能再开放（判定器卡上写“这个判定器已被站长撤下”），已经开放的照常。作者自己的判定器页上看得到撤下的原因。
- **入口**（用户定）：发红包第 2 步、命令 `/judges`、帮助页“代码判定红包 · 开发文档”旁边。起始页和红包广场不放，免得不写代码的人看着困惑。
- **卡片**：
  - 名字、一句说明、作者；
  - 数据“发过 N 个红包 · 判定 N 次 · 领到 N 人次”，只算开放过的红包，部署、测试、试一试都不算；
  - 标签：联网（第 7 节）、精选；
  - 按钮：“用它发红包”（第 6 节）和“查看”。
- **判定器页** `/judges/<编号>`：
  - 名字、说明、作者、数据；
  - 参数：每一项写名字、说明，保密的标出来；
  - 代码：公开的才有；
  - 版本：别人只看到开放过红包的版本；
  - 用它的红包：只列加入了红包广场的；
  - “用它发红包”；
  - **复制一份来改**（用户定）：复制成自己的判定器：带上代码（参数声明就在代码里），不带测试（别人的测试不公开，要自己写），名字下面写“基于 @作者 的判定器”，署名不会丢。要部署过、测试全过才能用，和自己写的一样算部署次数。
- 自己的判定器页另有：
  - 全部版本；
  - 名字、说明、代码公开、加入广场、允许精选这几项设置；
  - 部署新版本（第 1 节）。

## 9 站长精选

用户定（2026-10-28）：

- 两种：
  - **原样选入**：判定器还是作者的，精选的是某一版；
  - **改进后选入**：站长复制一份来改，归站长维护，卡上写“基于 @作者 的判定器”。
- 站长不直接改别人的判定器，否则别人的版本会被改动。
- 只能选“允许站长选入精选”的。作者以后取消授权，只影响以后的精选，已经选入的留着。
- 站长自己写的判定器也能直接放进精选。第一批由站长准备：猜数字、答题（题目和答案表）、每日一题、按等级发不同金额、前 N 个答对的、限时口令。
- 站长的“改进后选入”就是第 8 节的“复制一份来改”，再放进精选。
- 管理在网站管理现有的“判定器”页签里，加一节“精选”（用户定，不另开页签）：选入、移出、排序，以及第 8 节的撤下。

## 10 红包页

- 代码一节写上判定器：“判定器「猜数字」· @作者 · 第 3 版”。精选的写“站长精选 · 基于 @作者”。点名字去判定器页（在广场里的才能点）。
- 公开参数开放时就列出来；保密参数只写有几项和参数封存值。
- 结束后照旧公开代码和种子，再加上保密参数和盐。

## 11 费用

- 参数不算进代码，同一版判定器不管多少红包在用，一天只算 1 份 Dynamic Worker（[代码判定](programmable-hongbao-design.md) 第 7 节）。用的人越多越省。
- 联网的照旧每个红包每天一份。

## 12 不做

- 整个发红包表单由代码声明（第 4 节，用户定）。
- 把经典玩法改成判定器（第 4 节）。
- 判定器的评分、评论：先看数据，以后再说。
- 删除判定器：先不做，以后看需要（2026-10-28 用户定）。

## 13 先后

1. 先上线上一批（代码判定人人能发、商户直发、草稿分享等，[代码判定](programmable-hongbao-design.md) 第 1 节），它不依赖本文。
2. 协议第三版和“我的判定器”：
   - `params`、`hongbao`、`check` 三个导出；
   - 保密参数封存、结束后公开；
   - 判定器单独成一样东西；
   - 代码公开开关；
   - 表单第 2 步，以及试一试。
3. 判定器广场：加入广场、数据、精选、联网的风险提示、一键发红包。

## 14 第 2 步怎么做（2026-10-28 用户看过，定；做到第 5 部分）

第 13 节第 2 步（协议第三版和“我的判定器”）的做法和全部新文案。判定器广场（第 3 步）的文案到时候另给。

### 14.1 分几次做

1. **协议第三版和开发包**：第二版的运行时冻结，和第一版一样存一份副本；第三版加 `meta`、`params`、`hongbao`、`check` 四个导出和 `submission.params`。开发包、`AGENTS.md`、`/help/code` 跟着改。这一步没有界面。
2. **判定器成一样东西**：部署时生成判定器，各版本记在判定器上，不再记在草稿上；判定器卡最上面加名字和说明。

### 14.2 存什么

- **判定器**：作者、名字、说明、代码公开（结束后 / 一直）、基于哪个判定器（第 3 步的“复制一份来改”用）。
- **版本**：判定器上按先后编号，每一版存这些：
  - 代码，和测试全过的那份测试（都加密）、指纹、协议；
  - 读出来的 `meta`、`params`、`hongbao`、`network`，有没有 `check`；
  - 部署时间、过没过。
  - 全部版本都留着，不再只留最近 10 版：别人的草稿可能用着任何一版。
- **草稿和红包**：记住用的是哪个判定器的哪一版，以及填的参数（加密存）。开放时锁住，同现在锁住代码。用别人的判定器时，那一版的测试跟着存进红包，照旧不公开。
- **协议**：新部署的版本跑在第三版上。第二版部署的版本再用时，要在第三版上重新跑一遍测试，不算部署、不扣次数，同第一版升第二版时一样。已经开放的红包照旧用开放时那一版协议。

### 14.3 已有的迁过来

- 每个用过代码的草稿或红包，迁成作者名下的一个判定器（第 1 节）：
  - 名字先用红包标题的前 20 个字；
  - 草稿里部署过的版本都跟过去；
  - 已开放的红包绑着它开放时那一版。
- 代码和版本都是加密存的，数据库迁移读不了，所以由网站自己做：发布后在维护任务里加一项“判定器迁移”，每次迁一批，再跑也不会重复。
- 做的时候改进（2026-10-28）：红包作者自己读到这个红包时（打开编辑页、红包页、我的判定器）当场迁好，不用等维护任务，所以第 2 步不会打不开，也就没有“判定器正在迁移”这句。
- 草稿只迁得过去留着代码的版本：它自己的代码那一版，和“换回”要用的那一版；更早的版本当时就没存代码。
