# 判定器开发文档：让开发者的 Agent 默认就写对

2026-11-01 用户说：

- 生成的代码常把人机验证打开，红包作者不明白为什么有人机验证，体验也不好；
- `[打开矿洞夺宝，点格子开始挖宝](#附带网页)` 这类按钮常放在说明最后，说明长了被折叠，要点“展开”才看得到；
- 带网页的要开 `pageAutoOpen`；
- 带附带网页的判定器现在很常见，说明的优先级要提高，给出最佳做法。

看过分层的方案以后用户说“可以，按你建议的来”。

## 1 为什么会这样

- 样例 `examples/by-level` 写着 `humanCheck: true`；文档只说它是“建议打开领取前人机验证”，没说默认关、什么时候才写。
- 两个带网页的样例（数字炸弹、刮刮乐）的 `note` 都把按钮放在最后；文档只说能写按钮，没说放哪。
- `pageAutoOpen` 10-31 才加，样例、模板和“给 AI 的说明”里都没有。
- `AGENTS.md` 里附带网页是“（可选）”，排在第 351 行（共 455 行），只有 SDK 的接口；Skill 和 Cursor 规则只有一句“去读 AGENTS.md”。

Agent 主要照着样例抄，其次照文档开头写。

## 2 分三层

| 层 | 内容 | 放在哪 |
|---|---|---|
| 一定会被读到 | 第 3 节的“要点” | Skill 正文、`AGENTS.md` 开头、`/help/code` 的“给 AI 的说明”；能自动查的，`npm run check` 再提醒 |
| 按情况读 | 带网页的玩法、认人（鉴权）、自有后端、热闹的玩法 | `AGENTS.md` 按情况分节，Agent 只读和这个玩法相关的；`/help/page` 的“给 AI 的说明”放认人和自有后端的精简版 |
| 上线前过一遍 | 一张短清单 | `AGENTS.md` 末尾 |

Agent 读这些东西的方式：Skill 的一句描述一直在它眼前，用来判断该不该用；决定用了才读正文；`AGENTS.md` 由正文指过去，按需要读；`npm run check` 每次都跑、会照着改，最可靠。

不写：通用的网页常识（无障碍、CDN 怎么配），平台已经强制、协议里写过的限制不再重复。附带网页 SDK 那一大段接口清单压短，细节交给 `page/hb.d.ts` 的类型。

## 3 要点（三处一字不差，测试核对）

源头是 Skill 正文里两行标记之间的一段；`AGENTS.md` 开头照抄，`/help/code` 的“给 AI 的说明”构建时直接引用它。

1. 动手前先问清楚：玩法（输入什么、怎么算输赢）、奖池多大、谁能玩、每人能试几次、什么时候结算、要不要附带网页、要不要自己的后端、要不要联网。没说的按下面的默认做。
2. 人机验证默认不开：不写 `hongbao.humanCheck`。只有红包作者要求，或者玩法很容易被脚本刷（比如按等级白送），才写，并告诉他代价：有些网络和浏览器加载不出验证，这些人领不了。
3. 格子、卡牌、棋盘、动画这类玩法做成带附带网页的。带网页的三件事一起做：`meta.page` 写网页地址；`hongbao.pageAutoOpen: true`，进红包页就打开网页；`hongbao.note` 第一行就是打开网页的按钮，比如 `[打开矿洞夺宝，点格子开始挖宝](#附带网页)`，规则写在下面（说明长了会折叠，按钮放在后面要点“展开”才看得到）。
4. 每个输入都当成手打的来校验：网页可以被绕过，玩家能直接在指令框里提交。
5. 每个人都要有结算的出口：机会用完、牌打完时写 `settle: true`。平台不限提交次数，要限就按 `user.attempts` 自己拒绝。
6. 钱和输赢只由 `judge.js` 算：网页只照着 `view.data` 和 `player.view` 画；自己的后端算出的结果，要经判定器联网核对才算数。
7. 联网失败要在代码里接住，回一句话、不加钱；没接住算出错，连续出错 5 次红包会暂停领取。
8. 网页的后端要认人，用 `hb.identity()` 拿令牌、在后端验证；`hb.ready()` 里的昵称只能用来显示。
9. 会变的东西（答案、范围、次数、几个人能领）做成参数，别写死。
10. 写完跑 `npm test` 和 `npm run check`，照输出改，“提醒”也要看；不删测试凑数。

## 4 `AGENTS.md` 的新结构

1. 开头一句话说这是什么。
2. **要点**（第 3 节），后面一句“按情况读”：带网页 → “带网页的玩法”；后端要认人 → “认人”；有自己的后端 → “自有后端”；人多 → “热闹的玩法”；上线前 → “上线前”。
3. 怎么干活（原有，四条）。
4. 代码协议（原有，不动内容）。
5. **带网页的玩法**（原“附带网页（可选）”，提到这里）：
   - 先问要不要网页；格子、卡牌、棋盘、动画这类做成带网页的。
   - 发布顺序：判定器和测试 → 网页 → `npm run page` 试 → 放到静态托管 → 填 `meta.page` → `npm run check` → 部署。
   - 判定器这边：`meta.page`、`pageAutoOpen`、`note` 第一行放按钮。
   - 网页和判定器怎么配合：
     - 输赢只由判定器算，网页照着 `view.data`（大家看的）和 `player.view`（只给他的）画；个人的东西放 `player.view`，别塞进公开的 `view`。
     - **网页是活的、判定器代码是冻结的**：改了网页，进行中的红包马上用上，但它们还跑开放时那一版判定器。`view.data` 里放一个版本号，网页要能读旧格式。
   - 网页这边：
     - 提交时按钮写“判定中”，用 `hb.submit()` 的回答更新界面；没判定的每种原因都给提示（冷却用 `hb.now()` 倒数，没登录给“登录”按钮调 `hb.login()`）。
     - 用 `hb.on(...)` 订阅变化，不要自己轮询。
     - 先按手机设计：手机上它在底部抽屉里，宽屏上它的窗口最窄约 360。
     - 单独打开网页时 `hb.ready()` 会报错，显示一段说明。
     - 游戏状态不放网页本地，以判定器为准。
   - `npm run page`：换几个人、开冷却（`--cooldown 3`）、选“没登录”都试一遍。
   - SDK 一览（压短，细节见 `page/hb.d.ts`）。
6. **认人（鉴权）**：
   - 三种情况：不需要后端（`player.state`、`player.view`，天然分人）；后端要认人（`hb.identity()`）；后端的结果要发钱（判定器联网核对）。
   - 后端验令牌的清单：用公钥验签（按 `kid` 缓存）；核对 `iss`、`aud`、`exp`（留 30 秒误差）、`hongbao` 是自己认的；防重放（后端先发 `nonce`，核对后作废）；用 `sub`（LINUX DO 数字 ID）认人，不用用户名；数据按“红包编号 + 用户 ID”存。
   - 网页这边：令牌放内存，用 `Authorization` 请求头发，过期再要（不会再问）；不放本地存储、网址、日志；不依赖第三方 Cookie；后端跨域只放行自己的网页来源；在玩家点“开始”这类按钮时再要；不允许就降级成只读，给按钮让他改主意；本地 `npm run page` 签的令牌，上线后的后端不收。
   - 验证示例：Cloudflare Workers / Node，用 `jose`。
7. **自有后端**：
   - 和判定器的分工：后端给“核对接口”，判定器联网问它；联网失败接住；核对接口幂等（同一个凭证问几次答案一样，判定写库失败重判时会再问）；判定器和后端之间用另一把密钥，代码和保密参数结束后公开，结束后换；返回内容红包结束后本人看得到；要快要小（单个请求 10 秒，返回最大 64 KB，只许 GET 和 POST）。
   - 扛住开场：开放时所有人一起来（自动打开网页更是）；静态文件放静态托管；按用户 ID 限流；后端挂了网页能降级，公开数据照样从红包站来；读红包的公开信息几秒一次就够。
   - 放在亚太（玩家大多在国内，联网时判定器在亚太调你的后端）；https、默认端口；允许被红包站嵌入；跨域只放行自己的网页。
   - 对不上时以判定记录为准；数据至少保留到核对完。
   - 测试：`tests.json` 给通过、不通过、500、超时、连不上各写一条；`--live` 真连一次；开场前自己压一下。
8. **热闹的玩法**：别联网（联网的判定一个一个判，每次最多等 15 秒，人多会排队；不联网的能一批一起判）；`view` 只在公开内容真的变了时写（写一次推给所有在看的人）；`announce` 只写值得看的事；`state` 只存要用的；抽奖类防反复刷（限次数或用 `tools.userRandom`）。
9. `tests.json`、`simulate.json`、五个命令、例子（原有）。
10. 常见错误（原有，加三条：写了 `humanCheck`、按钮放在说明最后、带网页没写 `pageAutoOpen`）。
11. **上线前**：先发一个小红包试一轮（奖池小、截止短，看判定记录和出错记录）；`npm run simulate` 模拟几十个人；结束后 `npm run replay` 核对、换掉联网用过的密钥。

- 写了 `humanCheck: true`：“提醒：hongbao.humanCheck 会让用它发的红包默认打开领取前人机验证，有些网络和浏览器加载不出验证，这些人领不了。红包作者没要求就删掉。”
