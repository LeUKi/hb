# 代码判定红包的判定记录（2026-10-30，第 6 条）

用户 2026-10-29：代码判定红包的尝试统计和经典玩法天然不一样，应该因地制宜；缺一个按人看记录的地方；发红包的人要能随时按时间线看到所有记录。现在的匿名统计已经不适合代码判定。

用户 2026-10-30 确认，第 7 节三件都按建议：三个页签；按人汇总表直接加；告诉领的人红包作者看得到（放在指令框的提交规则里，第 3 节）。

## 0 现在有什么

| 哪里 | 谁看 | 有什么 |
|---|---|---|
| 尝试统计页 | 发红包的人 | 四个数：提交次数、提交的人、成功领取、发了的比例；“提交的内容”按内容匿名汇总，每种内容提交了几次、发了几次 |
| 红包页 · 参与名单 · 挑战 | 所有人 | 每个被判定过的人：判定几次、最后一次什么时候、领到没有。没有输入和回复（回复可能漏答案） |
| 红包页 · 我的提交 | 自己 | 自己的每一次：输入、领到没有、判定器的回复 |
| 红包页 · 作者工具 · 出错记录 | 发红包的人 | 判定器出错的那几次和原因 |
| 红包页 · 作者工具 · 判定数据 | 发红包的人 | 整份记录下载下来，用开发包重放 |

缺的是：发红包的人在网页上一条一条看每一次（谁、输入了什么、判定器怎么判的、回复了什么），和看某一个人的全部。

## 1 提议：代码判定红包的尝试统计换成“判定记录”

- 标题“判定记录”，下面一句“每一次提交和判定器的判定，只有你看得到。”
- 顶上四个数：提交 N 次、提交的人 N 人、领到的人 N 人（发出 x LDC）、出错 N 次。
- 三个页签，两段选择的样子同红包记录，记在地址里：**时间线**（默认）、**按人**、**按内容**。
- 开放以后随时能看，结束以后照旧；草稿时同现在“红包开放之后才有人提交。”。

### 1.1 时间线

- 每一次判定一行，新的在上：
  - 第一行：头像、昵称、等级，“第 3 次”，时间（今天的只写时分，别的写日期）；
  - 第二行：输入，等宽字，原样；
  - 第三行：结果。“领到 0.30 LDC”（金额被拉进范围的写“判定器给 0.80，按上限发 0.50”，同名单）；“没领到”；“出错：原因”（灰色，同出错记录）；
  - 有判定器的回复写“回复：……”；这次判定写了动态的再加一行“动态：……”；结束了红包的加一行“判定器结束了这个红包”。
- 筛选，两段选择下面一排小标签：全部、领到的、没领到、出错。
- 一次 20 条，往下滚读下一页（同红包记录）。新的不自动插进来（免得正看着跳）：顶上冒出一条“有 N 次新的提交”，点了回到最新。
- 点头像或昵称：叠出这个人的全部（1.2 的弹窗）。

### 1.2 按人

- 每人一行：头像、昵称、等级；“提交 N 次”；“领到 0.30 LDC”或“没领到”；最后一次提交的时间。
- 排序：最近（默认）、提交多的、领到的在前。
- 点一行叠一个弹窗：标题是昵称，下面“提交 N 次 · 领到 0.30 LDC”，再下面是他的每一次，同时间线的行，**旧的在上**（看他怎么一步步猜过来的）。

### 1.3 按内容

- 就是现在的“提交的内容”：按内容匿名汇总，提交了几次、发了几次，按次数从多到少。说明照旧（文案统一后是“按次数从多到少。发没发按那一次判定器的判定。”）。

## 2 入口

- 现在的入口叫“尝试统计”，在红包页上发红包的人的按钮里，和红包记录那一行的按钮里。代码判定红包改叫“判定记录”，经典玩法照旧“尝试统计”。
- 地址不变，代码判定红包打开就是判定记录。

## 3 谁看得到

- 只有发红包的人，同现在的尝试统计。
- 领到的人的输入在名单里本来就公开；没领到的人的输入、所有回复，现在只在判定数据下载里有，这一页把它们放到网页上，还是只给发红包的人。
- 告诉领的人：代码判定红包的指令框右下角 ⓘ（提交规则）原来写“原样提交：区分大小写，符号都算，首尾空格会去掉”，后面加一句“你的每次提交和判定器的回复，红包作者都看得到。”。

## 4 数据和读的量

- **时间线**：直接按红包和判定的序号倒着分页读判定记录（已有索引），出错的从出错记录按时间读一页，两边合在一起排。不用改表。
- **按人看一个人**：按红包、人、第几次读（已有索引）。不用改表。
- **按人的列表**：现在“参与名单 · 挑战”每读一页，都要把整个红包的判定按人分组一遍，读的行数等于这个红包判定过多少次；提交多了又慢又费 D1 的读行数（2026-10-25 读行数超量那次就是这类读法）。按人页也这样读会更费（还要能按次数、领到排序）。
  - 建议加一张按人汇总的表：红包、人、提交几次、领到没有、领到多少、第一次和最后一次提交时间。每次判定在写判定记录的同一批语句里更新它。按人页和挑战名单都改读它，读的行数是一页的人数。
  - 要一个迁移（已经开放的红包，迁移时从判定记录算一遍填进去）。
  - 也可以先不加表，按人页照挑战名单的读法做，等量大了再加。建议直接加：挑战名单也一起省下来。

## 5 先后

1. 时间线（只读现有的表）和入口改名。
2. 按人：汇总表的迁移、按人页、挑战名单改读汇总表。
3. 按内容：挪进页签，内容不变。

## 6 不做

- 导出表格：判定数据下载已经是整份。
- 实时推送新的一行：用“有 N 次新的提交”代替。
- 站长在网站管理里看别人的判定记录：现在没有这个需要。
