本文整理当前已确定的完整产品业务规则，作为技术方案、界面设计和业务验收的依据，不代表功能已经实现。一期的技术选型、部署与一致性机制见[一期技术方案](technical-design-phase-1.md)。

**一期仅提供作者商户直发和文本奖励，以及对应的活动、兑换、发现、记录与统计功能。** 平台收款、平台代发、平台余额、提现、平台资金占用、结余释放及 12% 费率功能全部后移。本文保留这些后续阶段的业务规则，不将其作为一期开发或验收要求。

第四章第 2–5 节及验收场景 15–17 属于后续阶段；其他章节涉及平台资金的描述也按此阶段划分理解。一期保留商户直发付款任务、自动查单和重试能力，不预建未使用的钱包及资金账本。

## 一、产品定位与基本概念

### 1. 产品定位

平台为 Linux DO 社区提供奖励兑奖服务。

作者在论坛发布谜题、提示和讨论，在本平台创建奖励活动。参与者提交正确口令后，获得作者预先配置的一份奖励。

平台负责：

- 活动创建、信息展示和发现入口。
- 口令校验、奖励分配与领取记录。
- LDC 分发与付款队列；平台余额及提现属于后续阶段。
- 文本奖励的分配与保存。
- 强制专属页活动的兑换尝试统计。

平台不承载谜题编辑、提示编排、解题流程管理。多层奖励通过多个活动、论坛帖子以及领取后信息中的链接自然组合。

### 2. 核心概念

| 概念 | 含义 |
|---|---|
| 活动 | 一个独立兑奖单元，拥有 UUID、有效口令、奖励池、期限和展示设置 |
| 奖励池 | 一个活动内尚待分配的全部奖励 |
| 一份奖励 | 一次成功领取得到的金额或文本 |
| 成功领取 | 已为用户分配并锁定一份奖励，领取资格和内容已经确定 |
| LDC 已确认发放 | LDC 已确认该笔分发成功，平台不再重发；与成功领取分开记录 |
| 余额可用结算 | LDC 将收款方待结算余额转为可用余额，不等同于平台已确认发放 |
| 专属页 | 指定某个活动 UUID 的页面，所有活动都有 |
| 全站兑换 | 未指定活动时，通过口令匹配活动 |
| 帖子索引 | 根据关联的论坛帖子，查询其对应活动 |
| 广场 | 作者主动加入的活动展示列表 |
| 归档 | 活动退出日常发现和全站匹配范围，历史记录及待履行付款继续保留 |

首版每个活动只选择一种奖励类型：**LDC 或文本**。一个帖子可以关联多个活动，因此可以分别提供不同类型的奖励。

一期付款成功统一展示：**“LDC 已确认发放，实际可用时间以 LDC 为准。”** 没有结算证据时，不显示“余额已到账可用”。

### 3. 用户角色

- **访客**：浏览广场、帖子索引和活动允许展示的信息。
- **登录用户**：提交口令、领取奖励、查看自己的领取记录。
- **活动作者**：创建和管理活动、维护商户配置、查看领取记录和符合条件的尝试统计；管理平台余额属于后续阶段。
- **管理员**：配置运营参数、处理无法自动恢复的付款异常；平台代发费率、提现及相关资金记录属于后续阶段。

浏览允许展示的信息不要求登录；提交兑奖和管理个人数据需要登录。领取限制和统计人数以 Linux DO 账号为单位。

## 二、活动配置、奖励与生命周期

### 1. 活动配置

活动包含以下业务配置：

| 分组 | 配置内容 |
|---|---|
| 基本信息 | 活动标题、作者、关联帖子 |
| 兑换规则 | 一个或多个有效口令、是否强制专属页兑换 |
| 奖励 | 奖励类型、份数及对应分配配置 |
| 时间 | 截止时间，默认开放后持续 24 小时 |
| 发现入口 | 是否加入广场 |
| 信息展示 | 数量展示方式、领取记录及其细项 |
| 阶段信息 | 领取前说明、领取后说明、结束后说明 |
| LDC 专用配置 | 一期使用商户直发及对应商户配置；平台代发和资金配置属于后续阶段 |

活动 UUID 使用足够难以猜测的随机标识。UUID 用于定位活动，不代替兑换口令和信息访问规则。

### 2. 口令规则

- 单个口令为 **6–18 个字符**，仅允许汉字、字母和数字。
- 一个活动可以配置多个有效口令，命中任意一个即可参与领取。
- 所有口令共享同一个奖励池、剩余份数和领取限制。
- 同一用户在同一活动中最多成功领取一份，换口令不能再次领取。
- 不同活动允许使用相同口令。
- 口令不绑定特定奖励金额；需要不同奖励池时创建不同活动。
- 不另外提供短数字口令模式。

本文采用以下匹配默认值，作为后续实现依据：

- 去除首尾空白后校验格式。
- 英文字母区分大小写。
- 不做模糊匹配、繁简转换或全角半角自动转换。
- 等价写法由作者明确加入有效口令列表。
- 不增加“必须同时包含汉字、字母或数字中的某几类”之类的额外限制。

### 3. 强制专属页兑换

“强制专属页兑换”在**首次创建活动时确定，此后不可修改**。

| 配置 | 全站口令兑换 | 专属页兑换 | 尝试统计视图 |
|---|---|---|---|
| 未开启 | 支持 | 支持 | 不提供 |
| 已开启 | 禁止 | 支持 | 提供 |

普通活动仍有领取记录和数量信息，但没有尝试统计视图。

从首页通过 UUID、活动链接、广场或帖子索引进入专属页，不违反强制专属规则。该规则限制的是全站口令匹配能力，不限制用户从哪个页面到达活动。

### 4. LDC 奖励

作者填写的金额是**发放金额**。领取者承担自己一侧实际发生的手续费，平台不将发放金额描述为手续费扣除后的净到账金额。

**作者不能领取自己创建的 LDC 活动。** 在分配奖励前拦截，不产生领取记录或付款任务；文本活动不增加此限制。平台尚不能可靠核实实际商户所属账号，因此仍须处理 LDC 返回的其他自付拒绝，不能将作者身份检查视为完整的商户归属验证。

金额配置支持：

| 方式 | 规则 |
|---|---|
| 固定 | 每份金额相同，按份数平均分配 |
| 随机 | 作者选择随机算法，首版包括二倍均值法、波动均值法（预生成） |
| 自定义 | 作者逐份填写金额，再选择顺序发放或不放回随机抽取 |

通用要求：

- 总份数和总发放金额明确。
- 每份金额为正，符合 LDC 支持的金额精度，当前按两位小数处理。
- 所有份额金额之和等于活动总发放金额。
- 固定模式无法精确均分时，要求调整配置，不暗中产生不同金额。
- 所有份额金额在活动开放前预生成并固定，开放后按既定方式分配。
- 成功分配后金额固定，不因付款排队、失败重试而重新抽取。

随机金额保存草稿时预生成，只有准备中修改总额、份数或算法时重新生成；修改其他配置、正式开放和请求重试不改变金额池。两种算法都采用不放回随机领取，不保证每份不同，也不宣称所有金额组合等概率。

二倍均值法根据剩余金额和剩余份数逐份生成，给其他份额保留至少 0.01 LDC，最后一份取得余款。波动均值法固定围绕初始均值上下 50%，上下界按 0.01 LDC 向外取整、每份最低 0.01 LDC，并确保总额守恒；只有一份时取得总额。具体整数公式见[技术方案](technical-design-phase-1.md#随机金额的版本化规则)。

### 5. 文本奖励

作者逐份录入文本，每个库存条目代表一份奖励，可选择顺序发放或不放回随机抽取。

文本可以用于兑换码、兑换链接或其他自定义交付内容。

- 一次领取分配一个条目。
- 同一库存条目不能重复分配。
- 分配后的文本只能由对应领取者和作者查看。
- 领取者可在自己的领取记录中再次查看。
- 文本奖励不受兑奖口令的 6–18 字符限制。
- 公开领取记录不能展示奖励文本的具体内容。
- 平台保证库存条目的分配关系，不保证第三方兑换码在外部系统中的有效性。

文本奖励与“领取后说明”不同：前者是分给某个人的奖励，后者是所有成功领取者可以看到的通用说明。

### 6. 阶段信息

三个字段均为选填：

| 字段 | 展示规则 |
|---|---|
| 领取前说明 | 访问活动页面时可见，领取后继续保留 |
| 领取后说明 | 成功分配奖励后，仅对已领取用户可见 |
| 结束后说明 | 活动结束后，对能访问该页面的用户展示 |

领取后说明在**奖励分配成功时**解锁，不等待 LDC 确认发放或结算为可用余额。

作者可以在这些字段中放置论坛链接、后续活动链接或其他信息。平台不赋予其“提示”“题解”等专门语义。

共享说明显示作者维护的当前内容；已经分配的奖励金额或私有文本保持固定。

### 7. 生命周期

| 状态 | 含义 |
|---|---|
| 准备中 | 尚未正式开放，包括配置未完成；后续平台代发还包括尚未满足资金要求 |
| 进行中 | 已正式开放、尚未到期且仍有未分配奖励 |
| 已结束 | 已到期、奖励已经领完，或在没有任何领取时由作者提前结束 |
| 已归档 | 实际结束满 72 小时后，退出日常发现和匹配范围 |

具体规则：

- 默认期限从**正式开放领取**开始计算，为 24 小时；后续平台代发等待入金的时间不占用默认期限。
- 作者可以设置具体截止时间，正式开放时该时间必须尚未到达。
- 领完或到期立即结束。
- 已有成功领取后，作者不能手动提前结束。
- 正式开放后截止时间只可延长，不能缩短；结束后不能通过延长期限重新开放。
- 实际结束满 72 小时自动归档。
- 结束和归档不以全部付款完成为前提。
- 归档不删除记录、不停止付款，也不收回已分配奖励。
- 作者和领取者分别可在“我的已创建”“我的已领取”中查看全部历史。
- 已知 UUID 仍可访问归档后的原页面，继续遵守原有信息权限。

### 8. 开放后的修改权限

正式开放后：

**允许修改：**

- 新增有效口令，总数最多 5 条；历史超过 5 条的集合保留，不再新增。
- 阶段说明和非关键展示文案。
- 数量展示（精确／模糊）与领取名单总开关。
- 关联帖子（主题 ID 与回复序号）；结束及归档后也可修改。
- 延长截止时间。
- 在满足条件时开启“加入广场”。

**不允许修改：**

- 删除已有有效口令。
- 奖励类型、奖励池内容、份数、金额和分配方式。
- LDC 发放方式及活动所对应的付款主体。
- 强制专属页配置。
- 首次开放时间。
- 已经开启的广场收录状态。

新增口令不追溯补发此前失败的尝试。原本失败的用户需要重新提交，且当时活动仍须可领取。

商户凭证的更新属于维护付款能力，不改变活动所承诺的付款主体和奖励。一期允许更新同一商户应用 `client_id` 的密钥，不能将未决付款换到另一商户应用重新支付。

## 三、兑换入口、发现与统计

### 1. 统一兑换界面

首页和专属页使用同一套界面，通过当前是否指定活动区分行为：

| 当前范围 | 输入行为 |
|---|---|
| 全站 | 输入口令后匹配活动；单个匹配直接处理，多个匹配展示列表供选择 |
| 指定活动 | 只校验当前活动的口令 |

首页提供“定位活动”入口，可输入 UUID、完整活动链接或论坛帖子链接。

- UUID、活动链接：进入对应活动。
- 帖子链接：查询关联活动，单个结果直达，多个结果展示列表。
- 从广场点击活动：进入对应专属页。
- 全站口令匹配到多个活动时，展示活动卡片列表；选择后进入专属页，保留已输入口令，先查看信息再确认领取。
- 返回全站兑换时，清除当前指定的活动范围。
- 界面必须清楚显示当前是全站兑换，还是正在兑换某个具体活动。

### 2. 全站匹配规则

**先筛选全部候选：单个匹配沿用直接兑换，多个匹配展示列表，由用户选择活动后确认领取。**

候选活动必须同时满足：

1. 已经正式开放过。
2. 未强制专属页兑换。
3. 尚未归档。
4. 提交口令命中其有效口令。

每个活动在结果中只出现一次。多个匹配按首次正式开放时间从新到旧排列，相同时间保持稳定排序；“最新”只影响排列，不排除其他活动。

以下条件不用于跳过候选：

- 活动已经结束。
- 当前用户已经领取。
- 当前用户的奖励尚未确认发放或尚未结算为可用余额。
- 当前用户是 LDC 活动作者。
- 活动没有加入广场。
- 活动没有关联帖子。

按匹配数量处理：

| 匹配结果 | 首页行为 |
|---|---|
| 没有活动 | 提示未匹配到活动 |
| 一个活动 | 沿用直接兑换流程；已结束则展示状态，本人已领取则展示原记录 |
| 多个活动 | 展示全部匹配活动的卡片列表，由用户选择进入专属页 |

多个匹配的交互与展示规则：

- 列表复用广场卡片样式和活动的信息展示规则，**不套用广场的收录条件**；未加入广场、没有关联帖的匹配活动也会出现。
- 已结束、本人已领取、奖励待付款的活动仍保留在列表中，并标明相应状态；多个匹配全部已结束时，仍展示列表供查看。
- 点击卡片进入对应专属页，保留本次输入的口令，无需重新输入；先查看活动信息，再点击“领取”完成兑奖。
- 展示列表和进入页面不占用奖励、不锁定金额，也不解锁领取后信息。
- 用户可以返回匹配列表继续选择其他活动。领取限制以活动为单位，同一用户可以分别领取多个同口令活动，每个活动仍最多领取一次。
- 领取时重新检查当前活动的状态和库存；如果已经结束，只展示当前活动的状态，不自动替用户领取其他活动。
- 列表展示后活动发生变化，进入专属页时显示最新状态；已经归档的页面仍可查看历史信息，但不能重新领取。
- 查询和浏览列表不计入领取数，也不产生尝试统计；普通活动从列表进入专属页后仍不提供尝试统计视图。

单个匹配直接兑换，或用户选择活动后确认领取时，按以下规则处理：

| 情况 | 结果 |
|---|---|
| 进行中且本人未领，但本人是 LDC 活动作者 | 提示作者不能领取自己创建的 LDC 活动，不分配奖励 |
| 进行中且本人未领，并且不受上述自领限制 | 尝试分配一份奖励 |
| 本人已领 | 展示原领取记录 |
| 已结束但未归档 | 展示结束状态和允许查看的信息 |
| 已结束且本人已领 | 同时展示结束状态和本人领取记录 |
| 已归档 | 展示历史信息及本人原领取记录（如有），不能重新领取 |
| 分配时恰好领完或到期 | 返回该活动已结束，不改选其他活动 |
| 操作中出现更新活动 | 本次继续处理已经选定的活动 |

本次选中的活动不能领取时，**不自动改领其他活动**；用户可以主动返回匹配列表重新选择。

强制专属活动不允许通过“首页输入正确口令后自动定位或跳转”的方式绕过入口限制。

已归档活动从后续匹配结果中移除；其他符合条件的同口令活动始终可以出现在结果中，无需等待较新活动归档。

### 3. 专属页兑换

所有活动都有专属页。

- 始终只校验当前 UUID 对应的活动。
- 不因口令错误、领完、到期或本人已领取而转向其他活动。
- 正确口令只有在成功分配奖励后才形成领取记录。
- 作者不能领取自己创建的 LDC 活动；在分配奖励前拦截，不自动转向其他活动，文本活动不增加此限制。
- 并发领取不能超发，同一用户不能重复取得奖励。
- 未成功分配时，不扣减可领取份数。
- 成功分配后立即扣减份数、保存奖励并解锁领取后说明。

### 4. 帖子索引

不设置统一的“公开／不公开”状态。

**作者填写关联帖子，就表示允许通过该帖子反向查到活动，不受广场开关影响。**

- 允许关联他人发布的帖子。
- 同一帖子可以关联多个作者的多个活动。
- 索引明确展示各活动的发放者；关联不代表楼主认可。
- 帖子按主题 ID 与回复序号共同标识；不同回复不混合。缺少回复序号按 1，规范链接始终包含回复号，丢失过的历史回复统一回填 1。
- 正常索引包含正式开放过、尚未归档的关联活动。
- 进行中和已结束活动均可出现。
- 准备中和已归档活动不出现在正常索引中。
- 过滤后一个结果直接进入专属页，多个结果展示列表，没有结果则说明暂无可查询活动。

关联帖子字段应告知作者：

> 填写后，用户可通过该帖子链接查询到本活动，无需加入广场。

### 5. 广场

广场是独立发现入口，由“加入广场”控制。

- 加入前必须有关联帖子，并具备必要基础信息。
- 默认不加入。
- 开启后不能手动撤回。
- 可以展示进行中和已结束活动，并明确区分状态。
- 活动归档后自动退出广场。
- 自动归档不等于作者撤回广场收录。

广场条目采用最小展示原则，点击后进入专属页。卡片不维护独立的信息权限，沿用活动的展示设置。

### 6. 信息展示

用于识别活动和理解领取条件的基础信息包括：

- 活动标题、发放者、奖励类型。
- 活动状态和截止时间。
- 已配置的关联帖子。
- LDC 活动的发放方式，以及是否可能排队付款。

这些基础信息不能被可选细节开关整体关闭。

作者可调整：

- 数量展示：精确、模糊，默认精确。旧隐藏和仅显示是否还有统一转换为精确。
- 领取名单总开关，默认开启。开启同时显示用户名、领取时间和 LDC 发放面额；没有子开关。旧关闭名单保持关闭，旧开启名单统一显示这三项。

精确展示包含总份数、已领取份数和剩余份数；模糊展示只返回状态等级，服务端不返回精确数量。

数量均按奖励是否已经分配计算，与 LDC 是否确认发放或结算为可用余额无关。

领取名单和活动状态本身可能透露部分进度。文本奖励内容不进入任何公共列表，文本活动名单也没有金额字段。

### 7. 尝试统计

只有强制专属页活动提供尝试统计视图，归档后作者仍可查看。

统计事件是：

> 登录用户主动提交一条符合格式要求的口令，并实际进入该活动的校验。

正确和错误口令均可记录。以下行为不计入：

- 只浏览页面或输入但未提交。
- 格式不合法。
- 在校验前被限流拦截。
- 同一次请求的重复点击或网络重发。
- 已领取后再次查询原记录。
- 活动已结束后的提交。
- LDC 付款或重试。

作者可查看：

| 指标 | 含义 |
|---|---|
| 总尝试次数 | 去除重复请求后的实际校验次数 |
| 独立尝试人数 | 提交过口令的不同账号数 |
| 提交内容聚合 | 用户提交的口令原文、次数和人数 |
| 命中情况 | 提交时是否命中有效口令 |
| 成功领取数 | 通过对应口令成功分配的奖励份数 |

补充规则：

- 同一用户主动提交同一错误口令三次，计三次尝试、一人。
- 校验命中但分配时已经领完，不计成功领取。
- 后续新增有效口令，不改写此前提交时的校验结果。
- LDC 待付款仍算成功领取，支付重试不增加统计。
- 统计仅作者可见，默认按提交内容聚合，不提供用户完整失败轨迹。
- 公开领取名单不连带公开尝试统计。
- 全站失败输入不分配给任何作者。
- 普通活动进入专属页，也不因此开启统计视图。
- 全站多匹配列表的查询和浏览不计入尝试统计或领取数；从该列表进入普通活动的专属页后，只有实际成功分配奖励才增加正常领取记录和领取数。

提交区域应说明：

> 提交的口令将供活动作者查看，用于兑换尝试统计。

## 四、LDC 资金、余额与付款

一期实现第 1 节商户直发与第 6 节付款队列。第 2–5 节保留为后续阶段规则，一期不提供对应界面、资金账本或资金操作。

### 1. 商户直发

作者维护 LDC 商户应用配置，活动使用对应应用付款。配置管理者身份不等于已经验证的 LDC 商户所有者身份，平台不宣称具备可靠的商户归属验证能力。

- 平台负责按领取结果创建和处理付款任务。
- 活动资金来自所配置的 LDC 商户应用，不产生平台入金或平台余额。
- 不提供“平台已预存资金”的标识。
- 同一 `client_id` 在平台内只有一个商户配置和付款调度入口。
- 每个账号至多一个当前商户；历史商户保留既有活动和付款维护能力，但不能用于新活动开放。新草稿绑定当前商户，旧草稿须明确重新绑定同模式当前商户，不改变已生成金额池。
- 新开放 LDC 活动要求当前商户的当前凭证版本最近十分钟检查通过；缺少有效结果时自动检查，草稿保留，最终开放事务再次核对版本。已开放活动重复开放返回原结果。
- 已开放活动在凭证未验证、检查中、认证失败或网络异常时继续允许领取并锁定奖励，付款等待可用凭证恢复。凭证变化不延长活动期限、不换奖、不清除未知结果。文本活动不依赖商户或凭证。
- 网络异常、额度限制等问题优先自动查单、等待和恢复；凭证失效或外部资金不足由作者维护，无法安全自动恢复的冲突才进入异常处理。
- 更新同一 `client_id` 的凭证不能导致已领取奖励重新抽取或重复付款，也不能绕过未决付款的核对。

### 2. 平台代发（后续阶段）

作者通过正常付款将资金转入平台，或者使用已有平台余额。

- 活动需要足额资金才能正式开放。
- 开放时为活动占用对应资金。
- 领取成功后，将相应资金保留为对领取者的待付奖励。
- 实际发放受平台账户可用额度约束。
- 页面明确说明奖励资金已预存，以及可能排队付款。
- 预存不表示承诺立即到账。

### 3. 入金与费率（后续阶段）

平台不额外叠加服务费，向作者收取的补足金额用于覆盖收款环节的手续费。

管理员可配置费率，当前默认 **12%**。

计算口径：

> 所需外部付款＝新增净资金需求 ÷（1－费率）

按支付支持的最小单位向上取整。费率和金额在付款订单生成时固定，后续修改管理员费率不影响已有订单。

例如：

- 活动需发放 100 LDC，没有可用余额。
- 作者应付 `100 ÷ 0.88`，向上取整为 **113.64 LDC**。

已有余额不重复承担收款手续费：

- 活动需 100 LDC，已有可用余额 40 LDC。
- 只对剩余 60 LDC 倒算新增付款金额。

资金确认到账后，按**实际净入金**记账。实际净额不足时不开放活动；超出所需占用金额的部分进入作者可用余额。

### 4. 作者余额（后续阶段）

作者余额区分可用资金和已占用资金。

已占用资金包括：

- 进行中活动尚未分配的奖励资金。
- 已领取但尚未完成付款的奖励资金。
- 待处理提现资金。

同一笔资金不能同时支持活动和提现。

活动结束时：

- 未领取部分释放到作者可用余额。
- 已领取但未付款部分继续保留用于发放。
- 不等待归档才释放未领结余。
- 同一笔结余不能重复释放。

商户直发活动不产生平台预存结余。

所有余额变动应能关联到入金、活动占用、结余释放、奖励付款或提现记录。

### 5. 提现（后续阶段）

作者可以申请提取可用余额，由管理员处理。

- 只能申请未被占用的余额。
- 提交申请后立即占用相应金额。
- 提现金额按发放金额理解，作者作为收款人承担自己一侧的手续费。
- 成功支付后结清。
- 被拒绝或确认不再执行的申请，释放对应占用。
- 付款结果不明时保持占用，不能同时释放余额和重试付款。

提现也受平台账户实际可用额度约束。

### 6. 付款队列

商户直发和后续平台代发都需要可靠的付款队列。一期按商户应用 `client_id` 隔离调度，不将其描述为已经验证的实际付款账号隔离。

基本流程：

> 奖励分配成功 → 生成付款任务 → 等待或执行 → 确认发放／自动查单与恢复／异常处理

业务要求：

- 同一领取记录只对应一笔应付奖励。
- 商户应用 `client_id`、业务号、收款人稳定身份、金额和所属活动固定；所有重试使用原应用、原业务号和原付款参数。
- 一期在对应商户应用下按任务先后处理；已明确可以安全等待或重试的失败任务不使整队永久停顿。
- 额度不足时保留任务，等待后续可用额度。实际每日额度按 LDC 付款账号共享，可能受其他商户应用及平台外交易影响；一期无法可靠识别共享账号或准确读取剩余额度，以 LDC 实际响应为准。
- 网络超时、响应丢失、发送进程中断及发送占用过期不直接等同付款失败；先自动查询原业务号，再决定是否重试。
- 付款结果不明时，只暂停对应商户应用的新发送，继续自动查单；核对清楚后自动解除暂停，其他商户应用继续处理。
- 查单暂时不可用或未找到时持续退避核对，不立即转人工。“未找到”或非成功状态不能独立证明此前没有扣款；原号安全重试以线上唯一约束和事务契约验证通过为前提。
- 作者可更新同一商户应用凭证、在 LDC 补足资金并触发检查；这些操作不能绕过未决付款保护。平台不为此提供充值或余额功能。
- 普通付款不适用独立线上验收的五次或二十四小时上限；持续承担付款责任，长期等待只调整频率。每次恢复发送先查询原单，已有订单证据只可增加，不因后续失败重新取得发送资格。
- 停止新开放、新领取、新发送分别控制。停止新领取仍可读取原奖励和幂等回放，停止新发送仍查原单，在途请求结果继续保存。普通付款不自动进行成功后的重复请求验证。
- 无法自动解释的订单冲突或业务拒绝进入异常处理。人工介入用于不能安全自动恢复的情况，不能以盲目重发替代核对。
- 付款异常不能让奖励重新进入可领取库存。
- 后续平台代发中，已分配奖励不能因付款失败自动退回作者可用余额。
- 活动结束、归档或退出列表都不取消付款责任。
- 任务投递或执行中断须可补偿；队列重复投递不重复付款，进入死信队列也不取消应付奖励。

领取者可查看自己的待发放、发送中、核对中、等待恢复、已确认发放或异常待处理状态。LDC 成功分发先进入收款方待结算余额，平台显示“LDC 已确认发放，实际可用时间以 LDC 为准”，不将发放确认等同于余额已经可用。未核实容量和结算规则前，不承诺精确到账日期，一期也不依赖尚未确认存在的分发回调。

## 五、业务验收、默认值与后续边界

### 1. 核心验收场景

以下为业务验收基线，逐项实施和验证状态见实施记录；本地模拟不代表真实付款验收通过。编号 15–17 只属于后续平台资金阶段；其他场景按一期商户直发与文本奖励范围执行。

1. 首页和专属页使用统一兑换界面，并能明确识别当前兑换范围。
2. 强制专属配置创建后不可修改，全站输入正确口令也不能绕过。
3. 同一用户使用不同有效口令，不能在同一活动重复领取。
4. 两个同口令活动同时进行时，均出现在匹配列表中，用户可分别选择和领取；最新只影响排序，不排除其他活动。
5. 活动归档后从后续匹配结果中移除，其他符合条件的同口令活动保持可匹配，无需等待较新活动归档。
6. 最后一份奖励被多人同时领取时，只能成功分配一次。
7. 分配过程中到期或领完，不自动改领其他活动。
8. LDC 金额锁定后不因付款重试改变；文本库存条目不重复分配。
9. 领取后说明在分配完成时解锁，不等待付款。
10. 强制活动正确记录错误原文、提交次数、账号人数和领取数，网络重发不重复计数。
11. 普通活动没有尝试统计视图，全站失败输入不归属给作者；匹配列表查询、浏览和进入普通活动专属页不产生尝试统计，成功领取仍形成正常领取记录。
12. 未加入广场的关联活动仍能通过帖子索引找到；允许同帖有多个作者的活动。
13. 已结束活动继续展示，结束满 72 小时归档后退出正常索引、广场和全站匹配。
14. 归档后个人记录、私有文本和待付款任务继续保留。
15. **后续阶段：** 平台代发未足额入金不能开放，100 LDC 在 12% 费率下按 113.64 LDC 生成付款需求。
16. **后续阶段：** 已有余额复用不重复收取入金手续费，未领结余释放后不能重复计入余额。
17. **后续阶段：** 已领取待付金额不能提现；提现申请占用的余额不能再次用于活动。
18. 开放后只能补充口令，不能删原口令或修改奖励池；新增口令不追溯补发。
19. 领取侧手续费由收款人承担，界面不混淆发放金额与净到账金额。
20. 数量、名单、金额等展示设置在专属页、广场摘要、帖子索引摘要和全站匹配卡片中保持一致，不泄露私有文本奖励。
21. 同口令活动一个进行中、一个已结束时，两者都出现在匹配列表中，结束活动不阻挡另一个；多个匹配全部已结束时，仍展示列表供查看。
22. 本人已领取和奖励待付款的活动继续展示，进入后可查看原记录，不重复分配。
23. 强制专属、准备中和已归档活动不参与全站匹配；未加入广场、没有关联帖的普通活动正常参与，每个匹配活动只出现一次。
24. 多匹配时点击卡片只进入详情并保留已输入口令，不占用奖励、不锁定金额、不解锁领取后信息，确认领取后才分配奖励。
25. 零个匹配提示未匹配到活动，单个匹配沿用直接兑换及状态展示；多个匹配不自动选择最新活动。
26. 列表展示后活动恰好结束或归档，进入时显示最新状态或历史记录，不能重新领取；实际分配前重新检查状态和库存，不自动改领其他活动。
27. 作者自己的 LDC 活动仍参与正常全站匹配，但在分配前禁止自领，不扣库存、不生成付款任务、不自动改领其他活动；文本活动不增加此限制。
28. 所有 LDC 份额金额在开放前固定，领取和付款恢复都不重新生成金额。
29. 超时、响应丢失、发送中断和队列重复后自动核对原业务号；只暂停对应商户应用的新发送，查单继续，核对清楚后自动恢复。
30. 同一付款始终使用原商户应用、业务号、收款人稳定身份和金额；更换密钥不能绕过核对或重复付款，无法核实的结果不被当成明确失败重发。
31. LDC 确认分发成功后停止重发，展示“LDC 已确认发放，实际可用时间以 LDC 为准”，不宣称收款方余额已经可用。

### 2. 本文采用的默认值

这些是文档中的默认产品行为，作者仍可调整允许配置的项目：

| 项目 | 默认值 |
|---|---|
| 活动持续时间 | 正式开放后 24 小时 |
| 归档时间 | 实际结束后 72 小时 |
| 强制专属页 | 默认关闭，创建时可选择，之后不可改 |
| 加入广场 | 默认关闭，开启后不可撤回 |
| 关联帖子 | 选填；填写即进入正常帖子索引范围 |
| 数量展示 | 精确 |
| 领取名单 | 默认开启，用户名、时间及 LDC 发放面额一起展示 |
| 阶段说明 | 默认空，均为选填 |
| 平台收款费率（后续阶段） | 12%，管理员可调整；一期不提供费率功能 |
| 每活动领取次数 | 每账号最多一次 |
| 每活动奖励类型 | LDC 或文本，二选一 |

### 3. 接入时需要核实的外部条件

以下不改变业务目标，但会影响具体实现，不能在核实前写成平台已有能力或对用户的承诺：

- 一期验证线上分发成功响应、商户查单、重复业务号行为、失败响应及异常对账语义。官方公开源码已提供查询分发订单、商户与业务号联合唯一约束及事务内分发的可行性依据，但不能把源码版本视为线上部署或契约验证的证明，证据见[一期技术方案](technical-design-phase-1.md)。
- 一期验证 Linux DO Connect 稳定账号身份与 LDC 收款身份的对应关系、可变用户名处理，以及论坛帖子身份的可靠获取方式；不能只凭用户名推定收款人。
- 一期验证商户等级对应的额度单位、限制、拒绝语义、重置时区及单次金额范围；没有可靠商户账号归属和剩余额度接口时不展示已验证归属或精确余量。
- 一期验证发放成功和查单成功所能证明的状态、收款方待结算余额与可用余额的区别，以及领取侧手续费、扣费方和取整规则。
- 平台收款、平台代发和提现的接口范围、实际净入金、资金可用时间及各环节费用留到后续资金阶段验证。
- 自然付款、接口分发与升级积分之间的实际关系在后续平台收款阶段核实，不作为一期承诺。

当前业务基线与[一期技术方案](technical-design-phase-1.md)共同作为分阶段实施和随机算法细则的依据。已实现文本兑奖与发现统计，LDC 的固定、自定义、两种随机金额及自动恢复已通过本地模拟验收；另有一笔受控真实发放及同号重复验证通过，普通真实活动已完成本轮限定的生产试运行闭环验收。环境与数据库控制继续保留；用户已确认套餐升级，升级后的实际 Workers 配额与 CPU 预算、额度拒绝与恢复、净收款及结算可用时间仍为后续验证项。完成状态和联调证据见[一期实施记录](implementation-phase-1.md)。不重新引入已移除的统一“公开”状态，也不将平台扩展为谜题管理系统。


## 活动配置与多口令规则（2026-10-05 修订）

创建和编辑共用单页分区：活动与奖励、展示设置、默认折叠的更多设置、底部摘要与操作。展示设置内关联帖子与广场开关相邻，校验错误定位当前字段；更多设置内有错误时自动展开。输入仅保存在页面内存，保留离开提醒。统一奖励方案包含文本顺序／随机，LDC 固定每份金额×份数、二倍均值、初始均值上下50%、自定义顺序／随机。方案切换保留各自临时输入，只有当前方案校验和提交，固定金额内部使用顺序发放。

主操作“保存并开放”保存同一个草稿后检查当前凭证，检查通过自动开放，不再要求第二次点击。次操作单独保存草稿。续接只在当前页面有效，绑定活动、商户和凭证版本；退出、离开或版本变化停止后续请求。网络未知时重放原创建请求，不能额外建立活动。正式开放才开始计算默认24小时。

作者可以删除从未开放且没有领取／付款关联的草稿。删除保留创建幂等墓碑，清理私有口令和库存；重复删除安全返回，原创建请求重放返回活动已删除。不能恢复删除草稿或把已经开放的活动当成草稿删除。

进行中的专属页：作者看全部答案；已领取者只看本人的领奖口令与本人后来解出的口令，其余仅显示数量，不返回未知答案、摘要或逐条标识。已领取者可继续验证其他口令；验证不会分配库存、增加领取次数、生成付款或Outbox，付款等待恢复也不影响继续验证。结束和归档后所有访客看到全部答案，只有本人看到“我的领奖口令／我已解出”标记，不公开其他用户的解出状态。口令不进入公共卡片。

领取和解出共用每账号每活动60秒10次实际校验额度，网络重放不计数。提交UUID绑定用途、活动和口令，错误结果不因后来新增答案被改写；重复命中只保留一个已解出答案。强制专属的解出计入尝试和命中，成功领取数不变。普通活动不保存失败口令原文；历史already_claimed请求不作为解出证据。结束判断即时执行，不等待Cron，结束后不再接受新的解出操作。
