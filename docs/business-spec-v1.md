## 一、产品定位与基本概念

### 1. 产品定位

平台为 Linux DO 社区提供奖励兑奖服务。

作者在论坛发布谜题、提示和讨论，在本平台创建奖励活动。参与者提交正确口令后，按活动类型取得即时奖励或一次限时开奖报名资格。

平台负责：

- 活动创建、信息展示和发现入口。
- 口令校验、奖励分配与领取记录。
- LDC 分发与付款队列；站内🐟额的转入和转出（第四章）。
- LDC 金额分配、报名、开奖与付款恢复。
- 强制专属页活动的兑换尝试统计。

平台不承载谜题编辑、提示编排、解题流程管理。多层奖励通过多个活动、论坛帖子以及领取后信息中的链接自然组合。

### 2. 核心概念

| 概念 | 含义 |
|---|---|
| 活动 | 一个独立兑奖单元，拥有 UUID、有效口令、奖励池、期限和展示设置 |
| 奖励池 | 一个活动内尚待分配的全部奖励 |
| 一份奖励 | 一次成功领取得到的 LDC 金额 |
| 成功领取 | 已为用户分配并锁定一份奖励，领取资格和内容已经确定 |
| LDC 已确认发放 | LDC 已确认该笔分发成功，平台不再重发；与成功领取分开记录 |
| 余额可用结算 | LDC 将收款方待结算余额转为可用余额，不等同于平台已确认发放 |
| 专属页 | 指定某个活动 UUID 的页面，所有活动都有 |
| 全站兑换 | 未指定活动时，通过口令匹配活动 |
| 帖子索引 | 根据关联的论坛帖子，查询其对应活动 |
| 广场 | 作者主动加入的活动展示列表 |
| 归档 | 活动退出日常发现和全站匹配范围，历史记录及待履行付款继续保留 |

活动只提供 **LDC** 奖励，支持固定、自定义、随机金额和限时开奖。一个帖子可以关联多个活动。

一期付款成功统一展示：**“已发放”** 没有结算证据时，不显示“余额已到账可用”。

### 3. 用户角色

- **访客**：浏览广场、帖子索引和活动允许展示的信息。
- **登录用户**：提交口令、领取奖励、查看自己的领取记录。
- **活动作者**：创建和管理活动、维护商户配置、查看领取记录和符合条件的尝试统计。
- **管理员**：配置运营参数、处理无法自动恢复的付款异常；管理站内🐟额的平台应用、费率、白名单，查单、确认到账和调整🐟额。

浏览允许展示的信息不要求登录；提交兑奖和管理个人数据需要登录。领取限制和统计人数以 Linux DO 账号为单位。

只通过本站官方 Connect 登录，所有账号的权限相同（青春版与 LiteAuth 登录已于2026-10-15取消，见文末同日章节）。活动和付款使用本站商户记录ID关联，Client ID是上游付款身份快照。

## 二、活动配置、奖励与生命周期

### 1. 活动配置

活动包含以下业务配置：

| 分组 | 配置内容 |
|---|---|
| 基本信息 | 活动标题、作者、关联帖子 |
| 兑换规则 | 一个或多个有效口令、是否强制专属页兑换 |
| 奖励 | LDC 金额方式、份数及对应分配配置 |
| 时间 | 即时活动默认开放后持续24小时；限时活动采用倒计时或指定开奖时间，默认倒计时600秒 |
| 发现入口 | 是否加入广场 |
| 信息展示 | 精确／模糊数量及领取名单总开关 |
| 阶段信息 | 领取前说明、领取后说明、结束后说明 |
| LDC 专用配置 | 商户直发用作者的商户配置；站内🐟额用平台应用 |

页面按活动名称与奖励配置、“参与与分享”“更多设置”和“摘要与操作”组织，首段不再显示“活动与奖励”二级标题。“参与与分享”包含关联帖子／回复、加入广场和强制专属页兑换；数量展示、领取名单、即时活动期限及阶段说明放入默认折叠的“更多设置”，有校验错误时展开并定位。

活动 UUID 使用足够难以猜测的随机标识。UUID 用于定位活动，不代替兑换口令和信息访问规则。

### 2. 口令规则

- 单个口令为 **6–18 个字符**，仅允许汉字、字母和数字。
- 一个活动可以配置多个有效口令，命中任意一个即可参与领取。
- 所有口令共享同一个奖励池、剩余份数和领取限制。
- 同一用户在同一活动中最多成功领取一份，换口令不能再次领取。
- 不同活动允许使用相同口令。
- 口令不绑定特定奖励金额；需要不同奖励池时创建不同活动。
- 不另外提供短数字口令模式。

本文采用以下匹配默认值，作为后续实现依据：

- 去除首尾空白后校验格式。
- 英文字母区分大小写。
- 不做模糊匹配、繁简转换或全角半角自动转换。
- 等价写法由作者明确加入有效口令列表。
- 不增加“必须同时包含汉字、字母或数字中的某几类”之类的额外限制。

### 3. 强制专属页兑换

“开启口令尝试统计（口令仅在活动页兑换）”在草稿阶段可双向切换，**首次正式开放后不可修改**；已结束、已归档且曾开放的活动同样锁定。

| 配置 | 全站口令兑换 | 专属页兑换 | 尝试统计视图 |
|---|---|---|---|
| 未开启 | 支持 | 支持 | 不提供 |
| 已开启 | 禁止 | 支持 | 提供 |

普通活动仍有领取记录和数量信息，但没有尝试统计视图。

从首页通过 UUID、活动链接、广场或帖子索引进入专属页，不违反强制专属规则。该规则限制的是全站口令匹配能力，不限制用户从哪个页面到达活动。

### 4. LDC 奖励

作者填写的金额是**发放金额**。Credit 按付款商户（发红包的人）的支付等级扣分发费（4%–15%），从领取者的到账里扣除；平台不把发放金额说成净到账金额，表单写明这条规则和费率范围。

**作者不能领取自己创建的 LDC 活动。** 在分配奖励前拦截，不产生领取记录或付款任务。平台尚不能可靠核实实际商户所属账号，因此仍须处理 LDC 返回的其他自付拒绝，不能将作者身份检查视为完整的商户归属验证。

金额配置支持：

| 方式 | 规则 |
|---|---|
| 固定均分 | 每份金额相同，填写每份金额与奖励份数 |
| 即时随机 | 填写总额、份数及随机算法，保存草稿时预生成金额 |
| 自定义金额 | 作者逐份填写金额，再选择顺序发放或不放回随机抽取 |
| 限时开奖 | 正确口令先报名，截止后选中奖者并固定金额，再生成付款 |

通用要求：

- 总份数和总发放金额明确。
- 每份金额为正，符合 LDC 支持的金额精度，当前按两位小数处理。
- 完整金额池之和等于配置总额；限时人数不足且关闭发完奖池时，仅发出其中实际获奖份数，其余不发。
- 固定模式无法精确均分时，要求调整配置，不暗中产生不同金额。
- 即时活动的份额在活动开放前生成并固定；限时活动在开奖时生成并持久固定，不因恢复重新抽取。
- 成功分配后金额固定，不因付款排队、失败重试而重新抽取。

随机金额保存草稿时预生成，只有准备中修改总额、份数或算法时重新生成；修改其他配置、正式开放和请求重试不改变金额池。两种算法都采用不放回随机领取，不保证每份不同，也不宣称所有金额组合等概率。

二倍均值法根据剩余金额和剩余份数逐份生成，给其他份额保留至少 0.01 LDC，最后一份取得余款。波动均值法固定围绕初始均值上下 50%，上下界按 0.01 LDC 向外取整、每份最低 0.01 LDC，并确保总额守恒；只有一份时取得总额。具体整数公式见[技术方案](technical-design-phase-1.md#随机金额的版本化规则)。

### 5. 存量数据隔离

文本 / CDK 功能完全移除，旧活动不再进入列表、历史、统计、帖子定位、匹配或管理员展示；旧链接和本人领取详情按现有身份检查后返回未找到。不保留历史查看、领取、解密或后台恢复。旧数据库行、字段、索引和历史迁移原样保留，不转换、不清理、不补写业务状态。

统一库存继续承载 LDC 金额及开奖分配；标题、口令、Markdown 说明、奖励附言、结束说明和分享文字继续保留。旧全站多候选快照不改写候选集合，只显示有效 LDC；即使只剩一个也需明确选择。已绑定 LDC 按原目标和编号恢复，已绑定退役类型或全为退役候选不继续、不自动换目标。

### 6. 阶段信息

三个字段均为选填：

| 字段 | 展示规则 |
|---|---|
| 领取前说明 | 访问活动页面时可见，领取后继续保留 |
| 领取后说明 | 成功分配奖励后，仅对已领取用户可见 |
| 结束后说明 | 活动结束后，对能访问该页面的用户展示 |

领取后说明在**奖励分配成功时**解锁，不等待 LDC 确认发放或结算为可用余额。

作者可以在这些字段中放置论坛链接、后续活动链接或其他信息。平台不赋予其“提示”“题解”等专门语义。

共享说明显示作者维护的当前内容；已经分配的奖励金额保持固定。

### 7. 生命周期

| 状态 | 含义 |
|---|---|
| 准备中 | 尚未正式开放，包括配置未完成；后续平台代发还包括尚未满足资金要求 |
| 进行中 | 已正式开放、尚未到期且仍有未分配奖励 |
| 已结束 | 已到期、奖励已经领完，或在没有任何领取时由作者提前结束 |
| 已归档 | 实际结束满 72 小时后，退出日常发现和匹配范围 |

具体规则：

- 即时活动支持正整数分钟、小时、天，从**正式开放领取**开始计算；未指定数值的旧配置继续为24小时。后续平台代发等待入金的时间不占用期限。
- 作者可以设置具体截止时间，正式开放时该时间必须尚未到达。
- 领完或到期立即结束。
- 已有成功领取后，作者不能手动提前结束。
- 正式开放后截止时间锁定，不能延长、缩短或通过修改期限重新开放。
- 实际结束满 72 小时自动归档。
- 结束和归档不以全部付款完成为前提。
- 归档不删除记录、不停止付款，也不收回已分配奖励。
- 作者和领取者分别可在“我的已创建”“我的已领取”中查看全部历史。
- 已知 UUID 仍可访问归档后的原页面，继续遵守原有信息权限。

### 8. 开放后的修改权限

正式开放后：

**允许修改：**

- 活动标题。
- 阶段说明和非关键展示文案。
- 数量展示（精确／模糊）与领取名单总开关。
- 关联帖子（主题 ID 与回复序号）；结束及归档后也可修改。
- 领取前人机验证（开或关），只影响之后的领取和报名。

- 开启“加入广场”，不要求关联帖子或回复。

**不允许修改：**

- 新增、删除、修改或重排有效口令；历史口令集合原样保留。
- 截止时间及相对开放时长。
- 奖励池内容、份数、金额和分配方式。
- LDC 付款模式及活动绑定的商户ID。
- 强制专属页配置。
- 首次开放时间。
- 已经开启的广场收录状态。

历史已追加的口令继续有效，既有失败尝试不改写、不追溯补发；本次规则生效后，开放活动不再允许追加口令。

商户配置维护不改变活动绑定的商户ID或奖励。同一商户可以修正Client ID和对应密钥；已有付款只有在从未发送或全部发送都有可信未建单证据时，才允许追加身份更正。未知、在途或已有订单任务继续按已固定的身份核对，不能直接转到另一应用重付。

## 三、兑换入口、发现与统计

### 1. 统一兑换界面

首页和专属页使用同一套界面，通过当前是否指定活动区分行为：

| 当前范围 | 输入行为 |
|---|---|
| 全站 | 自动识别口令或活动标识；口令进入兑奖发现，活动标识直接跳转或查询关联活动 |
| 指定活动 | 只校验当前活动的口令 |

首页只保留一个输入框，不展示页面标题、输入框可见标题或 placeholder；框内帮助按钮说明输入方式，无障碍标签为“口令”。空输入不显示主按钮；非空输入完整匹配活动标识时，按钮显示“跳转活动”，其他非空输入显示“兑奖”。6–18 字规则提示仅在非空普通口令不符合规则时展示，正常口令和跳转模式不展示。

- UUID、有效 14 个 Emoji 表情码、本站完整活动链接：进入对应活动。
- `https://linux.do/t/topic/<主题ID>` 或 `https://linux.do/t/topic/<主题ID>/<楼层>`：查询关联活动，单个结果直达，多个结果展示列表。省略楼层按 1 楼；不接受 HTTP、短路径、标题路径或额外路径。
- 从广场点击活动：进入对应专属页。
- 全站口令匹配到多个活动时，在模态框中展示活动列表；选择后关闭弹窗、进入活动页，并自动提交兑奖或报名。
- 返回全站兑换时，清除当前指定的活动范围。
- 界面必须清楚显示当前是全站兑换，还是正在兑换某个具体活动。

### 2. 全站匹配规则

**先匹配候选而不执行领取：单个匹配直接进入活动页，多个匹配弹窗选择；到达活动页后自动执行一次兑奖或报名。**

候选活动必须同时满足：

1. 已经正式开放过。
2. 未强制专属页兑换。
3. 尚未归档。
4. 提交口令命中其有效口令。

每个活动在结果中只出现一次。多个匹配按首次正式开放时间从新到旧排列，相同时间保持稳定排序；“最新”只影响排列，不排除其他活动。

以下条件不用于跳过候选：

- 活动已经结束。
- 当前用户已经领取。
- 当前用户的奖励尚未确认发放或尚未结算为可用余额。
- 当前用户是 LDC 活动作者。
- 活动没有加入广场。
- 活动没有关联帖子。

按匹配数量处理：

| 匹配结果 | 首页行为 |
|---|---|
| 没有活动 | 提示未匹配到活动 |
| 一个活动 | 进入活动页后自动提交；已结束则展示状态，本人已领取则展示原记录 |
| 多个活动 | 模态展示全部匹配活动，由用户选择后关闭弹窗并进入活动页自动提交 |

多个匹配的交互与展示规则：

- 列表复用广场卡片样式和活动的信息展示规则，**不套用广场的收录条件**；未加入广场、没有关联帖的匹配活动也会出现。
- 已结束、本人已领取、奖励待付款的活动仍保留在列表中，并标明相应状态；多个匹配全部已结束时，仍展示列表供查看。
- 点击活动先关闭弹窗，再进入活动页自动提交；口令无需重新输入，等待、错误及原请求重试均在活动页显示。
- 匹配和导航本身不占用奖励、不锁定金额，也不解锁奖励附言；只有活动页的正式提交成功后才产生对应业务事实。
- 用户可以返回匹配列表继续选择其他活动。领取限制以活动为单位，同一用户可以分别领取多个同口令活动，每个活动仍最多领取一次。
- 领取时重新检查当前活动的状态和库存；如果已经结束，只展示当前活动的状态，不自动替用户领取其他活动。
- 列表展示后活动发生变化，进入专属页时显示最新状态；已经归档的页面仍可查看历史信息，但不能重新领取。
- 查询和浏览列表不计入领取数，也不产生尝试统计；普通活动从列表进入专属页后仍不提供尝试统计视图。

活动页消费单次自动兑奖意图或用户主动提交时，按以下规则处理：

| 情况 | 结果 |
|---|---|
| 进行中且本人未领，但本人是 LDC 活动作者 | 提示作者不能领取自己创建的 LDC 活动，不分配奖励 |
| 进行中且本人未领，并且不受上述自领限制 | 尝试分配一份奖励 |
| 本人已领 | 展示原领取记录 |
| 已结束但未归档 | 展示结束状态和允许查看的信息 |
| 已结束且本人已领 | 同时展示结束状态和本人领取记录 |
| 已归档 | 展示历史信息及本人原领取记录（如有），不能重新领取 |
| 分配时恰好领完或到期 | 返回该活动已结束，不改选其他活动 |
| 操作中出现更新活动 | 本次继续处理已经选定的活动 |

本次选中的活动不能领取时，**不自动改领其他活动**；用户可以主动返回匹配列表重新选择。

强制专属活动不允许通过“首页输入正确口令后自动定位或跳转”的方式绕过入口限制。

已归档活动从后续匹配结果中移除；其他符合条件的同口令活动始终可以出现在结果中，无需等待较新活动归档。

### 3. 专属页兑换

所有活动都有专属页。

- 始终只校验当前 UUID 对应的活动。
- 不因口令错误、领完、到期或本人已领取而转向其他活动。
- 正确口令只有在成功分配奖励后才形成领取记录。
- 作者不能领取自己创建的 LDC 活动；在分配奖励前拦截，不自动转向其他活动。
- 并发领取不能超发，同一用户不能重复取得奖励。
- 未成功分配时，不扣减可领取份数。
- 成功分配后立即扣减份数、保存奖励并解锁领取后说明。

### 4. 帖子索引

不设置统一的“公开／不公开”状态。

**作者填写关联帖子，就表示允许通过该帖子反向查到活动，不受广场开关影响。**

- 允许关联他人发布的帖子。
- 同一帖子可以关联多个作者的多个活动。
- 索引明确展示各活动的发放者；关联不代表楼主认可。
- 帖子按主题 ID 与回复序号共同标识；不同回复不混合。缺少回复序号按 1，规范链接始终包含回复号，丢失过的历史回复统一回填 1。
- 正常索引包含正式开放过、尚未归档的关联活动。
- 进行中和已结束活动均可出现。
- 准备中和已归档活动不出现在正常索引中。
- 过滤后一个结果直接进入专属页，多个结果展示列表，没有结果则说明暂无可查询活动。

关联帖子字段应告知作者：

> 填写后，用户可通过该帖子链接查询到本活动，无需加入广场。

### 5. 广场

广场是独立发现入口，由“加入广场”控制。

- 加入前须具备活动必要基础信息，帖子关联独立选填。
- 默认不加入。
- 开启后不能手动撤回。
- 可以展示进行中和已结束活动，并明确区分状态。
- 活动归档后自动退出广场。
- 自动归档不等于作者撤回广场收录。

广场条目采用最小展示原则，点击后进入专属页。卡片不维护独立的信息权限，沿用活动的展示设置。

### 6. 信息展示

用于识别活动和理解领取条件的基础信息包括：

- 活动标题、发放者和金额方式。
- 活动状态和截止时间。
- 已配置的关联帖子。
- LDC 活动的发放方式，以及是否可能排队付款。

这些基础信息不能被可选细节开关整体关闭。

作者可调整：

- 数量展示：精确、模糊，默认精确。旧隐藏和仅显示是否还有统一转换为精确。
- 领取名单总开关，默认开启。开启同时显示用户名、领取时间和 LDC 发放面额；没有子开关。旧关闭名单保持关闭，旧开启名单统一显示这三项。

精确展示包含总份数、已领取份数和剩余份数；模糊展示只返回状态等级，服务端不返回精确数量。

数量均按奖励是否已经分配计算，与 LDC 是否确认发放或结算为可用余额无关。

领取名单和活动状态本身可能透露部分进度。金额、时间、匿名与名单开关继续按照各自权限执行。

即时领取名单保留完整领取时间，原相对时间改为“正式开放至领取成功”的纯秒数（最多3位小数）。全活动最早的有效领取者获得“手速王”；其耗时不超过10秒（含）时改为“我焯有桂！”。按原始毫秒比较，精确并列均获得称号，可与手气称号并列。隐藏时间时同时隐藏手速及其称号。报名和自动开奖不评领取手速。

### 7. 尝试统计

只有强制专属页活动提供尝试统计视图，归档后作者仍可查看。

统计事件是：

> 登录用户主动提交一条符合格式要求的口令，并实际进入该活动的校验。

正确和错误口令均可记录。以下行为不计入：

- 只浏览页面或输入但未提交。
- 格式不合法。
- 在校验前被限流拦截。
- 同一次请求的重复点击或网络重发。
- 已领取后再次查询原记录。
- 活动已结束后的提交。
- LDC 付款或重试。

作者可查看：

| 指标 | 含义 |
|---|---|
| 总尝试次数 | 去除重复请求后的实际校验次数 |
| 独立尝试人数 | 提交过口令的不同账号数 |
| 提交内容聚合 | 用户提交的口令原文、次数和人数 |
| 命中情况 | 提交时是否命中有效口令 |
| 成功领取数 | 通过对应口令成功分配的奖励份数 |

补充规则：

- 同一用户主动提交同一错误口令三次，计三次尝试、一人。
- 校验命中但分配时已经领完，不计成功领取。
- 后续新增有效口令，不改写此前提交时的校验结果。
- LDC 待付款仍算成功领取，支付重试不增加统计。
- 统计仅作者可见，默认按提交内容聚合，不提供用户完整失败轨迹。
- 公开领取名单不连带公开尝试统计。
- 全站失败输入不分配给任何作者。
- 普通活动进入专属页，也不因此开启统计视图。
- 全站多匹配列表的查询和浏览不计入尝试统计或领取数；从该列表进入普通活动的专属页后，只有实际成功分配奖励才增加正常领取记录和领取数。

提交区域应说明：

> 提交的口令将供活动作者查看，用于兑换尝试统计。

## 四、LDC 资金、余额与付款

第 1 节商户直发和第 6 节付款队列已经上线。第 2–5 节是站内🐟额，细节和每条决定的出处见[站内🐟额设计文档](balance-design.md)：第一步只做转入、🐟额和管理面板，第二步做转出。

### 1. 商户直发

作者维护 LDC 商户应用配置，活动使用对应应用付款。配置管理者身份不等于已经验证的 LDC 商户所有者身份，平台不宣称具备可靠的商户归属验证能力。

- 平台负责按领取结果创建和处理付款任务。
- 活动资金来自所配置的 LDC 商户应用，不产生平台入金或平台余额。
- 不提供“平台已预存资金”的标识。
- 同一 `client_id` 永久属于平台内同一个商户配置，不能被其他商户占用；该商户可以切回自己历史使用的Client ID。调度占用按商户ID统一，旧、新Client ID不能形成并发付款入口。
- 每个账号至多一个当前商户；历史商户保留既有活动和付款维护能力，但不能用于新活动开放。新草稿绑定当前商户，旧草稿须明确重新绑定同模式当前商户，不改变已生成金额池。
- 新开放 LDC 活动要求当前商户的当前凭证版本最近十分钟检查通过；缺少有效结果时自动检查，草稿保留，最终开放事务再次核对版本。已开放活动重复开放返回原结果。
- 已开放活动在凭证未验证、检查中、认证失败或网络异常时继续允许领取并锁定奖励，付款等待可用凭证恢复。凭证变化不延长活动期限、不换奖、不清除未知结果。
- 网络异常、额度限制等问题优先自动查单、等待和恢复；凭证失效或外部资金不足由作者维护，无法安全自动恢复的冲突才进入异常处理。
- 修改名称、Client ID或密钥不改变商户ID、活动绑定、已领取奖励或付款业务号。付款模式不可改，商户不可删除。
- 改Client ID必须同时填写对应密钥；同ID下密钥留空保留原配置。新版本检查通过前不发送。修改凭证时存在进行中活动、未完成开奖或未完成付款，须确认分类影响范围；保存时新风险出现需重新确认。
- 已有订单或历史未知不能因更换配置清除。失效的历史付款身份只能修复该Client ID的密钥，不能改变业务号、收款人、金额或强制重发。

商户在同一外层配置页维护名称、Client ID 和密钥，没有有效修改禁用保存；创建须完整填写。付款记录和完整详情共用一个紧凑表格弹窗，保留系统返回、刷新恢复和焦点，旧深链接只作为兼容入口。完整详情按一次概况、订单、实际付款时间线和处理记录组织，不展示资格卡片、手动检查或内部版本数字；只有异常且允许时提供“更新原订单密钥”。

### 2. 站内🐟额

- 站内🐟额（简称🐟额）是存在本站的 LDC，单位 🐟，1 🐟 对应 1 LDC，没有汇率。界面上不用钱、充值、提现、币这些说法，也不写汉字“鱼”。
- 和商户直发完全分开：商户直发的 LDC 不经过本站，🐟额也不能用来付商户直发的红包。以后发红包二选一：LDC 红包（商户直发）或 🐟 红包（用🐟额发，领到的 🐟 记进领取人的🐟额），一个红包不混用。
- 只对白名单开放，直到管理员关掉白名单；名单外的人看不到入口。转入和转出各有开关，开关只管新操作。
- 平台应用是 Credit 里单独新建的集市应用，不是作者的商户；站长本人不能转入或转出（Credit 不允许给自己付款或分发）。

### 3. 转入

- 用户在 Credit 收银台确认，把 LDC 付给平台应用；Credit 扣除 1.00–2000.00 LDC，到账 = 扣除 − 流转费。流转费按管理员手填的流转费率（默认 12%，对应 Credit 的集市手续费率），和 Credit 一样四舍五入到分。两个框可以从任一边填，另一边自动算。
- 没有回调：只在有人来问时查单（详情页、🐟额页、重新查询、管理员），查到付款成功且信息一致才到账，每笔只到账一次。查不到就是“未完成”，不是终态，之后查到成功照样到账。
- 下单被拒时先查单再定状态；已到账的单以后查不到成功，只做标记提醒管理员去 Credit 核对，不自动扣回。管理员核对后可以手动确认到账。
- 防刷只有一条：每人每小时最多新建 30 笔转入。

### 4. 🐟额与锁定

- 每人的🐟额分可用和锁定。锁定按笔记录用途（转出，以后还有 🐟 红包），结束时解锁或扣走。
- 每一笔变动写一条只追加的明细，可用和锁定永远等于明细之和。只有管理员扣回能让可用变成负数，负数时不能转出。
- 退款由站长人工处理：在 Credit 退给用户后，在管理面板“调整”里扣回，原因必填、用户能看到。用户界面上没有退款文案，也没有争议期；站长定期检查 Credit 的争议列表。
- 管理面板的“代存合计”是所有人的正可用加锁定，平台 Credit 账户里至少要留这么多。

### 5. 转出（第二步）

- 用户把🐟额转回自己的 Credit 账户，自动由平台应用分发，不审核，额度用完就排到第二天，和红包付款一样；和站长自己的红包共用 Credit 账户的每日额度。
- 申请时锁定转出数量；发放完成扣走，Credit 明确拒绝、能确定没有订单时（比如收款人不存在）自动“未发出”、🐟 退回可用，结果不明时一直查单。

### 6. 付款队列

商户直发和第二步的🐟额转出都走这个付款队列。一期以商户ID统一调度租约，并保留每次实际使用的应用Client ID，不将其描述为已经验证的实际付款账号隔离。

基本流程：

> 奖励分配成功 → 生成付款任务 → 等待或执行 → 确认发放／自动查单与恢复／异常处理

业务要求：

- 同一领取记录只对应一笔应付奖励。
- 原Client ID、业务号、收款人稳定身份、金额、所属活动及原参数摘要保留。安全修正以不可变追加记录确定有效Client ID，其余付款参数不变；在途和未知结果继续使用原身份核对。
- 一期在对应商户应用下按任务先后处理；已明确可以安全等待或重试的失败任务不使整队永久停顿。
- 额度不足时保留任务，等到北京时间次日 0 点后 5–30 分钟再试（Credit 按 Asia/Shanghai 换日，随机错开各商户）；同一商户应用后面的付款排在它后面一起等，不再各自去撞额度。领取人和作者看到额度已用完、什么时候继续；总额超过 800 LDC（最低一档的每日限额）的红包，在表单里提示可能顺延到第二天。实际每日额度按 LDC 付款账号共享，可能受其他商户应用及平台外交易影响；一期无法可靠识别共享账号或准确读取剩余额度，以 LDC 实际响应为准。
- 网络超时、响应丢失、发送进程中断及发送占用过期不直接等同付款失败；先自动查询原业务号，再决定是否重试。
- 付款结果不明时，只暂停对应商户应用的新发送，继续自动查单；核对清楚后自动解除暂停，其他商户应用继续处理。
- 查单暂时不可用或未找到时持续退避核对，不立即转人工。“未找到”或非成功状态不能独立证明此前没有扣款；原号安全重试以线上唯一约束和事务契约验证通过为前提。
- 作者可修改同一商户配置、更新原订单密钥或在LDC补足资金，后台自动安排恢复；这些操作不能绕过未决付款保护，不提供手动检查入口。商户直发不使用站内🐟额。
- 普通付款不适用独立线上验收的五次或二十四小时上限；持续承担付款责任，长期等待只调整频率。每次恢复发送先查询原单，已有订单证据只可增加，不因后续失败重新取得发送资格。
- 停止新开放、新领取、新发送分别控制。停止新领取仍可读取原奖励和幂等回放，停止新发送仍查原单，在途请求结果继续保存。普通付款不自动进行成功后的重复请求验证。
- 无法自动解释的订单冲突或业务拒绝进入异常处理。人工介入用于不能安全自动恢复的情况，不能以盲目重发替代核对。
- 付款异常不能让奖励重新进入可领取库存。
- 活动结束、归档或退出列表都不取消付款责任。
- 任务投递或执行中断须可补偿；队列重复投递不重复付款，进入死信队列也不取消应付奖励。

领取者可查看自己的待发放、发送中、核对中、等待恢复、已确认发放或异常待处理状态。LDC 成功分发先进入收款方待结算余额，平台显示“已发放”，不将发放确认等同于余额已经可用。未核实容量和结算规则前，不承诺精确到账日期，一期也不依赖尚未确认存在的分发回调。

## 五、业务验收、默认值与后续边界

### 1. 核心验收场景

以下为业务验收基线，逐项实施和验证状态见实施记录；本地模拟不代表真实付款验收通过。编号 15–17 只属于后续平台资金阶段；其他场景按一期商户 LDC 直发范围执行。

1. 首页和专属页使用统一兑换界面，并能明确识别当前兑换范围。
2. 口令尝试统计配置在草稿阶段可修改，开放后不可修改；启用时全站输入正确口令也不能绕过。
3. 同一用户使用不同有效口令，不能在同一活动重复领取。
4. 两个同口令活动同时进行时，均出现在匹配列表中，用户可分别选择和领取；最新只影响排序，不排除其他活动。
5. 活动归档后从后续匹配结果中移除，其他符合条件的同口令活动保持可匹配，无需等待较新活动归档。
6. 最后一份奖励被多人同时领取时，只能成功分配一次。
7. 分配过程中到期或领完，不自动改领其他活动。
8. LDC 金额锁定后不因付款重试改变；LDC 库存条目不重复分配。
9. 领取后说明在分配完成时解锁，不等待付款。
10. 强制活动正确记录错误原文、提交次数、账号人数和领取数，网络重发不重复计数。
11. 普通活动没有尝试统计视图，全站失败输入不归属给作者；匹配列表查询、浏览和进入普通活动专属页不产生尝试统计，成功领取仍形成正常领取记录。
12. 未加入广场的关联活动仍能通过帖子索引找到；允许同帖有多个作者的活动。
13. 已结束活动继续展示，结束满 72 小时归档后退出正常索引、广场和全站匹配。
14. 归档后个人记录、已分配金额和待付款任务继续保留。
15. **站内🐟额：** 流转费率 12% 时，到账 100 🐟 要 Credit 扣除 113.64 LDC；每笔转入只到账一次，查不到付款不到账。
16. **站内🐟额：** 可用和锁定永远等于明细之和；只有管理员扣回能让可用变负，负数时不能转出。
17. **站内🐟额（第二步）：** 转出申请即锁定，锁定的 🐟 不能再用；确定没发出时自动退回，结果不明时不退回也不重发。
18. 开放后口令、截止与奖励池均锁定；历史已保存口令和截止保留，不追溯改写领取或尝试记录。
19. 分发费从领取者到账里扣，费率看发红包的人的 Credit 等级；界面不混淆发放金额与净到账金额。
20. 数量、名单、金额等展示设置在专属页、广场摘要、帖子索引摘要和全站匹配卡片中保持一致，不泄露受限金额、说明或私人付款信息。
21. 同口令活动一个进行中、一个已结束时，两者都出现在匹配列表中，结束活动不阻挡另一个；多个匹配全部已结束时，仍展示列表供查看。
22. 本人已领取和奖励待付款的活动继续展示，进入后可查看原记录，不重复分配。
23. 强制专属、准备中和已归档活动不参与全站匹配；未加入广场、没有关联帖的普通活动正常参与，每个匹配活动只出现一次。
24. 多匹配时点击卡片只进入详情并保留已输入口令，不占用奖励、不锁定金额、不解锁领取后信息，确认领取后才分配奖励。
25. 零匹配就近提示；单匹配导航后自动提交；多匹配弹窗选择后导航并自动提交，不自动选择最新活动。
26. 列表展示后活动恰好结束或归档，进入时显示最新状态或历史记录，不能重新领取；实际分配前重新检查状态和库存，不自动改领其他活动。
27. 作者自己的 LDC 活动仍参与正常全站匹配，但在分配前禁止自领，不扣库存、不生成付款任务、不自动改领其他活动。
28. 所有 LDC 份额金额在开放前固定，领取和付款恢复都不重新生成金额。
29. 超时、响应丢失、发送中断和队列重复后自动核对原业务号；只暂停对应商户应用的新发送，查单继续，核对清楚后自动恢复。
30. 同一付款保留原商户ID、业务号、收款人稳定身份和金额；Client ID修正只允许从未发送或全部发送可信未建单且无未知／订单证据的普通任务，不能绕过核对或重复付款。
31. LDC 确认分发成功后停止重发，展示“已发放”，不宣称收款方余额已经可用。

## LDC 四类奖励与限时开奖

LDC 奖励方式分为固定均分、即时随机、自定义金额、限时开奖。固定均分填写每份金额与奖励份数；即时随机填写总金额、奖励份数并选择算法；自定义金额填写金额列表及按顺序/随机；限时开奖填写总奖池、获奖名额、可空报名上限、最晚开奖时间（倒计时秒数或指定时间）、随机算法及人数不足时发完奖池开关。即时随机与限时开奖均支持二倍均值、初始均值上下50%。方案及算法切换保留临时输入，仅当前配置参与校验。

获奖名额N是最多获奖人数（1–1000）；报名上限M独立，默认留空，只按时间开奖，填写正整数则达到M即停止报名并提前开奖。M可以小于、等于或大于N。新活动倒计时默认600秒（10分钟），从正式开放成功起计算，是最晚截止时刻。实际获奖人数K=min(截止时有效报名人数,N)，人数超过名额时随机无放回选择中奖者。首次选择限时模式也不自动填写报名上限；修改获奖名额不暗中联动，历史保存的倒计时和上限原样保留。

人数不足时发完奖池默认开启：开启按K份生成并发完整个奖池；关闭按N份生成完整金额池，再随机取K份发放，其余不发放。零报名直接结束，无领取或付款。奖池为拟发面额，本站不预扣托管资金；没有未发金额退款流程。整数分、每份至少0.01、安全整数与无偏随机的原规则保留。即时随机仍在草稿保存时生成库存，限时开奖只在开奖时生成。

报名只取得一个资格，不是领取或到账。作者不能报名自身LDC活动，同账号同活动只有一条报名，多个口令不增加机会。报名成功即可查看本人的报名口令、复制及继续解出其他口令。截止后公开所有口令；个人报名/领奖/解出标记仅对本人展示。公开获奖名单只在结果完整发布后显示，仍服从名单开关与数量展示设置；作者可分页查看报名及结果。

页面区分等待开奖、报名截止且开奖处理中、已中奖及未中奖；付款状态沿用现有文案。我的参与合并即时领取与限时报名，每个活动不重复列报名和获奖。报名统计不计为成功领取，成功领取只计实际中奖记录。中奖后才解锁领取后说明。服务端截止判定不依赖浏览器计时器，实际结算及逐笔付款可能延后。

开放后金额配置、算法、人数、报名上限、开关、商户与开奖时间模式及期限冻结。有人报名后不能取消或改变开奖时间；无人报名可提前结束。已有报名不因停新报名或凭证失败撤销，仍须开奖并承担付款责任。关联帖子和原本可改的展示资料继续允许修改。

本批四类奖励与限时开奖已于2026-10-06完成本地回归、Stage浏览器验收及生产发布。生产允许新限时活动按正常作者和凭证规则开放；Stage仍关闭真实资金。本地完整应用证明报名、持久开奖和付款恢复闭环，线上本批仅执行配置、登录、迁移及既有数据核验，没有新增资金活动或把模拟结果当作线上开奖付款实测。

登录界面提供“官方 Connect”和“LiteAuth 青春版”，不因一个入口故障自动改用另一个。LiteAuth 仅接纳论坛账号来源及 `lite_self_app` 登录方式；`id`是Linux DO论坛ID，`sub`和`liteauth_user_id`不能作为合并依据。官方升级是本站官方登录成功的结果，不根据本次入口、信任等级、客户端字段或其他站点的登录经历推断。

账号页显示资格、当前会话来源、LDC使用能力及更新资料入口。青春版提供“升级当前账号”的官方登录入口，授权绑定当前本站账号；官方返回不同论坛ID时停止升级并保留原会话，不静默换号或合并。升级成功返回原页面，不自动兑换，也不把口令传入OAuth URL或持久存储。离开、退出及会话失效清除私有资料与口令。

青春版限制在口令校验和分配／报名之前执行，返回 `OFFICIAL_CONNECT_REQUIRED` 和中文原因，不产生库存占用、领取、报名、付款任务或Outbox。直接接口、内部ActivityDO、D1原子接纳及待分配补偿均使用同一资格规则。全站匹配不隐藏命中的LDC卡片：单项LDC显示限制，多项继续由用户明确选择活动，不能过滤旧候选后自动领取剩余活动。原提交UUID、候选快照与终态回放保留；升级不重算已经结束的提交，新主动操作使用新UUID。

## 2026-10-17 领取前人机验证（当前有效）

作者可在“更多设置”打开“领取前人机验证”，默认关闭。打开后，每次领取或报名在受理前都要在弹窗里通过一次 Cloudflare Turnstile：口令正确时、直接领取时、限时开奖报名时都会弹出。弹窗写明这是作者的要求，通过后自动继续领取或报名；关掉弹窗就不领取。

- **只在会受理时才要求**：口令错误、已经领过或报过名、红包已结束、冷却中，都照常回答，不弹验证。要求验证的那次请求不计尝试、不计冷却、不写任何记录；拿到令牌后用同一个提交编号重发。原编号重试照常回放结果，令牌用过也一样。
- **服务端核验**：API 向 Cloudflare 核验令牌。令牌只能用一次，5 分钟内有效，还要与本站域名、动作（领取或报名）和这个红包对得上。核验不通过就再要求一次验证；Cloudflare 核验超时、出错或本站密钥有误时放行并记录，因为这类故障不是请求方能造出来的。服务端查到唯一红包就直接领取的接口同样受限。
- **环境**：没有配置 Turnstile 密钥的环境不能打开这一项；已经打开的红包遇到密钥缺失时不再要求，并记录错误。
- **代价**（表单里写明）：中国大陆网络、广告拦截插件或部分隐私浏览器可能加载不出验证，这些人领不了。它挡得住直接调接口的脚本，挡不住真人用多个账号，也挡不住付费打码。
