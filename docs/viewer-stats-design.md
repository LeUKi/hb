# 在看人数：最高、来看过的人和曲线（2026-11-19 评估）

用户 2026-11-19：在看人数除了实时人数，再加上历史人数曲线（或者只要历史最高），还有总人数；红包结束后展示总人数和最高在线人数。

状态：用户选了 B（数字加曲线，2026-11-19）；做好了，还没发布。界面写进 [05](redesign/05-hongbao.md) 第 3 节“在看人数”。

## 1 现在

- 红包页左上角“N 人在看”（[05](redesign/05-hongbao.md) 第 3 节，`live-viewers.tsx`）：此刻开着这一页、连着推送的登录用户，同一人几个标签页只算一个；游客不连推送，不计入，也看不到。
- 这个数只在红包自己的对象（ActivityDO）里现数现推：有人连上、断开时数一遍连接，0.3 秒内合成一次推给大家（`announceViewers`）。没有记下来，红包结束、连接断开就没了。
- 社区小程序的连接也在同一条推送上，一起算，小程序也显示这个数。

## 2 要加的

| 数 | 意思 |
|---|---|
| 最多同时在看 | 同时在看人数的最高值，和出现的时刻 |
| 来看过的人 | 开过这一页、连上过推送的不同登录用户 |
| 曲线 | 从第一个人来看到结束，每分钟一个点 |

## 3 做法

- **记在红包的对象里**：只有它知道谁连着。都在已经会发生的“有人连上 / 断开”里顺手记，不加定时器、不加闹钟，所以对象不会多醒、也不会醒得更久。
  - 来看过的人：对象自带的 SQLite 里一张表，每人一行，已有就跳过；总数就是行数。
  - 最多同时在看：人数和时刻两个值，破纪录才写。
  - 曲线：每分钟一行，记这一分钟最多几人、分钟末几人。没人进出的分钟沿用上一分钟分钟末的人数，不写。
- **推送**：现有的人数推送（`viewers`）多带“最多”和“来看过”两个数，不多发消息。小程序不认这两个字段，照旧只显示人数；要它也显示，就等下一次小程序审核。
- **结束后看的那份写进 D1**：新表，一个红包一行，存最高值、时刻、来看过的人数和曲线（压到最多 240 个点）。两个时候写：最后一个人离开时，和红包结束时。没人看的时候数不会变，所以 D1 里那份总是最新的。结束后，公开数据带上这一行，游客也看得到。
- **看曲线**（`GET /api/activities/:id/viewers`）：进行中（含待开放、等开奖）由登录用户点开时向红包对象要一次，不随推送常带；结束后，以及游客，读 D1 里那份，不唤醒对象。
- **结束那一刻**：对象看到结束时先把数记完、写进 D1，推给大家的结束数据里直接带上这两个数，不用等下一次读取。结束以后再连上的（等付款的人）不再计入。
- 要加一个迁移（0072），发布时照例先跑迁移。

## 4 开销

按 2026-11-17 用量调查里 11-13 到 11-16 的量估算：每天约 65 个红包有人看，红包对象每天 5–7 千次请求。

| 项 | 增加多少 | 每月额度 |
|---|---|---|
| 红包对象请求 | 只有进行中点开曲线时多一次；有人连上、断开不加请求 | 100 万（本月本来就会超一点，多出的每百万次 $0.15） |
| 红包对象时长 | 约等于 0：不加定时器，只在已经醒着的时候写 | 40 万 GB-s |
| 对象 SQLite 写入 | 每次连上或断开最多 2 行，每月几十万行 | 5000 万行 |
| 对象存储 | 每个红包几 KB 到几十 KB，留在对象里 | 5 GB |
| D1 写入 | 每个红包几次，每天几百行 | 5000 万行 |
| D1 存储 | 每个红包 1–2 KB，每月几 MB（现在正式库每天本来就涨约 5 MB） | 5 GB |
| D1 读取 | 打开结束后的红包多读 1 行 | 250 亿行 |
| 推送 | 每条人数推送多 20 来个字节；推出去的消息不计费 | — |

算下来每月不到 1 美分，主要成本是开发工作量。

不能这样做：每分钟用定时器把曲线写进 D1。定时器在的时候对象一直醒着，每次多醒约一分钟，按现在的量一个月要多出二三十万 GB-s。

## 5 口径和局限

- 和“N 人在看”同一口径：只数登录、连着推送的人，游客不计入。结束后给所有人看时也是这个数。
- 发布前已经开始的红包，从发布那一刻起记，之前的补不回来。
- 手机切到后台要等心跳超时才断开，所以最高值和曲线末尾会多算一两分钟。
- 发布或重启时所有连接会断开再重连。曲线每分钟取最多，看不出这个缺口。
- 一个红包超过 5000 个连接后，多出来的人改成轮询，不计入（现在也是这样）。
- 待开放的红包也连推送，曲线从待开放就开始记，开放那一刻在曲线上标出来。

## 6 界面

用户选了 B：胶囊改成可点，点开一张卡片，上面是数字，下面是曲线（细节见 [05](redesign/05-hongbao.md) 第 3 节）。评估时说结束后在“结果区加一行”，做的时候改成仍放在左上角的同一个位置：同一个胶囊、同一张卡片，不在页面里另占一行。

- 曲线只有一条，不要图例。用图表的第一种颜色（`--chart-1`，深色模式另有一档）：2px 的线，下面铺 10% 的淡色；底下一条细线当基线；最高点画一个 8px 的点。
- 指着曲线，或者手指按住左右滑，就读出那一刻：一分钟一个点时写“19:42 · 28 人”，几分钟一个点时写“19:42 起 3 分钟 · 最多 28 人”，最后一段写“现在 12 人在看”。曲线也能用键盘选中，左右方向键逐点查看。
- 定时开放的红包，开放之前一分钟以上就有人在看时，开放那一刻画一条细竖线，写“开放”。
- 红包实况图要不要在结束后也写这两个数，另外再定。
