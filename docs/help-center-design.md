# 帮助中心

状态：定稿（2026-11-20 用户：“按推荐做完”）。问题的具体写法以页面为准，编号以这里为准。

现在的帮助是一页 `/help`（输入框、命令、九个常见问题），加六份各写各的说明：`/help/start`、`/help/code`、`/help/page`、`/help/points`、`/help/token`、`/help/api`。它们没有目录，不能跳到某个问题，🐟额、PLUS、发放状态、领取范围、打赏、私信通知这些常被问到的事也没有写。这一篇把它们并成一个帮助中心。

## 1 先按要做的事分

进来先选“你要做什么”，再看这件事的问题。分法按“要做的事”，不按身份：同一个人今天领红包、明天发红包，要找的是不同的问题。

| 入口 | 给谁 | 地址 |
|---|---|---|
| 领红包 | 所有人 | `/help/claim`（新） |
| 发红包 | 红包作者 | `/help/send`（新） |
| 收打赏 | 做打赏卡的人 | `/help/tips`（新） |
| 🐟额和 PLUS | 有🐟额的人、受邀开通 PLUS 的人 | `/help/fish`（新） |
| 做玩法 | 写判定器、做附带网页、接自己服务的人 | `/help/start`（原“做一个玩法”扩成入口） |
| 发行三方积分 | 想让自己网站的积分能发红包的站长 | `/help/points`（原接入说明，加常见问题） |

前四个是“用红包站”，后两个是“开发和接入”，首页分成这两组。

**判定器开发者和附带网页开发者合成一个入口“做玩法”**，理由：

- 是同一批人。带网页的玩法一定有判定器（钱只经判定给出），附带网页只是这个玩法的界面。只嵌自己网站、没有判定器的红包很少；这种情况也是先读同一张“选做法”表。
- 先要决定的是“用哪种做法”（只写判定器、加网页、再加自己的服务），这张表现在就在 `/help/start`。分成两个入口，就得先替用户做这个决定。
- 开发包、给 AI 的说明、本地测试都是同一套：`npm run page` 同时跑判定器和网页。

所以按文档分，不按人分：入口页“做玩法”里先是选做法和给 AI 的说明，再是常见问题，最后是两份完整文档（判定器开发文档 `/help/code`、附带网页接入说明 `/help/page`）。

个人令牌（`/help/token`）和🐟额开放接口（`/help/api`）不单独成入口：用的人少，且各有归属。个人令牌放在“领红包”里（用脚本领），开放接口放在“🐟额和 PLUS”里（PLUS 的功能）。

## 2 页面

### 2.1 首页 `/help`

从上到下：

1. 标题“帮助”，说明一行照旧（⌘K 打开输入框；手机上是点地址条）。
2. **你要做什么**：六张卡片，分两组（“用红包站”四张、“开发和接入”两张）。每张是图标方块、名字和一句话（例如“领红包：口令、领不到、什么时候到账”），点进入口页。宽窗口一行两张，手机一行一张。卡片和首页常用命令同一种卡片、同一种图标方块。
3. **大家常问**：八个问题，一行一个，后面带 ›。点了直接去那个入口页，并滚到这个问题（第 3 节）。
4. 原来首页上的“输入框能识别什么”和“命令”两组，挪到“领红包”的第一章（`q-inputs`、`q-commands`）；首页不再放。

### 2.2 入口页（问题页）

同一个版式，内容是一章一章的问题：

- 标题行：“‹ 帮助”返回，标题是入口名，一句说明。
- 正文最宽 44rem，和别的页面一样。每章一个小标题（`PageSection`），章里每个问题是一个块：问题一行（加粗），下面是回答。回答都展开，不做折叠：能整页搜索，也能一眼扫完。
- 回答写成完整的句子，用站上的叫法；要去别的页面就给链接（“去 LDC 商户配置 ›”）；用到的数字从代码里取（像现在 `PAYMENT_RESEND_MINUTES` 那样），不在文案里写死。
- 开发文档（`/help/code`、`/help/page`、`/help/points`、`/help/token`、`/help/api`）换成同一个版式，内容不动，补上没有的章节编号。

### 2.3 右边的目录

- 宽窗口（窗口内宽 ≥ 60rem）：正文右边一栏目录，宽 13rem，随页面滚动停在顶上。列出所有章；当前这一章展开它的问题。
- 当前位置：左边一条 2px 朱红竖线，文字变成朱红。滚动时竖线滑到下一项（和分段选择的滑块同一种动画），不跳。
- 点一项：平滑滚到那里（系统要求减少动态时直接跳），地址里的 `#` 跟着换（替换，不多占历史记录）。
- 窄窗口和手机：没有右栏。右下角浮一个小的“目录”按钮（玻璃，和窗口的浮动按钮一样），点开是叠在上面的弹层，列同样的目录；选一项后弹层收起并滚过去。读到第一章之前不显示这个按钮。

### 2.4 跳到某个问题

- 每个问题有固定的编号（`#q-not-in-scope` 这样的英文短词），写好以后不改，站内外的链接都靠它。
- 打开带编号的地址：等内容排好后滚到这个问题（`useHashTarget` 的做法），问题块的底色先是淡金色，1.5 秒内退掉，让人知道是这一条。
- 每个问题标题行末尾有一个小的“复制链接”按钮（32px 幽灵图标按钮，`CopyButton`），复制的是完整地址。站长在社区回答问题时可以直接贴这条链接。

## 5 站内的入口

- 入口是帮助首页本身：命令 `/help`、各页面原有的“接口说明”“怎么做 ↗”等链接照旧，指向的地址不变。
- 界面上让人卡住的地方（领取范围的提示、余额不足的提示条、我的结果的发放状态、邀请页）都已经在原处把原因和下一步写清楚了，不再加“去帮助看看”的链接（2026-11-20 做的时候看过，加了只是多一行）。以后某处只写了一半、要读一段才明白的，再链到对应的问题。
- 输入框里搜问题（输入 `/help` 加关键词）先不做。

## 6 图标方块

首页常用命令的图标方块原来各用一种颜色（淡红、淡金、琥珀、黑漆、深金、灰），彼此不搭；深色下黑漆的那块几乎看不见，“施工中”的深金又太亮。现在都是一种：淡金底、深金图标，深色下是 14% 的金色底、浅金图标（用户从四种里选的）。帮助首页的六张卡片用同一种方块（`components/ui/icon-tile.tsx`）。

## 7 代码

- 问题按入口写成数据（`apps/web/src/components/help/*-help.tsx`、`start-faq.tsx`、`points-faq.tsx`）：编号、问题、回答、所在的章。回答是 React 节点，能放链接；数字取自代码里的常量（`@hb/contracts`、开发包的限制），每个问题上方写着出处。
- 版式 `HelpFrame`（`components/help/help-doc.tsx`）：右边的目录从页面自己的小标题读出来（带编号的 `h2` 和其中的问题块），所以问题页和五份开发文档共用；还有手机上的“目录”按钮和弹层、滚到问题和高亮。
- 原来 `/help` 上的输入框说明、命令列表和常见问题拆进了各入口页；“做一个玩法”原来的“三样东西各做什么”并进了 `q-three-parts`；五份开发文档每节都有了编号。旧地址都不变。
- 开发文档里的代码例子有高亮（2026-11-20 用户问“为什么展示代码时没有代码高亮”）：JavaScript、JSON、Python 按判定器编辑器的配色上色，浅色面板上用深一些的同色系，深色下就是编辑器的原色；提示词、curl、返回头这些照旧是纯文字。用的是判定器编辑器同一套解析器，不开编辑器，按需加载（`lib/code-highlight.ts`，`Block` 在 `views/help-api-view.tsx`）；标签以 `.js`/`.json` 结尾或写着 JavaScript、Python 的自动上色，别的用 `lang` 指明。
