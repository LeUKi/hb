# 震动反馈（2026-10-22 定）

像 iOS 那样，在操作上轻轻震一下，让反馈更及时，并且全站一个手感。用户定位为彩蛋：

- 不改任何原有的东西：界面、样式、流程、文案都不动，只在已有的操作里加一下震动；也不加开关。
- 单独一个提交，方便整体回滚。
- 先上 Stage 试。

## 1 哪些设备会震

- **安卓**：Chrome、Edge 等支持网页震动（Vibration API），会震。
- **iPhone**：iOS 上的浏览器都用 Safari 的内核，不支持网页震动；以前借隐藏的系统开关来震的办法，苹果在 iOS 26.5 堵上了。这里不用这种办法，iPhone 上暂时不震。以后 Safari 支持了，会自动生效。
- **电脑**：没有震动马达，不会震。

## 2 五种震法

全站只用这五种，各处只说“这是哪一种”，不各自定义：

| 种类 | 安卓上的节奏（毫秒） |
|---|---|
| 选择 | 震 10 |
| 轻触 | 震 15 |
| 成功 | 震 14，停 60，震 22 |
| 提醒 | 震 24，停 80，震 24 |
| 出错 | 震 18，停 45，震 18，停 45，震 28 |

## 3 四层用法（2026-10-22 用户要求扩大范围，形成全站风格）

一次操作从“按下去”到“出结果”，按层来震；后一层的会取代还没震完的前一层。

### 按：轻触

全站统一在一处判断，以后加的按钮也自动有：

- 红色的主按钮、删除这类危险按钮，按下就轻触一下（下一步、完成、存草稿、开放、发红包、知道了……）。
- 会打开菜单或弹层的按钮（分享、名单、说明、各处“？”等）；已经打开时再点不震。
- 头像（打开用户卡片）、登录、红包上的印章。
- 复制成功。

### 选：选择

- 开关、分段和筛选、选择卡片、等级卡片：值真的变了才震，点已经选中的那一项不震。
- 展开或收起一部分（带展开状态的按钮）。
- 加一个或去掉一个：指定的人、口令。

### 进：选择（一步一下）

- 开奖时，报了名、停在红包页等着的人：名单冻结、取随机数、取到随机数，每走一步一下；出随机数前的最后 3 秒，每秒一下。

### 果：成功、提醒、出错

- 全站统一在一处判断：自己发起的每一次修改（存、开、转、改、删、邀请、密钥……）有了回答，成功就“成功”，失败就“出错”。领取、口令、红包的保存另有自己的节奏，不在这里重复。
- 红包打开（领到、报名成功，和打开动画同时）、开奖时自己中了：成功。
- 不在领取范围里的说明弹出、开奖时自己没中、尝试太频繁、结果没确认：提醒。
- 口令不对、首页口令没匹配到红包、下一步或存草稿时还有要改的地方：出错。
- 红包表单的提示按颜色：绿的成功、黄的提醒、红的出错。

## 4 规则

- 只回应用户自己的操作和它的结果（开奖进度和结果是自己报名的结果）。打开页面、滚动、鼠标悬停、别人领取推送来的变化都不震。
- 用户还没碰过页面时不震（浏览器本来也不让）；页面不在前台时不震。
- “选择”连着很快地点（45 毫秒内）只震一次；新的一下会取代还没震完的。
