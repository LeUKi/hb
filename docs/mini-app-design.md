# 论坛小程序（2026-11-02）

LINUX DO 上的 Discourse 小程序：打包成 ZIP 上传，在论坛的沙箱框里运行。开发包（文档、SDK、示例）在 `~/Downloads/discourse-mini-app-guidelines`，没放进本仓库。目标是在论坛里直接打开、领取红包，不跳出去、不另外登录；先做一个验证包，确认红包站的样子和动画在论坛的沙箱里照样能跑。

## 1 这套小程序能做什么

- 运行：ZIP 里五个基础文件（`manifest.json`、`index.html` 正文片段、一个 IIFE 的 `app.js`、一个 `app.css`、`strings.json`）；不能加载外部脚本、字体、图片，没有打开外部网页的接口。论坛里的地址是 `https://linux.do/apps/<应用 ID>`。
- SDK：平台在 `app.js` 之前装好 `globalThis.miniApp`。当前用户（`id`、`username`、`name`、`initials`）、主题（深浅、颜色、语言、减少动画、尺寸）、启动参数、本地存储、剪贴板、全屏；网络只能调 manifest 里声明、审核过的接口，论坛给每次调用签一张 JWT（15 分钟，绑定这个接口）。HTTP 5 秒、请求 4 KiB、返回 64 KiB；WebSocket 每条连接最多 5 分钟、每条消息 4 KiB。游客没有网络。
- 沙箱构建不用审核：在应用页上传 ZIP，平台检查格式后发“沙箱就绪”私信，在 `/apps-sandbox/<应用 ID>/<版本>-<8 位构建标识>` 运行，只有作者和管理员打得开，保留 7 天。正式发布才提审。

## 2 红包站在里面能做到的

| 功能 | | 说明 |
| --- | --- | --- |
| 看红包，领直接领取、口令、代码判定（输入框）的红包 | 能 | 联网判定可能超过 5 秒：领取接口先回“已排队”，再查结果 |
| 开了人机验证的红包 | 不能 | 加载不了验证，不能绕过：说明到红包站领 |
| 附带网页 | 不能 | 嵌不进外部网页 |
| 发 LDC 红包 | 不能 | 要跳 Credit 付款 |
| 发 🐟额红包 | 以后 | 从余额扣，不用跳转 |
| 转账、转出这类资金操作 | 不放 | |
| 头像 | 首字母 | 远程图片加载不了；头像组件本来就有这个样子 |

## 3 身份

- 论坛账号 ID 就是 LINUX DO Connect 的 ID：论坛的能力测试台给 `lafish` 的 `id` 是 332940，红包站库里也是。
- 服务端只信 JWT：`sub` 是论坛账号 ID，没有用户名和信任等级。SDK 给小程序的用户资料能被玩家改，只能显示用。
- 在红包站登录过的人用库里的用户名和信任等级；没登录过的，用户名取小程序发来的（只用来显示和付款，身份以 `sub` 为准），限信任等级的红包请他到红包站登录一次。付款时 Credit 会不会核对用户名，还要确认。

## 4 样子：同一套代码

小程序在 `apps/mini`，直接用红包站的样式表（`apps/web/src/styles.css`：设计变量、基础、组件）和组件（印章、计数、礼花、按钮、输入框、分段选择、头像……），不另画一套。红包站只用系统字体、图标是打包进去的 SVG，和小程序的限制不冲突；React、motion、Tailwind 打成一个 IIFE 和一个 CSS。

- 封面头、封面数据、我的结果这几块直接读了红包站的窗口外壳、附带网页按钮、实时状态和路由，验证包里先照它们的样式类和结构拼了一个简化版；做正式版时拆成“只管显示、数据从参数进来”的组件，两边共用。
- **深色**：红包站只有浅色，论坛要求深浅都能用。深色时页面就用论坛主题给的底色（`theme.background`，默认深色主题是 `#222222`），文字、填充、线是中性的白色加透明度，换哪个深色主题都不会显出一块补丁；整页只有红包是红的。`apps/mini/src/mini.css` 在 `:root[data-mode="dark"]` 下换掉这些和强调色、成功、错误色，写死白色的玻璃（次要按钮、输入框、分段选择的滑块、说明卡）另外覆盖。红包本身的红、金和代码判定的黑漆不变。第一版用的是偏红的深酒红底，放在论坛的中性灰里像一块发闷的补丁，用户觉得难看，就改了。这套深色以后红包站也能用。
- 不跟论坛的强调色：红包的红和金保持一贯；深浅和减少动画跟论坛走（`theme.get()`、`theme.onChange()`），减少动画时不放扫光、金圈、礼花，金额不滚动。
- 论坛的框就是窗口：页面自己滚动，封面上面没有顶栏（`--bar-h: 0`），封面在最上面。

## 5 验证包

一屏红包，数据是包里的四个示例（不联网，红包站一行不改），底下能切换：直接领取、口令、代码判定（黑漆封面，回纹是 `data:` 图片）、要人机验证（说明到红包站领）。开红包时“正在领取…”、印章弹开、扫光、金圈、礼花、金额滚动，和红包站一样。只申请 `theme.read` 和 `launch.read`。

在沙箱里要看的：样式和动画是否都在（运行时改样式、`data:` 图片会不会被沙箱拦）、深浅切换、减少动画、手机和宽屏、`lifecycle.ready()` 后不再显示加载中。

本地（2026-11-02）：`bun run --cwd apps/mini dev`（`http://127.0.0.1:5194`，`src/dev.tsx` 装一个替身 SDK，右下角切深浅和减少动画；`?mode=dark`、`?reduce` 也行），手机宽度和 900 宽、浅色和深色、四个示例、减少动画都看过；产物里没有 `eval`、`new Function`、动态 `import()` 和外部地址。

第一次上传（构建 `d609566d`）一直停在“加载失败”，Console 里没有小程序自己的报错。论坛的框没有来源（`null`），带 `trusted-types 'none'`，多半在 ready 之前把框藏起来；原来 `lifecycle.ready()` 等到下一帧才调，`display: none` 的框没有帧，所以一直等不到。现在首次渲染（`flushSync`）后马上调；出错时把原因显示出来，也调。本地模拟了一样的框（无来源的沙箱框、同样的 Trusted Types、脚本内联）：旧包在框被藏起来时 8 秒都没有 ready，新包三种情况都在 150 ms 左右 ready，开红包的动画照常。

第二次上传（`03f9ef97`）在论坛的沙箱里打得开（2026-11-02，在 Chrome 里验收）：封面、印章、扫光、礼花、金额滚动、代码判定的回纹（`data:` 图片）、深色、400 宽的手机宽度都正常。只有口令提交不了：论坛的框不许提交表单，回车和提交按钮都不会触发 submit 事件。所以小程序里不用 `<form>`，回车（输入法正在组字时除外）和按钮直接调用处理函数。改完后上传的 `54b8bf8a` 在沙箱里验过：口令用回车和按钮都能领，输错有提示，领取中显示“正在领取…”；深色和论坛的底色连成一片；Console 里没有小程序自己的报错。

## 6 打包和上传

1. 在论坛个人资料的应用页建一个应用，复制应用 ID。
2. `bun run --cwd apps/mini pack`：构建，再用论坛 SDK 的 `pack` 打出 `apps/mini/dist/package/app.zip`。SDK 不在本仓库：`MINI_APP_SDK` 指向它的 `sdk/` 目录，默认是下载的开发包。应用 ID 和版本取 `manifest.json`（ID 是 `01a19ba5-b9d2-766f-9fb9-b7eddc10e0c7`，2026-11-02 建的应用），`MINI_APP_ID`、`MINI_APP_VERSION` 能改；同一个版本可以反复上传新构建。要在沙箱的 DevTools 里看源码，加 `MINI_APP_DEBUG=1`。
3. 在应用页的沙箱页签上传这个 ZIP，等“沙箱就绪”私信，打开沙箱地址检查。

## 7 下一步

验证包在沙箱里没问题以后：红包站加认论坛 JWT 的入口和小程序专用的接口（读红包、领取或提交、查结果、我的记录），沙箱的请求只放行到 Stage；封面拆成共用组件；从启动参数读红包编号打开真的红包。
