# 10 页面规范核对（2026-11-11）

用户看了三方积分后台（“全部摊开”）以后问：还有没有类似没照规范做的地方。照 [07](07-pages.md) 第 1 节“共用规则”、第 10 节“网站管理”和 [04](04-visual.md) 把各页过了一遍（三方积分后台和发放记录页刚按“列表 + 详情”重做，不在内）。下面是核对过的结果，按要紧程度排。

## A 会出错或用不了的

1. **三方积分：重新发送后还是找不到账户，结果卡只写“未发出”，不说为什么。** 这笔以 `failed` + `recipient` 结束（`api/points/payments.ts`），`pointsFailureWords`（`lib/points.ts`）没有这一种。应该和 LDC 一样显示“这笔没能发出”的说明。
2. **判定器广场“站长精选”永远只有前 20 个。** 自动加载只接在“全部”上（`judges-view.tsx`）。两个页签都要接上，末尾写“共 N 个”。
3. **三方积分下架、删掉密钥是自己拼的弹窗。** 下架失败的提示写在弹窗后面的面板上，看不到（`points-edit-view.tsx`、`points-detail-view.tsx`）。换成 `ConfirmDialog`，错误写在弹窗里，按钮变“再试一次”。
4. **三方积分的详情页、设置页打开不存在或别人的积分，显示“读取失败 / 重试”。** 应该是提示页（未找到 / 没有权限），像打赏卡页那样。
5. **三方积分设置页保存后整页重新挂载**：焦点丢到页面最上面，也没有“已保存”。应该原地保留，按钮旁写“已保存”（网站设置、商户配置的做法）。

## B 版式没照规矩来的

- **打赏记录**（`tips-view.tsx`）：收到的 / 我打赏的、时间范围、打赏卡、付法都存在页面里，后退和刷新就丢；底下是“再读 20 条”按钮，没有“共 N 条”；读取时只有一行字，没有骨架和失败状态；两个筛选是原生下拉框（全站只有这一处）。应该和🐟额明细一样：写进地址、自己加载、`ResultLoad` + `EmptyNote`、小号分段选择。
- **我添加的积分**（`points-view.tsx`）：每种一张卡片带三个按钮（设置、查看详情、发放记录），按钮不是真链接；没有积分时是一行字。应该一行一项、整行可点（像“我的判定器”），其他入口用 `MoreLink`；空状态用 `EmptyNote` 带“添加积分”。
- **施工（站长）**（`admin-roadmap.tsx`）：一行点开在原地展开详情和五六个操作按钮。规范是“列表 + 详情”，操作放在详情里。**和施工设计 §4 写的冲突，要你定。**
- **施工页**（`roadmap-view.tsx`）：“已完成 N 件 ›”“不做的 N 件 ›”在页面里原地展开整串列表，开没开也不进地址。规范的做法是点开一个弹窗看列表（像🐟额的“已停用的密钥”）。**和施工设计 §2.2、§2.3 冲突，要你定。**
- **判定器的版本**（`judge-view.tsx`、`judge-public-view.tsx`）：一个版本点开，原地展开指纹和最高 22 行的代码框。偏“摊开”，可以改成每个版本一个弹窗。判定器广场设计 §8 写的是“点开看代码”，两种都说得通。
- **邀请页**（`invite-view.tsx`）：没有用页面标题行，自己画了标题，窄面板；重试后焦点落不到标题上。
- **打赏卡编辑**（`tip-edit-view.tsx`）：表单用了宽页面（规范是表单也 44rem），预览放下面即可；没有离开确认。

## C 细节

- **少了返回行**：帮助的四个子页（`/help/code`、`/help/page`、`/help/start`、`/help/api`）和 `/help/points`；付款详情的“付款记录”写成了小标题而不是返回；三方积分详情页是自己的积分时也该有“‹ 三方积分”。
- **有含义的选择用了分段选择**（规范是选项卡片）：判定器的“代码公开”（选了不能改回）、🐟额后台的“补加 / 扣回”、施工的“放进”；🐟额邀请的“有效期”算边缘。
- **三方积分页面的忙碌和出错写法**：提交审核、暂停、恢复、填密钥的“保存”按下后不写“正在…”；错误写成“没有保存，请稍后再试”这类，规范是“X没有完成：原因”、读取写“X失败”。
- **用词**：三方积分的设置页、发红包时的余额那行、结果卡和 `/help/points` 里写“发红包的人”“领取的人”，规范是“红包作者”“领取者”。
- **晚到的字**：三方积分结果卡里发行方写的说明（没开户、到账后、不允许）是另读一次才出来，卡片先显示、再冒出一段或换一句；发红包时三方积分还在读的那一瞬，草稿会写“选的积分现在不能用了”、金额单位先是 LDC。
- **每敲一个字查一次**：施工发帖时的“相似的”、几处填用户名的预览（🐟额转账、邀请、站长调整），规范是停顿 0.3 秒再查。
- **列表末尾**：施工、判定记录在知道总数时写“已全部加载”，规范写“共 N 件 / 次”；几处筛选后为空没有“换个筛选看看”。
- **圆角**：三方积分设置页、更换按钮、施工、判定记录、排行榜、开奖数据有几处是普通圆角，不是超椭圆。
- **感叹号**：打赏成功“已打赏，谢谢！”。

## 照规范的

🐟额各页、排行榜、商户页、网站管理的红包 / 用户 / 付款 / 操作记录基本照规矩来；三方积分的页面宽度、页面加载、重新发送的确认、测试按钮的忙碌态是对的。

## 怎么改

先修 A（都是小改动，一批）；B、C 按功能分批，每批照最近的同类页面改，改完更新本页。施工的两处和设计文档冲突，先问用户。
