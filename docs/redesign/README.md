# 外观重构

本目录存放整体重构的方案与设计文档。所有内容在定稿前都是提案；定稿前，[DESIGN.md](../../DESIGN.md) 仍是生产环境的有效规范。

## 目标

- 以 Tailwind v4 为主写样式，页面布局与风格全部重做；可复用组件保留逻辑、重做样式；路由一并重新设计。
- 简洁但不简陋，实用导向，不写口号；字号与控件适量放大；仅浅色主题；仅系统字体。
- 应用程序形态，不再是“顶栏 / 底栏 + 文档流”的网站：借浏览器的风格（不照搬布局），网页是动态背景，网站是居中的窗口（各层叫法见 [02](02-shell.md) 第 1 节）。
- SPA，一次性加载全部功能，首次加载显示进度条。
- 桌面与手机分别适配、风格一致；功能分优先级，低优先级藏在二步操作里。

## 流程

1. **清单评审**：逐项确认 [功能与界面清单](01-inventory.md) 里每一项的去留、合并、拆分和优先级。
2. **分步原型**：每一步只做一块界面，评审后再做下一块。原型位于 `apps/web/redesign/`，与生产代码隔离。
3. **设计文档定稿**：每一步的结论写进对应文档，最后合并成新的设计规范，替换 DESIGN.md 中的视觉部分。
4. **实施**：按定稿方案迁入 `apps/web/src`，同步更新测试。

## 运行原型

```bash
bun run redesign:dev
```

打开 <http://127.0.0.1:4178>。左下角“原型”按钮（或 Shift + D）打开开发工具条，可以直接打开任意一个示例红包（“红包页”分组）、打开“内嵌图一览”，切换身份、窗口尺寸预览、减少动态效果、限时开奖结果、发放状态、慢速启动，并填入各类示例输入（含命令）。原型只使用本地示例数据，不请求任何接口。

在原型里试试：

- 按 `/` 或 ⌘K / Ctrl K 打开输入框，输入 `/` 查看命令；点右上角头像打开用户卡片，点第一行的名字进账号资料（看“发出的金额”）。
- 在起始页输入一个不存在的口令（如“测试口令2099”）按领取：按钮依次变成“正在确认…”和“还需等待 5 秒”，宽度连续变化、数字往下滚、红色渐变成灰，倒数完再变回来。
- 在起始页输入“周末口令2026”回车：只匹配到一个红包，跳到红包页后自动领取，看打开动画。
- 领取后红包皮收成小红包皮；往上滚到顶回到大红包皮，往下滚又变小。点红包皮上的“领取名单”看紧凑名单；在口令区点“验证其他口令”（或点地址条，列表第一行就是它），输入“公共口令2026”。
- 打开“周年庆 · 自定义”：说明太长，点“展开全文”看说明弹窗；领取后点小红包皮说明行的“展开”回到大红包皮（手机上小红包皮没有说明行）。
- 右上角的“分享”一直跟着，悬停就能展开菜单。
- 打开开发工具条的“内嵌图一览…”，看论坛里显示的图：切换视角（当前身份 / 未登录 / 没参与 / 参与过）、生成后的时间（看过期提示）、限时开奖和发放状态；单张图的地址是 `/🧧/<表情码>/🖼️.svg`。
- 在起始页输入“公共口令2026”看多匹配结果页（地址 `/🔑/<编号>`），输入 `https://linux.do/t/topic/2964597/1` 看帖子里的红包（地址 `/💬/2964597/1`）。
- 用开发工具条的“红包页”打开各类红包（自定义金额、无需口令的抽奖、模糊数量、已过期、无人报名……）；在“周五抽奖”报名后，把限时开奖切到“已开奖 · 中”或“未中”。
- **第三步的页面**：开发工具条的“页面”分组列出了全部入口。
  - 点右上角“发红包”：四步叠成一摞卡。点“限时开奖”自动进入下一步；空着按回车看这一步的错误；填好一路回车到“起个标题”，标题可以不填（用灰字的默认标题），“保存并开放”依次显示保存、检查商户凭证、开放，然后直接打开新红包（作者视角：不能领，口令全部可见，下面有编辑 / 付款记录）。中途点上面的一条回到那一步，后退 / 前进也能走步骤；“开放后 24 小时截止 · 改”和“更多设置”打开二级面板，附言和结束说明在面板里的第三级。
  - 红包记录 → 我发的：每行右侧三个按钮去 📝 编辑 / 📊 尝试统计 / 🧾 付款；“下周抽奖”是草稿：点开进 📝 编辑，点“预览红包页”看草稿预览，右栏有“删除草稿”。
  - 编辑进行中的“读书会 · 十月书单”：奖励、口令、时间都锁住了，只能改标题、说明、帖子和数量展示（它已加入广场，那个开关也锁着）。
  - 付款记录里点“一只猫”（发送已暂停）和“Kiki”（核对中）看付款详情的经过和处理记录。
  - LDC 商户配置：在“商户密钥”里随便填一个测试值保存，看“谨慎更换商户配置”确认弹窗和之后的凭证检查（少于 8 个字符会检查不通过）；工具条的“LDC 商户”可以切换未配置 / 正在检查 / 未通过 / 付款暂停。
  - 网站管理：先在工具条把身份切到“管理员”。概览里点“付款异常待处理”直接打开筛好的付款列表；红包、用户、付款三页点一行在右侧看详情（手机上是弹窗）；网站设置改一下尝试间隔再看操作记录。
  - 在发红包页填几个字后点左上角标志或用指令框换页，会先问“还有没保存的修改”（在步骤之间后退不会问）。手机尺寸下，发红包页的按钮在吸底操作条里。
  - 工具条的“页面数据”切到“加载慢 / 读取失败 / 刷新失败”看页面的三种状态；切到“加载更多失败”后在网站管理 → 用户滚到底，看“重试加载”。身份切到“新账号”看红包记录、付款记录、商户页的空状态。
  - 列表滚到底自动加载下一批（网站管理的用户、付款都超过 20 条），点进一行再后退，条数和位置都还在。
  - 工具条打开“模拟手机键盘”，窗口尺寸切到“手机”，在起始页点输入框：输入框移到顶部、页面压暗，建议列表停在假键盘上方；后退收起，打的字还在。
  - 身份切到“新账号”后配置商户（密钥填 8 个字符以上的测试值），再发一个红包并开放：商户页的“用它付款的红包”变成 1 个，换 Client ID 时会出现“谨慎更换商户配置”。
  - 先把身份切到“管理员”（也是林间），在网站管理 → 付款看“老周 · 读书会 · 1.00 LDC”（提示是“要等发红包的人在付款详情里更新原订单密钥”）；再打开付款记录，顶部“有 1 笔付款等你更新原订单密钥 · 去更新”，填一个测试密钥保存，看状态变成核对中。原型的修改不保存，刷新页面恢复示例数据。
  - 手机尺寸下在发红包页按 Tab 往下走：每个输入框都停在吸底操作条上方；保存时故意留空，操作条左边变成“N 处要改 ›”。
  - 工具条“提交结果”切到“结果未知”再领一个红包或保存草稿：按钮变成“重试原提交”，再按一次就成了；切到“失败”再“保存并开放”：草稿存好、开放失败；切到“版本冲突”在网站设置保存：换成另一位管理员刚存的版本。
  - 工具条“身份检查”切到“失败”：顶栏头像变成“身份检查失败，重试”，需要登录的页面请你重新检查。
  - 点红包皮上发红包的人、名单里的名字，弹出资料卡；口令区的眼睛按钮隐藏口令（共享屏幕时用）。
  - 红包记录切到“我参与的”、广场往下滚，点进一个红包再后退：页签和滚动位置都还在。

旧原型（`bun run prototype:dev`，4177 端口）继续作为业务行为参照。
