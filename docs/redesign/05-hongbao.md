# 05 红包页

状态：定稿。代码在 `apps/web/src/components/hongbao/` 与 `components/views/hongbao-view.tsx`；数据分级在 `lib/hongbao.ts`，称号在 `lib/titles.ts`，用时格式在 `lib/roster-time.ts`，内嵌图在 `packages/contracts/src/activity-image.ts`。

## 1 概念：活动就是红包

用户决定：站内没有其他类型的活动，界面上统一叫“红包”。代码、数据库和接口里仍叫 activity，不改。

| 原来 | 现在 |
| --- | --- |
| 活动 | 红包 |
| 发起活动（`/new`） | 发红包 |
| 活动历史（`/history`） | 红包记录 |
| 已公开的活动（`/square`） | 红包广场 |
| 兑奖、兑换 | 领取；限时开奖仍叫报名、开奖 |
| 跳转活动 | 打开红包 |
| 活动链接 / 活动 ID | 红包链接 / 红包 ID |
| 匹配到 N 个活动 | 匹配到 N 个红包 |
| 品牌描述“口令兑奖” | 口令红包 |
| 直接参与 | 无需口令 |

- 命令新增 `发红包 fahongbao fhb`、`红包记录 hongbaojilu hbjl`、`红包广场 hongbaoguangchang hbgc` 等写法，保留 `公开红包 gkhb` 等旧写法；去掉带“活动”的写法（见 [03](03-commands-routes.md)）。
- [01 功能与界面清单](01-inventory.md) 描述的是现行生产界面，保留原用词。

## 2 页面结构与叫法

**大红包皮**（没参与时一直是它；参与过后滚到最顶上也是它）：

```
顶栏（叠在红包皮上）
[● 12 人在看]                                     [⤴ 分享 ▾]  ← 都吸顶
                (小) 小满的红包
               周末红包 · 20 份
          [口令红包] [固定均分] [来自帖子 ↗]

    “周末快乐！口令藏在帖子一楼的最后一句话里。”      ← 说明，最多 6 行

   总额            已领              剩余
   17.60 LDC       8 / 20 份         02:17:50
   每份 0.88 LDC   ▓▓▓▓▓░░░░░░       截止 18:47
          (阿)(晴)(K)(老)(橘)  领取名单 ›
╲__________________ (开) __________________╱     ← 参与过后没有印章
          点「开」，输入口令领取 · 或按 ⌘K
结束说明 ……
口令 · 2 个 · 2 个未解出
```

**小红包皮**（参与过、页面不在最顶上时；吸在顶栏下面）：

```
顶栏（叠在红包皮上）                              [⤴]
              (小) 小满的红包 · 帖子 ↗
                周末红包 · 20 份                   ← 和大红包皮同样折行，最多两行
     说明：周末快乐！口令藏在帖子一楼的最后… 展开    ← 收起成一行（手机上没有这一行）
   总额 17.60 LDC    已领 9 / 20 份    剩余 02:17:50   (阿)(晴)(K) 领取名单 ›
╲______________________________________________╱
                 +0.88 LDC  ……我的结果
```

- **尺寸**按窗口（不是视口）算，在 `hongbaoSizes()` 里统一得出：
  - 大红包皮至少为窗口高的 68%（手机 60%），限制在 27–46rem；内容更多时更高，但不超过窗口高（先压缩说明，见第 12 节）；
  - 小红包皮按内容，宽窗口约 210px，手机约 230px；
  - 封口弧高 `clamp(36, 6% 高, 64)px`，印章直径 `clamp(76, 20% 宽, 112)px`。
- 内容最宽 36rem，一列；红包页里没有口令输入框，口令走带作用域的指令框（见 [02](02-shell.md) 第 4 节）。
- **我的看法**：
  - **名单做成弹窗，赞成。**生产本来就是可后退关闭的弹窗；弹窗里能放紧凑的表格，并带上红包标题，截图自带上下文；页面只剩红包本身、我的结果、说明和口令，更紧凑。
  - **分享吸顶，赞成。**分享是领完以后最常做的事，放在固定位置随时能点。宽窗口用图标加“分享”，手机只用图标。

## 3 数据分级

照生产接口整理（`apps/api/src/activities/service.ts`、`claim-queries.ts`、`password-service.ts`），页面按这张表投影（`apps/web/src/lib/hongbao.ts`）。

| 级别 | 谁能看 | 内容 | 页面上的位置 |
| --- | --- | --- | --- |
| 完全公开 | 所有人，含游客 | 发红包的人、标题、状态；奖励方式（固定均分 / 拼手气 / 自定义 / 限时开奖）；参与方式（口令 / 无需口令）；开放与截止（开奖）时间；关联帖子；金额与数量（模糊时按下面的规则隐藏）；限时开奖的报名人数、上限、开奖后的中奖人数；说明；口令个数 | 红包皮（含说明）、口令区标题 |
| 名单 | 所有人，实时，**始终公开** | 头像、昵称、金额、用时、称号。限时开奖开奖前只有报名名单，开奖后加中奖名单 | 名单弹窗 |
| 结束后公开 | 所有人 | 结束说明、全部口令明文 | 结束说明、口令区 |
| 仅本人 | 领取或报名的人 | 自己的金额、发放状态、用过的口令、验证出的口令（已解出）、领取后附言、开奖结果 | 我的结果、口令区 |
| 仅发红包的人 | 发红包的人 | 全部口令、领取明细（所用口令和付款状态）；全部配置、尝试统计、付款记录 | 红包页上：口令区（全部口令）、名单弹窗每行多一行（[07](07-pages.md) 第 6 节）；其余在 📝 📊 🧾 页 |

- **模糊数量**照生产隐藏：
  - 不显示份数；
  - 固定均分不显示总额，只显示每份；
  - 限时开奖不显示报名人数、中奖人数和上限（写“名额不公开”）；
  - 名单弹窗不写人数（标题、名单切换、末行都不写；名单行本身仍能数出来，和生产一样）。
- **余量档位**按剩余比例：0 为已领完，>50% 充足，>20% 有限，其余少量（与生产同一阈值，生产的完整说法是“奖励充足 / 奖励有限 / 剩余少量奖励 / 奖励已领完”）。
- **口令区**：没参与时只显示个数，每个口令一行占位（固定 12 个字符、模糊、带锁，写“未解出”），不透露真实长度和字符。
- **长口令**（最多 32 个字）：口令区每一行、我的结果、发红包的人的名单弹窗里的口令，放不下时换行显示全文，不截断。窄窗口里口令区的标签（已解出等）挪到口令下面，让口令占满一行。
- **更新**：登录用户开着红包页时，变化都由服务端推送，页面不定时读取：
  - 有人领取或报名、开奖、发红包的人改了内容或提前结束：马上推来最新的公开数据（0.3 秒内的连续变化合成一次），名单和口令一览只在推来的数据显示有变化时各读一次；
  - 只有自己看得到的变了（自己那笔的付款进度；发红包的人是名单里任何一笔）：只推一句“你的数据变了”，页面只重读自己那份；
  - 到截止时间：页面按时钟自己翻成已结束，随后推来结束说明，口令全部显示；
  - 红包结束后：还在等付款的人保留连接，到账再断开，其他人马上断开。

  游客、草稿和连不上推送的人照旧轮询：公开数据 5 秒，名单、口令和等付款 15 秒。红包结束、付款也都到账以后，谁都不再读取。
- **在看人数**（2026-10-18 用户决定）：红包进行中，登录用户的页面左上角吸顶显示“N 人在看”，和右上角的“分享”对称：同样的白色玻璃胶囊，不可点；前面一个缓慢呼吸的绿点（在线的意思，不用红色，免得像提醒；减少动态效果时不呼吸），数字变化时逐位滚动。
  - 数的是此刻开着这个红包页、连着推送的登录用户，包括自己；同一人开几个标签页、几台设备都只算一个。游客不连推送，所以不计入，也看不到这个数。
  - 有人进来或离开就推新的人数（和公开数据一样，0.3 秒内的变化合成一次）；连接断开时收起，重连后随第一条人数回来。切到后台的手机页面要等心跳超时才断，人数会晚一两分钟才减少。
- **我的结果**里，发放状态、用过的口令和自己的称号排在同一行；底部注明哪些只有你看得到，只列这张卡上真有的几项（如“金额、发放状态、口令和附言仅你可见”，报名未中“报名记录和口令仅你可见”）。
- **🐟额红包**（[🐟额设计](../balance-design.md) 第 14 节）：我的结果的金额后面一个小 🐟（在🐟额，点开说明），发放状态写“已存入🐟额”和“转出 ›”，🐟额可用不到 1 时多一行“满 1 LDC 可以转出到 Credit。”；领取提示是“已领取 0.10 LDC，存进了🐟额。”。发红包的人的名单每行写“已存入🐟额”，没有付款记录入口。
- **没有 Credit 账户**（上游回复“收款人不存在”，规则见 [付款运维](../payment-operations.md)）：发放状态下面换成一块提示，代替原因说明（用户决定）：
  - 被拒后 5 分钟内：标题“还没有 LINUX DO Credit 账户”，说明“这笔 0.10 LDC 暂时发不出去，请先注册 Credit 账户，确认注册好了再回来点‘重新发送’：只能重新发送一次”；两个按钮“注册 Credit 账户 ↗”（新标签打开 credit.linux.do）和“重新发送”；下面一行“还剩 4:32 可以重新发送，过时不再补发”，倒计时到 0 就换成下面的样子；
  - 点了以后按钮显示“正在重新发送…”，之后状态下面一直写“正在重新发送，稍等十几秒”，直到到账或再次被拒；
  - 已经重新发送过、或过了 5 分钟：标题“这笔没能发出”，说明被拒后 5 分钟内可以重新发送一次，现在已经不能再发，不再补发；没有按钮。

## 4 红包皮上的公开数据

标题下面一行是标签，只放领取的人一眼要知道的特点，不写金额（金额看三格）。每个标签悬停、聚焦或点按时弹出一句说明，读屏软件把它读作标签的描述（`tag-hint.tsx`）。

| 标签 | 什么时候有 | 说明 |
| --- | --- | --- |
| 口令红包 / 无需口令 | 一直有 | 输入正确的口令才能领取 / 登录后直接领取，不用口令（限时开奖说“报名”） |
| 固定均分 / 拼手气 / 自定义金额 / 限时开奖 | 一直有；拼手气和限时开奖接上分法，如“拼手气 · 微信同款” | 分法的说明和发红包表单里的一样 |
| 🐟额 | 🐟额红包 | 领到的 LDC 先存进🐟额，随时可以转出到你的 Credit 账户（[🐟额设计](../balance-design.md) 第 14 节） |
| 需人机验证 | 打开了领取前人机验证 | 这是发红包的人的要求；中国大陆网络、广告拦截插件或部分隐私浏览器可能加载不出验证 |
| 已结束 | 结束后 | 没有 |
| 来自帖子 ↗ | 关联了帖子 | 是链接，打开帖子 |

统计口令尝试、人数不足时发完奖池、加入广场、付款商户都不做标签。

三格，下面是名单入口。

| 格 | 显示 |
| --- | --- |
| 金额 | 固定均分：总额 17.60 LDC / 每份 0.88 LDC（模糊时只有“每份 0.50 LDC”）；拼手气：奖池 / 平均 3.00 LDC（除不尽时“平均约 3.33 LDC”）；自定义：奖池 / 平均每份，发红包的人自己看到的是“按顺序发放”或“随机发放”；限时开奖：奖池 / 抽 N 人。模糊时第三行空着。玩法已经写在标签里，第三行不再重复 |
| 数量 | 精确：已领 x / y 份 + 进度条；模糊：余量 + 四格；限时开奖：报名 N 人（有上限时 N / 上限 人 + 进度条，否则“不限人数”），开奖后中奖 N 人 / M 人报名；模糊时“名额 · 不公开” |
| 时间 | 剩余 / 距开奖 倒计时 + 截止 / 开奖时刻（“18:47”“明天 20:00”“10月16日 18:26”；手机上一格放不下，后天以后只写日期“截止 10月16日”，时刻看上面的倒计时）；超过一天的倒计时省掉秒（“1天 01:32”）；结束后为状态：已领完 / 已过期 / 已开奖 / 无人报名 / 开奖中 |

- 手机上标签和注释 13px、数值 20px；窗口窄于 375px 时随窗口缩小（320px 时 11px / 16px），“1天 23:55”“开奖 明天 20:00”这类最长的内容也不出省略号。
- **小红包皮上**：宽窗口里名单入口和三格在同一行，手机放到下一行。
- 名单入口在大小红包皮上都能点，样式不变。
- **名单入口的头像**：最近领取（限时开奖开奖前是最近报名）的 5 个人，开奖后是奖金最大的 5 个。头像和三格数据同一次读到，人数和头像总对得上；读到新的人，名单随即重读，开着的名单弹窗也马上跟上。

## 5 分享

右上角吸顶的“分享”按钮（头像正下方，属于内容区）：鼠标悬停时原地展开下拉菜单，移开后收起；点击、轻触或按 Enter / ↓ 会固定展开，再点一次、点别处或按 Esc 收起。菜单从按钮右上角展开。

菜单分两组（用户决定）：上面三种给社区用，分割线下面是原始链接。窗口太矮放不下时，菜单里面滚动。

| 菜单项 | 复制的内容 | 什么时候有 |
| --- | --- | --- |
| 社区专用链接 | `` [`/🧧/<表情码>`](https://linux.do/t/topic/3033290/2) ``：路径写成代码，社区不会把表情转成图片，也不展开链接预览；链接固定是本站在社区的那一帖，不直接链到站外。下面一行写“避免转码与违规推广” | 一直有 |
| 专用链接与口令 N | 三行：`【标题】`、社区专用链接、`` 口令：`…` ``（领取和报名都写“口令”） | 每个你能看到的口令一项：领取或报名后是你用的和验证出的，结束后是全部；游客在进行中看不到口令，就没有这几项。N 按你能看到的顺序编号，下面一行显示口令本身 |
| 社区内嵌代码 | 四行：`<center><a href="https://linux.do/t/topic/3033290/2">`、`<picture><source type="image/svg+xml" srcset="…/🧧/<表情码>/🖼️.svg 1x"><img width="420" height="560" `、`alt="小满的红包：<表情码>"></picture>`、`</a></center>`。链接和社区专用链接一样，`alt` 写表情码、不写标题。下面一行写“可实时展示红包数据” | 一直有；图片见第 6 节 |
| 原始链接 | `https://…/🧧/<表情码>`，分割线下面第一项 | 一直有 |
| 原始链接与口令 N | 三行：`【标题】`、原始链接、`口令：…`，不带 Markdown，给社区以外用 | 和专用链接与口令 N 一样 |

- 复制后，那一项变成“✓ 已复制”约 0.9 秒，然后菜单收起，焦点回到“分享”；读屏播报“已复制链接与口令 1”之类。复制失败显示“复制失败”。
- 键盘：↓ / ↑ 在项目间移动，Home / End 到头尾，Esc 收起并回到按钮，Tab 离开时收起。

## 6 内嵌图

**地址**：`/🧧/<表情码>/🖼️.svg`，`/🧧/<表情码>/🖼️` 也可以；表情 🖼️ 带不带变体选择符（U+FE0F）都认，因为链接经过论坛、聊天软件时常被去掉。内嵌代码用带 `.svg` 的那个。

**只回答三件事**：谁的什么红包、现在还能不能领、我领到了没有。细节点开红包页看。

**按看图的人分级**（2d，沿用生产现有的分级，只换画面）：

| 看图的人 | 红包皮上 | 印章 | 封口下方 |
| --- | --- | --- | --- |
| 未登录：没有图片 Cookie、浏览器拦截第三方 Cookie、发红包的人自己 | 发红包的人、标题 | 进行中“查看”，开奖中“开奖中”，结束后灰色“完” | 一行余量和“数据截至”；结束后写结束原因 |
| 已登录 · 没参与 | 同上 | 开 / 报，开奖中“开奖中”，结束后灰色“完” | 同上 |
| 已领取 / 中奖 | 同上，封口打开、没有印章 | — | 你已领取 / 你中奖了、+0.88 LDC（绿色大字）、发放状态、领取于（中奖：开奖于）10月14日 18:21:05 |
| 已报名 | 同上 | “已报名”，开奖中为“开奖中” | 已报名，等待开奖 / 正在开奖，加“数据截至” |

- **余量一行**：剩余 12 份；限时开奖为“已报名 23 人”；模糊为“余量有限”（领完是“已领完”）；模糊的限时开奖只写“限时开奖”；开奖中为“正在开奖”。
- **从不画**：任何人的头像、领取或报名的人、口令、说明和附言、总额 / 每份 / 奖池、截止和开奖时间、称号。
- **为什么这样取舍**：
  - 论坛读者多数没有可用的图片 Cookie，游客图不能假设身份：他可能已经领过，所以印章只写“查看”，不写“开”。
  - 不画头像：数据库里只有头像链接，图里不能引用外部资源；也不画谁领了红包。
  - 余量很快过时：每张图都写“数据截至 18:21:05”，并且一直保留；会变的数据（余量、等待开奖、还没发放的金额）在它下面再加一行提示，10 秒后“数据可能过期，打开红包查看最新”（琥珀色），30 秒后换成“数据已过期，打开红包查看最新”（红色）。只用 CSS 延时，图里不能跑脚本。
  - 发放状态用生产图片的四档说法：已发放（绿）、付款处理中、正在核对原订单（琥珀）、需要关注（红）。
- **画面**（2c 的画风，内容精简）：
  - 420 × 560，和内嵌代码一致；超椭圆卡片，浅色纸底，柔和投影；
  - **封着**：红包皮上是“小满的红包”、一道金色短线、标题（最多两行）；印章压在封口弧线正中，字数越多字越小（单字 40px、两字 24px、三字 19px），每 6.4 秒一道光泽；下面一行主信息、“数据截至”和过期提示；
  - **打开**（已领取 / 中奖）：红包皮短一截，没有印章；下面是“你已领取”、+金额、发放状态小标签、领取（中奖为开奖）的时刻、“数据截至”；
  - **开包动画**（打开的图才有，图片一加载就播一次，和红包页的开包同一套）：开始时是封着的样子；0.16 秒印章轻按后缩小消失、一圈金光扩散；0.42 秒起封口的红色面向上收到打开的高度（0.6 秒），同时一道光扫过红包皮；0.78 秒起“你已领取”、金额、发放状态、时间依次上浮淡入。动画结束停在打开的样子；减少动态效果时直接显示打开的样子；
  - 结束、未中：降低饱和度，印章换成锡色；
  - 最下面一行是这个红包的 14 个表情（表情码），不写品牌；在指令框里粘贴它就能打开红包。只用系统字体（表情用系统彩色表情字体），没有脚本，也不引用外部资源。
- **实现**：画法在 `packages/contracts/src/activity-image.ts`，接口按图片 Cookie 认出看图的人后现画（[06](06-production.md) 第 6 节）。

- **为截图设计**：标题带人数，下面一行写清是谁的哪个红包、已领多少、何时开放，截图不用另外解释。
- **每人一行**（40px）：序号、22px 头像、昵称（超长省略，至少保留几个字）、“你”、称号、用时、金额。用时和金额列定宽、等宽数字右对齐；悬停显示具体时刻。列头对读屏隐藏（列表单独滚动，和列头分开），每格自己说明：“第 N 位”“用时 …”“… LDC”。
- **用时**是开放到领取（或报名）的时长：
  - 不到 1 分钟：`4.627秒`，固定三位小数，精确到毫秒；
  - 不到 1 小时：`1分15秒`；不到 1 天：`3小时05分`；1 天以上：`2天3小时`；
  - 只给 分 和 秒 补零；时间缺失或为负显示“—”。
- **顺序**：先领的在上，序号固定，新领取出现在底部（用户选定）。中奖名单按金额从高到低。
- **限时开奖**有两个名单，用一条拉满宽度的小号分段选择切换（不是页签）：中奖名单（开奖后，默认）/ 报名名单；开奖前只有报名名单。
- **加载**：和别的列表一样滚到底自动加载（[07](07-pages.md) 第 1 节）。没人时写“还没有人领取。”“还没有人报名。”或“没有人中奖。”。
- **浮层规则**同用户卡片（[02](02-shell.md) 第 7、9 节），关闭后焦点回到名单入口。
- **手机**：底部浮起面板（外框见 [04](04-visual.md) 第 3 节）；列宽收窄，用时改小一号，保证带长称号（「我焯有桂！」）的行也能露出昵称。

## 9 口令区：验证其他口令

- **入口**：已领取或已报名、口令红包、进行中、还有未解出的口令时，口令区标题右侧出现“验证其他口令”（规则照生产：只有参与过的人能验证）。
- **流程**：
  - 点击后展开带“验证 · 红包标题”作用域的指令框，占位文字“输入其他口令”，下拉只有“验证「标题」的口令”，动作按钮“验证”；
  - 也可以点地址条：展开后列表第一行就是“验证「标题」的其他口令 · N 个未解出”，选中后一样（[02](02-shell.md) 第 4 节）；
  - 和领取共用 2 秒冷却，确认约 450ms。
- **结果**：

| 情况 | 结果 | 冷却 |
| --- | --- | --- |
| 正确 | 口令行标绿色“已解出”并短暂泛金（1.6 秒，减少动态效果时不闪）；指令框收起；播报“口令已解锁，不会再次领取奖励。”；焦点回到“验证其他口令”（没有剩下的就落在刚解出的那一行） | 有 |
| 不正确 | 指令框保留，文字红闪两下，“口令不正确，请重新尝试。” | 有 |
| 已经知道的口令 | “你已经知道这个口令。”（前端判断，生产没有这个结果） | 无 |
| 红包已结束 | “红包已结束，口令已公开。” | 无 |
| 没收到结果（网络或服务出错） | 指令框保留，“没有收到验证结果，请再试一次。”（验证不改任何东西，再试就是）；429 时“尝试过于频繁，请稍后重试。” | 只有 429 有 |

- 解出口令不会再领一次，也不增加中奖机会。
- 原型里解出的口令只存在内存里，按身份分开记，重置参与记录时清空。
- 口令行标签的优先级：已用此口令报名 > 已用此口令领取 > 已解出 > 已公开。
- **进行中默认隐藏**（用户决定）：进行中的红包常被截图转发，口令一露出就可能无意中泄露。所以红包结束前（草稿也算），看得到的口令一律先隐藏，后面跟一个眼睛按钮：
  - 口令区：标题右侧的眼睛一次显示或隐藏全部，每行右侧的眼睛单独切换；刚解出的口令也先隐藏；
  - 我的结果：用过的口令后面一个眼睛；
  - 发红包的人的名单弹窗：顶部说明那一行末尾一个眼睛，切换所有行的口令；
  - 红包记录“我参与的”：只写“用口令领取”，不写口令（整行是链接，放不下眼睛）。

  隐藏时是模糊的占位字符（固定 12 个，由红包或这一行生成，和口令的长度、字符都无关），读屏念“已隐藏”，口令本身不在页面上；显示和隐藏之间交叉淡化。不记住选择。红包结束后口令都已公开：全部明文，没有眼睛。

## 10 印章（平面）

| 情况 | 印章 | 点击后 |
| --- | --- | --- |
| 口令红包 | 开 | 展开带作用域的指令框，输入口令领取 |
| 无需口令的红包 | 开 | 直接领取 |
| 限时开奖 | 报 | 同上，改为报名 |
| 未登录 | 开 / 报 | 打开用户卡片登录 |
| 冷却中（无需口令） | 变淡，仍可聚焦 | 提示“还需等待 N 秒” |
| 没收到领取 / 报名结果 | 开 / 报 | 提示“点「开」重试原提交”和“尚未确认领取结果，请重试原提交以确认结果。”；再点是同一次提交，不受冷却限制，不会领两次 |
| 已结束（未参与） | 灰色“完” | 不可点，提示红包已领完 / 已过期 / 已开奖 / 无人报名 / 报名已截止，正在开奖… |
| 参与过 | 没有印章 | — |

- 内嵌图上的印章另有几种写法（查看 / 已报名 / 开奖中 / 未中），见第 6 节。
- **空闲**：每 6.4 秒一道斜向光泽扫过。确认中：光泽连续扫过，外圈一段金色弧线在平面内旋转。
- **状态之间都有过渡**（3c）：印章上的字交叉淡化；金色弧线淡入淡出；变淡、变灰 200ms（底色的四个色标注册成颜色，金能渐变到锡色）。下面那句提示和倒计时之间交叉淡化，倒计时的数字逐位往下滚。
- **悬停 / 按下**：1.04 / 0.96。焦点环：奶油色加深红色双圈。
- **单匹配后自动领取**：起始页输入的口令只匹配到一个红包时，进入红包页约 0.42 秒后自动领取。
- **提交没成功**（生产的处理）：网络断了或服务出错时不知道领没领到，保留这次提交，指令框和印章的按钮都变成“重试原提交”；收到 429 时提示“尝试过于频繁，请稍后重试。”。限时开奖处处写“报名”，包括指令框的按钮和下拉。
- **领取前人机验证**（作者打开时）：口令正确、点「开」或点「报」之后，先弹出“人机验证”（标题之下一句“这是 @作者 的要求：领取这个红包需要先通过人机验证，通过后会自动领取。”，限时开奖写报名）。弹窗里是 Cloudflare 的小组件，转圈通过后（偶尔要点一下复选框）写“已通过，正在领取…”，等领取有了结果再关，结果照常出现在页面上。关掉弹窗就不领取，提示“没有完成人机验证，这次没有领取。”。小组件加载不出来或没通过时写明可能的原因（中国大陆网络连不上 Cloudflare、广告拦截插件），给“重试”。令牌两次都没通过时提示“人机验证没有通过，请稍后再试。”。这种红包的页面会提前加载验证脚本，弹窗打开时就能开始。
- **尝试统计**：开了统计的红包，输入口令的指令框下面先写一句“这个红包开了尝试统计：提交的口令会汇总给发红包的人看。”（生产在口令框下也有这句）。
- 印章是金币，按“只有真正的圆形保持圆形”的规则不做超椭圆。

## 11 打开动画

D = 0.15 秒；从指令框领取时 D = 0.5 秒，等指令框先飞回地址条。

| 时间 | 动作 |
| --- | --- |
| 0 | 记录领取；读屏播报“已领取 0.88 LDC。”；页面不在顶部时先用 0.3 秒滚回顶部，之后的时间仍从领取算起 |
| D | 印章轻按回弹（放大到 1.12） |
| D + 0.14 秒 | 印章缩小淡出；一圈金色光环扩散消失 |
| D + 0.18 秒 | 一道光扫过红包皮（0.6 秒） |
| D + 0.26 秒 | 大红包皮收成小红包皮（0.62 秒），做法和滚动切换相同（第 12 节）：标签行、说明全文、数据第三行淡出或缩小消失，发红包的人、标题、标签和数值移动并缩小，名单入口移动；下面的内容同步上移 |

- **报名**：同一套动画，没有金额，不落碎片；播报“已报名，等待开奖。”。
- **开奖结果**：页面开着时开奖，只淡入结果；中奖时数数、落碎片，未中显示“本次未中奖 · 谢谢参与”。发放状态从开奖那一刻算起。
- **回访**：打开已领过的红包，直接是小红包皮。
- **减少动态效果**：直接到最终状态，没有光泽、旋转、碎片和数数。
- 只用位移、缩放和透明度；倒计时、冷却秒数放在叶子组件里，每秒刷新不会触发布局动画。

## 12 大小红包皮的切换

- **没参与**（可领取、已结束没参与）：只有大红包皮，跟着页面滚动。
- **参与过**（开包后、回访）：红包皮吸在顶栏下面（红色仍从窗口顶边画起），有两种状态：
  - **往下滚超过 32px，变小；回到最顶上（小于 1px），变大**。中间 31px 的空档防止触控板的细小抖动来回切换，按一次方向键（40px）就能跨过；
  - 每次切换是一段 0.42 秒的动画，不跟着滚动走，也不停在中间。切换可以互相打断，从当前位置接着动；
  - 滚动引起的切换不改滚动位置，所以不会和惯性滚动打架；
  - 进入小红包皮时页面停在 32px（开包、回访），小红包皮下面压着正文最上面的 32px，所以随时能往上滚回大红包皮；页面最小高度为窗口高 + 32px + 1rem，内容很短也能滚；
  - 自己进入小红包皮（开包、切换到领过的账号）分两步：先把大红包皮吸顶、页面移到 32px，红包皮下面一段临时边距抵消这 32px，看起来什么都没动；之后的另一次提交才切换，这段边距和高度一起动画到 0。切换那一刻页面从不移动；
  - 其他入口：小红包皮说明那一行的“展开”（只在宽窗口，焦点落到标题）、Home / PageUp 回到大红包皮；End / PageDown 变小；
  - 吸顶时内容区的 `scroll-padding-top` 等于小红包皮的高度，聚焦或页内查找的内容不会藏在下面；顶栏不显示“已滚动”的分隔线。
- **过渡**（大 → 小，小 → 大反过来）：

| 部分 | 大红包皮 | 小红包皮 | 过渡 |
| --- | --- | --- | --- |
| 红包皮高度 | 见第 2 节 | 按内容 | 高度动画，下面的内容跟着移动 |
| 发红包的人 | 28px 头像，15px 字 | 18px 头像，13px 字，后接“· 帖子 ↗” | 移动并缩小 |
| 标题 | 22–36px 半粗，行高 1.3，最多两行，超出省略 | 17–20px，折行和大红包皮相同 | 同一个元素等比缩小、移动。两种红包皮按同样的 em 宽度折行（大红包皮上量出来，最多 16em），都最多两行，所以小红包皮上也是同样的一两行，缩放不会变形 |
| 标签行 | 第 4 节的标签 | 没有 | 淡出 |
| 说明 | 15px / 24px，全文，最多 6 行；窗口矮时先压缩它（至少 2 行），被截断时末行渐隐、加“展开全文” | 宽窗口 13px 一行摘要和“展开”；手机上没有（小红包皮吸顶，已经占了近三成屏幕；完整说明往上滚回大红包皮就能看到） | 全文淡出，摘要淡入 |
| 三格数据 | 标签 15px / 数值 26px（窄窗口见第 4 节）/ 第三行 | 标签 12px、数值 15px 并成一行 | 标签和数值移动并缩小；第三行先缩小再消失 |
| 名单入口 | 三格下面，15px，22px 头像 | 样式不变 | 只移动 |

- **长说明**：生产允许 10,000 字的 Markdown。放不下的进说明弹窗（和名单弹窗同一个外框 `panel-dialog.tsx`：占一条历史记录，Esc / 后退关闭，焦点回到“展开全文”）。原型按纯文本显示、按空行分段；生产用 SafeMarkdown，链接在红底上是奶油色加下划线。
- **实现要点**（`hero.tsx` 顶部注释、`use-cover-state.ts`、`use-cover-height.ts`、`cover-motion.ts`）：
  - 外框同时带 motion 的 `layout` 和 `layoutRoot`：子元素的布局动画相对外框计算，吸顶时改滚动位置不会让它们跳；
  - 红色面的高度是一个始终为像素值的 motion value，切换时从当前高度动到新内容的高度；不对它用 `layout`，缩放会把弧线压扁；
  - 只有两种状态都有的元素（叶子）带 `layout`，只在一种状态出现的元素用 `AnimatePresence mode="popLayout"`；
  - 只在一种状态出现的元素也带 `layout="position"`：离开的那一份跟着所在的行滑走再淡出，不会因为行的位置突变而跳一下；新的一份在旧的一份消失前就开始淡入（重叠约 0.3 秒），中间没有空白的一刻；
  - 2d 评审时标题和说明的过渡会闪：原因是两行标题用了淡出再淡入、中间有空档，离开的元素又因为所在的行移动而跳了一下。曾试过两份标题共享 `layoutId` 交叉淡化，但在开包前先滚回顶部的情况下会整体偏移 83px，所以改成一个元素加相同的折行；
  - 内容区关闭滚动锚定（`overflow-anchor: none`），否则红包皮变矮时浏览器会把滚动位置往回拉，到 0 又变大；
  - 挂载时找滚动容器要从红包皮自己的元素往上找：祖先的 ref 在子组件的 layout effect 之后才挂上。
