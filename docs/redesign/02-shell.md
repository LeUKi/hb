# 02 外壳与兑奖入口（第一步）

状态：定稿，2026-10-15 上线。代码在 `apps/web/src/components/shell/` 与 `components/omnibox/`。命令与地址见 [03](03-commands-routes.md)，视觉语言见 [04](04-visual.md)。

只借浏览器的风格，不照搬浏览器布局：没有标签页，没有前进 / 后退按钮。返回靠左上角图标、Esc 或系统返回。

## 1 界面分层与叫法

从下到上：

```
背景（动态光晕）
└ 窗口（超椭圆；手机上铺满屏幕）
   ├ 窗口托板 ……… 窗口的投影
   ├ 玻璃层 ……… 半透明毛玻璃，和窗口一样大
   └ 内容区 ……… 和窗口一样大、可滚动；每个地址一个“页面”画在这里
      ├ 顶栏 ……… 叠在内容区最上面：起始页图标 · 地址条 · 发红包 · 红包记录 · 头像
      │   └ 地址条 …… 顶栏中间的地址；点击变成指令框
      ├ 页面操作 …… 页面自己的固定按钮，吸在头像下方（红包页：分享）
      ├ 压暗层 ……… 指令框或面板打开时盖住整个窗口（含顶栏）
      ├ 指令框 ……… 大输入框 + 建议列表（起始页居中，或展开在窗口上部）
      ├ 用户卡片 …… 点头像弹出
      ├ 名单弹窗 …… 红包页点“领取名单”、红包记录里点一行的“名单”弹出

```

红包页内部各部分的叫法见 [05 红包页](05-hongbao.md)。

**顶栏的材质**见 [04](04-visual.md) 第 3 节。

**为什么各层自己裁切成窗口形状**：背景模糊会被祖先元素的裁切截断。2b 时内容区外面套了一层超椭圆裁切，结果顶栏的模糊在 Chrome 里完全采不到滚动的页面（模糊调到 40px 透过去的字照样清楚）。现在内容区外层不裁切，只保留矩形 `overflow: hidden`；需要窗口形状的层各自裁切（`WindowClip`）：玻璃层、`main#view`、顶栏（用窗口的路径，只裁上面两个角）、指令框压暗层、用户卡片和名单弹窗的压暗层。所有层用同一个尺寸来源，路径完全一致。玻璃层和内容区仍是两个同尺寸的兄弟元素。

**地址条与指令框是同一个元素**，整个窗口只有一个实例，在三个落位点之间移动：起始页中的落位点、顶栏里的停靠位、展开时的指令位。

品牌的唯一来源是 `redesign/lib/brand.ts`。2d 起品牌名是“lafish的红包站”（原来的“解meme”彻底放弃），但尽量不出现在界面上：只用在浏览器标签页的标题里（“周末红包 · 20 份 · lafish的红包站”，起始页只有品牌名；未找到、结果列表这类页面用页面上的标题，例如“未找到页面 · lafish的红包站”“帖子里的红包 · lafish的红包站”）。起始页没有看得见的标题，给读屏留了一个隐藏的一级标题（品牌名）。界面上只有标志：朱红超椭圆方块加金点，左上角、加载界面和网站图标（favicon，`brandIconSvg()` 生成的 SVG）都用它。名称可以为空；去掉标志时，左上角显示“起始页”图标。

## 2 三种形态

| 形态 | 何时 | 外观 |
| --- | --- | --- |
| 起始 | 路由 `/` | 居中大输入框，高 64（窄窗口 56） |
| 停靠 | 其他路由 | 顶栏里的地址条，高 44（窄窗口 40）；桌面和手机都停在顶部（用户决定） |
| 展开 | 点击地址条、⌘K / Ctrl K、按 `/`、口令红包点「开」 | 回到大输入框尺寸，位于窗口上部，背后的页面压暗并高斯模糊 |

切换方式：

- **起始 → 停靠**：提交口令（单匹配 / 多匹配）、跳转红包、执行命令、帖子查询有结果时发生。
  - 起始页的次要元素先淡出。
  - 指令框按真实位置和尺寸移动到停靠位。
  - 输入内容淡出，地址淡入。
  - 新页面稍晚淡入，并上移 14px 到位。
- **停靠 → 起始**：系统返回或点左上角图标，反向移动。系统返回保留起始页输入内容；点图标清空输入（相当于重新开始）。
- **停靠 ⇄ 展开**：展开时背后的页面模糊压暗，指令框移到指令位，下方出现建议列表；Esc、点击压暗区域、再按 ⌘K 或系统返回都可以收回。

移动时只改位置与宽高，不用缩放，文字不会被拉伸。输入框元素始终保留在页面中，输入内容与输入法状态都不会因为移动而丢失。背景和阴影由 CSS 类按形态切换并过渡；超椭圆的圆角半径随移动一起变化（起始 22 → 停靠 14 等，见 [04](04-visual.md)）。

## 3 地址条内容

地址条显示的就是当前地址，不再显示红包名和口令：

| 当前页面 | 地址条显示 |
| --- | --- |
| 红包 | `/🧧/🔕🐋…☕`（表情码，斜杠浅色）；悬停提示和无障碍名为红包标题 |
| 红包下的 📝 📊 🧾 | 红包地址后接 `/📝` 等，宽窗口附浅色页名；读作“编辑红包「标题」”等 |
| 命令页 | `/history` 等，等宽字；宽窗口后面附浅色中文名。下面的子页（`/payments/<编号>`、`/admin/users` 等）显示完整路径加页名 |
| 口令多匹配结果 | “匹配到 N 个红包”（不显示口令；读不到结果时写“查找结果”） |
| 帖子关联结果 | `linux.do/t/topic/<id>/<楼>` |
| 未找到 / 无效地址 | 当前路径，浅色 |

- 窄窗口显示 `🧧 + 表情码`，放不下时缩小表情的字号，14 个都显示（390px 宽的手机上约 9px）。
- 宽窗口右侧显示快捷键提示（⌘K 或 Ctrl K）。
- 参与状态只在页面里显示。
- **切换动画（滚筒）**：地址变化时，原地址向上转走，新地址从下方转上来。
  - 两行文字在同一个滚筒上（转轴在文字后方约半个地址条高），始终相差四分之一圈，弹簧带轻微回弹。
  - 命令页之间、红包之间、结果页选中红包、系统前进后退都会滚动。
  - 只在地址条本来就显示着地址时滚动。从起始页或展开的指令框回到停靠时，地址条直接淡入新地址；离开停靠时保留原地址淡出。
  - 减少动态效果时直接替换。
- 地址条的无障碍名就是当前地址的读法（红包读作“红包「标题」”），滚动中的文字对辅助技术隐藏。

## 4 口令与地址的关系：作用域（已采用）

- 在红包页展开指令框时，左侧带作用域标签（红包标题）：
  - 输入口令并回车 = 领取这个红包，走现有的领取接口与 2 秒冷却；
  - 下拉同时给出“领取 红包标题”和“在全部红包中查找”两条；
  - 作用域里只能输入口令：占位文字是“输入口令”；输入链接或命令时提示“这里只能输入口令；清空后按退格，可改为输入链接或命令。”，不标红、也不提供一键优化；
  - 空输入时按退格，或点标签上的 ×，去掉作用域，回到全局查找 / 跳转；
  - 口令不正确时提示“口令不正确。”，并给出“在全部红包中查找”。
- 只有当前账号能用口令参与这个红包时才带作用域（已登录、口令参与、进行中、未参与，不是自己发的；别人的草稿当作不存在）。
- 因此红包页里不放口令输入框：口令红包点「开」只是展开带作用域的指令框；直接领取的红包点「开」直接领取（见 [05](05-hongbao.md)）。
- **验证作用域**（2c）：“验证其他口令”打开带“验证 · 红包标题”标签的指令框，见 [05](05-hongbao.md) 第 9 节。
- **列表第一行是这个红包**（3c）：在红包页点地址条（或按 ⌘K）展开、没有作用域、输入为空时：
  - 参与过、还有未解出的口令：第一行是“验证「标题」的其他口令”，右侧小字“N 个未解出”；回车或点它进入验证作用域。没有未解出的口令就没有这一行；
  - 还没参与、去掉了领取作用域：第一行是“领取 标题”（限时开奖是“报名”），可以选回来；
  - 打开时高亮的就是这一行；退格去掉作用域后，它又回来。

- 指令框落在窗口高度约三分之一处：宽窗口上方留白 `clamp(3rem, 24cqh, 16rem)`，窄窗口 `clamp(2rem, 16cqh, 8rem)`。
- 最近输入：
  - 本地尝试历史的前 10 条，带状态点（绿 = 已匹配，灰 = 未匹配，琥珀 = 未确认）；
  - 点击只填入，不提交；

  - 注册表里标为常用、且当前身份可见的命令；

## 6 指令框细节

- **输入元素**：单行 textarea 加镜像层。
  - textarea 能原样保留粘贴进来的换行符，由镜像层把不可用字符标红（空白显示 `·`，换行显示 `↵`），不会悄悄删掉。
  - 含换行时，输入框最多长到 3 行。
  - 命令模式下，开头的 `/`（或 `、`、`／`）显示为朱红色。
- **占位文字**：宽窗口“输入口令、红包链接，或输入 / 使用命令”，窄窗口“口令、红包链接或 / 命令”。
- **协议标签**：空输入时只显示钥匙图标；输入后显示类型名（口令 / 红包 ID / 表情码 / 红包链接 / 帖子 / 命令），类型变化时宽度平滑过渡。
- **右侧**：有内容时出现“清空”和动作按钮。动作按钮文案：
  - 优化（当前项为一键优化时）
  - 领取（限时开奖为“报名”）/ 打开红包
  - 前往 / 登录（命令）
  - 验证（作用域为“验证其他口令”时）
  - 正在确认… / 再次确认（查找没收到结果）/ 重试原提交（领取、报名没收到结果，见 [05](05-hongbao.md) 第 10 节）/ 还需等待 N 秒
  - 换字的过渡见 [04](04-visual.md) 第 4 节；倒计时到整秒才更新数字，每秒都准时。
- **提示行**：
  - 口令不合规时显示规则说明和字数（如 `10 / 18`）。建议列表打开时，这一行移到列表顶部。
  - 提交结果：
    - “未匹配到红包。”（同时输入框里的文字红色闪烁两下，见下）
    - “请先登录。”（附“登录”）
    - “查找结果未确认，请再次确认。”
    - 帖子链接没有关联红包：“这个帖子里还没有红包。”
- **口令不对时闪红**：口令没有匹配到红包，或在作用域里提示“口令不正确。”时，输入框里的文字按“黑、红、黑、红、黑”闪烁两下（共 800ms），让人一眼看出这个口令不对。
  - 闪完恢复黑色，输入内容保留，可以直接修改；
  - 两次闪烁低于每秒 3 次；开启“减少动态效果”时只变红一次再恢复，不闪烁；
  - 帖子链接没有关联红包时不闪：那不代表输入错了。
- **未知结果**：输入锁定，按钮变为“再次确认”，用同一个请求重试；重试不受冷却限制。
- **建议列表**：起始页在命令模式、或口令可以一键优化时弹出；展开态始终显示。
  - 一键优化：口令不合规、且去掉不可用字符或全角转半角后结果不同时，第一项是“一键优化 → 优化后的口令”。Tab 或回车应用，只改输入、不提交；应用后不再合规的部分照常提示（例如字数不够）。不合规的口令不能查找，所以此时列表里只有这一项。
  - 命令：匹配到的命令（规则见 [03](03-commands-routes.md)）。
  - 空输入（仅展开态）：先是“这个红包”那一行（第 4 节，没有就不显示），再是最近输入，最多 10 条（生产保留 100 条、显示 10 条）；底部一行“最近输入只存在这个浏览器里 · Shift+Delete 删除选中的一条”（窄窗口只有前半句）和“清空”按钮（窗口内确认“清空最近输入？…不能恢复”，清空后回到输入框）。
  - 口令：作用域时显示“领取 红包标题”和“在全部红包中查找”，否则显示“查找口令”。
  - 红包标识：“打开 红包标题”。
  - 帖子：“查看帖子里的红包”。
  - 无法识别的链接（其他网站、写错的地址）：提示“无法识别这个链接。支持本站的红包链接和 LINUX DO 帖子链接。”，不当作口令标红。
- **手机上的搜索模式**（窗口窄于 640px，或满屏的横屏手机）：
  - 起始页的输入框一被点中就进入展开态，和其他页面点地址条一样：输入框移到顶部，压暗起始页，下面列出最近输入、命令或建议；已经输入的文字带过去；
  - 后退、Esc、点压暗层都会收起：输入框回到原位，文字留在框里，输入框失焦，键盘收起；
  - 建议列表的底边停在屏幕键盘上方（用 `visualViewport` 算出键盘挡住了多少）；红包页“开”和“验证其他口令”打开的展开态也一样；
  - 桌面不变。
- **键盘**：
  - 回车执行当前项；
  - Tab 补全当前命令，或应用一键优化；
  - Shift + 回车不换行、不提交；
  - Esc 在展开时收回，在起始页先清空、再失焦；
  - 退格在空输入时去掉作用域；
  - ↑ / ↓ 选择建议；
  - 输入法组词期间回车不提交（包括 Safari 在组词结束后同一时刻发出的回车）。
- **输入法组词期间**：输入框里是还没确认的拼音和分隔符。口令按组词开始前的内容判断，提示行、红色标记和一键优化都不随拼音闪动，组词结束后再更新。命令照常实时匹配（匹配时本来就忽略拼音分隔符）。
- **全局快捷键**：见 [03](03-commands-routes.md)。

## 7 历史记录与地址

- 展开的指令框、用户卡片、名单弹窗、说明弹窗各占一条历史记录（`state.omnibox` / `state.panel`；发红包的“更多设置”也是，见 [07](07-pages.md) 第 5 节）：系统返回关闭它们。任何面板打开时，舞台不可交互，⌘K 和 `/` 不响应。
- 关闭时：如果上一条就是打开它的那条记录，执行后退；否则（例如刷新后）原地去掉状态，不会退出网站。
- 在指令框或卡片打开时跳转到别处，用替换而不是新增记录，返回时不会重新弹出已关闭的指令框或卡片。
- 结果页里选择红包用替换：返回时不会重复出现已用过的选择。
- **口令不进地址、不进历史记录、不进持久存储**：
  - 多匹配结果的地址只含结果编号。结果存在服务端的兑换记录里，只限本人（[06](06-production.md) 第 6 节）；原型用 sessionStorage 代替，也只存红包 ID；
  - 口令只在内存中；
  - 自动领取的意图（单匹配，或在结果页选中一个，见 [07](07-pages.md) 第 11 节）也只在内存中。

## 8 启动加载

- 进度界面直接写在 `index.html` 里（内联样式与脚本），在任何 JS 下载前就显示。内容为：深红背景（光晕停在初始位置）、与窗口同尺寸的磨砂玻璃、品牌标志、金到红的渐变进度条、百分比。
- 加载界面同样是超椭圆：内联脚本里有一份 figma-squircle 路径算法的小移植（与库的输出误差小于 0.0001px），窗口、标志和进度条的形状与应用完全一致，切换时不跳变。
- 里程碑：
  1. HTML 解析，12%
  2. 主程序包执行完毕，70%
  3. 身份确认，88%
  4. 首帧提交，100%
- 两个里程碑之间按渐近曲线缓慢前进；到 100% 后淡出约 220ms，应用内容从下方 10px 淡入。
- 至少显示 450ms，避免一闪而过；“慢速”模式下拉长每一段，便于评审。
- 身份确认最多等 8 秒：请求失败也算确认（由顶栏提供重试），超时就先进入应用，顶栏显示正在确认身份。
- 失败处理：本站的脚本加载出错时，先等 1.5 秒自动重新加载一次——刚发布的那几秒，页面和程序包可能来自新旧两个版本（程序包取不到，或者被当成页面返回），过一会儿再取就配套了；一分钟内又出错，或 20 秒后主程序包仍没有执行，显示“加载失败”和“重新加载”（进入应用后清掉这次重试的记录）；主程序包已经执行的，20 秒时直接进入应用。别处的脚本（如 Cloudflare 自动加进页面的统计脚本，常被拦截插件拦掉）出错不算。淡出期间遮罩不拦截点击。
- 隐藏或被遮挡的标签页不绘制动画帧：每一帧等待都与一个短定时器竞争，保证加载照样完成，并跳过最短显示时间。
- 加载完成前应用根节点处于 `inert`，不可交互。

## 9 用户卡片

- **顶栏的头像位**：会话确认前是灰色的占位圆；游客是“登录”按钮（窄窗口只有图标）；已登录是头像；身份检查失败见下。点它打开用户卡片。
- **位置**：点头像弹出，锚定在头像下方、右对齐，宽 20rem；窄窗口两侧各留 8px。以右上角为原点缩放加淡入。
- **背景**：整个窗口压暗并高斯模糊（与展开的指令框同一个压暗层），窗口其余部分不可交互。
- **已登录**：
  - 第一行是头像、昵称、@用户名，整行可点，进入账号资料，右侧写 `/me`（不再有账号类型标签：青春版已取消，见 [06](06-production.md)）；
  - 命令列表，右侧以等宽字显示路径：红包记录 `/history`、LDC 商户配置 `/merchant`、付款记录 `/payments`、网站管理 `/admin`（仅管理员）；
  - 底部“退出登录”。
- **游客**：登录界面，只有“通过 LINUX DO 登录”。
- **登录没完成**（第三步补充）：LINUX DO 带着 `?authError=…` 回来时，先把这个参数从地址里去掉（刷新不会再提示），再自动打开用户卡片的登录界面，按钮上方一条提示说明原因，按钮改为“再试一次”。文案沿用生产，去掉青春版和升级相关的几种：
  - 取消（`access_denied`、`cancelled`）：灰色“登录已取消，可以重新尝试。”；
  - 服务不可用（`service_unavailable` 等）：琥珀“登录服务暂时不可用，请稍后再试。”；`auth_not_configured` 时按钮变成不可点的“登录暂时不可用”；
  - 会话失效（`invalid_state`）：琥珀“登录会话已失效，请重新登录。”；
  - 其他：红色“登录没有完成，请重新尝试。”
  - 实现注意：TanStack 的浏览器历史会把同一轮里的“替换 + 压入”合并成一次压入，去掉参数的替换要先生效，再压入用户卡片那条历史记录。
  - 已登录的人带着 `?authError` 回来（刷新资料没完成）：会话保留，替换到 `/me` 说明原因，见 [07](07-pages.md) 第 4 节。
- **身份检查失败**（会话接口出错，生产的做法）：页面按游客继续，不卡在启动加载上。顶栏头像的位置换成琥珀色“身份检查失败，重试”（手机只有图标），点了显示“正在确认身份…”；需要登录的页面显示“身份检查失败，请重新检查后继续。”和“重新检查”；打不开的红包链接也是这样（可能是只有发红包的人能看的草稿），标题仍是“未找到红包”；用户卡片里同样是“身份检查失败”和“重新检查”。
- **退出登录**：在卡片里退出后留在当前页，需要登录的页面随之换成登录提示（`/me` 里的退出见 [07](07-pages.md) 第 4 节）。也可能失败：卡片里提示“退出没有完成：网络或服务出了问题，你仍是登录状态。可以再试一次。”。
- **焦点**：打开时焦点进入卡片。Esc、点击压暗区域或系统返回关闭，退出动画结束后焦点回到头像（2c 修好了按 Esc 后焦点落在页面外的问题）；从卡片跳转到别处时，焦点进入新页面。名单弹窗和说明弹窗用同一套规则，焦点回到打开它的“领取名单”入口（红包记录里是那一行的“名单”）或“展开全文”。

## 11 响应式

窗口尺寸由视口决定：

| 视口 | 窗口 |
| --- | --- |
| ≥1024 宽且 ≥560 高 | 四周留 32px，最大 1200 × 940，超椭圆圆角 28 |
| 640–1023 宽 | 四周留 16px，超椭圆圆角 22 |
| <640 宽或 <560 高 | 满屏，无圆角，玻璃更不透明（92%），让开安全区（见下） |

**安全区**（只在满屏时；`index.html` 用了 `viewport-fit=cover`）：`--safe-top / right / bottom / left` 取 `env(safe-area-inset-*)`，浮在桌面上的窗口都是 0。

- 顶栏在刘海下方（`--bar-h` = 64px + 上方安全区），两侧也让开；
- 页面的滚动区让开两侧；展开的指令框落在刘海下方；
- 底部浮起的面板（名单、说明和页面里的弹窗）离两侧和底部至少 8px，并让开底部横条；用户卡片让开两侧；
- 发红包的吸底操作条（[07](07-pages.md) 第 5 节）也让开底部安全区。

窗口内部的布局只看窗口自身尺寸（容器查询 `@container/window`），不看视口：

- **宽布局**（窗口宽 ≥ 40rem，文中的“宽窗口”）：协议标签显示类型名；顶栏为三列等宽侧栏，保证地址条始终居中。“发红包”在窗口宽 ≥ 66rem 时才带文字：再窄，右侧三个按钮放不进侧栏，会压到地址条上，所以和手机一样只有图标。
- **窄布局**（小于 40rem，“窄窗口”）：只显示图标。
- **手机**（窄窗口，或满屏的横屏手机）：起始页的输入框点中后进入搜索模式（第 6 节）。

## 12 动效

| 动作 | 时长 |
| --- | --- |
| 指令框移动、外观与圆角过渡 | 340ms |
| 地址滚筒 | 约 420ms（弹簧，轻微回弹；淡入淡出 240ms） |
| 页面入场 | 260ms（延后 100ms） |
| 页面离场 | 140ms |
| 压暗层 | 220–240ms |
| 用户卡片 | 180ms（退出 120ms） |
| 名单弹窗 | 200ms（宽窗口缩放淡入，手机从下方升起；退出 120ms） |
| 标签宽度变化 | 200ms（真实宽度动画而不是缩放，超椭圆不变形） |
| 按钮换字 | 宽度 240ms；旧字淡出 120ms、新字淡入 200ms（带 1.5px 模糊）；数字滚动 280ms；底色 200ms |
| 口令不对的红色闪烁 | 800ms，两次（减少动态效果时 900ms，一次） |
| 顶栏材质（透明 ⇄ 毛玻璃、分隔线） | 200ms |
| 背景光晕 | 见 [04](04-visual.md) 第 3 节 |
| 红包页打开 | 约 1.9 秒，见 [05](05-hongbao.md) |

- 缓动统一为 `cubic-bezier(0.2, 0, 0, 1)`。
- 进入与离开的页面叠放在同一格，交叉淡入淡出，不跳动；离开中的页面不接收点击。
- 移动途中目标位置变化（例如窗口尺寸变化）时，以剩余时间改道，不跳帧。
- 系统设置开启“减少动态效果”时，所有移动直接到位，只保留必要的淡入。

## 13 焦点与可访问性

- **焦点去向**：
  - 关闭指令框（Esc、点击压暗区）后，焦点回到地址条；
  - 因跳转而离开时，焦点进入新页面，不唤起键盘；
  - 红包页的焦点见 [05](05-hongbao.md) 第 9、11 节；
  - 回到起始页时，只有用精确指针设备（鼠标、触控板）、窗口又不是手机尺寸时，才自动聚焦指令框：手机上聚焦就会进入搜索模式，要等点了才进。
- **语义**：
  - 指令框外层是 `<search>` 元素；
  - 建议列表为 `listbox` / `option`，焦点留在输入框，通过 `aria-activedescendant` 指向当前项；
  - 协议识别结果通过隐藏的 `aria-live` 播报。
- **结果的播报**：结果由一直在的 live region 念出；显示结果的那行字本身不是 live region，所以口令规则和字数（`n / 18`）不会每按一键念一次。
  - 指令框有一个：查找、领取、验证的结果，不论显示在提示行、列表顶部还是红包页的印章下面，都由它念；
  - 页面里同样做：发红包表单顶部一个，念保存结果；口令区一个，念验证结果（句号隔次出现，同样的结果再来一次也会再念）。
- **Tab 顺序**：先是“跳到主要内容”（平时不显示，聚焦时出现在窗口左上角，回车把焦点放到页面上），然后是顶栏的标志、发红包、红包记录、头像，再是地址条，最后是页面。顶栏盖在页面上面靠的是层级（z-index），不是文档顺序。
- **隐藏状态**：隐藏的地址条或输入层对辅助技术隐藏，并移出 Tab 顺序。
- **地址条读法**：红包地址以“红包「标题」”朗读，不逐个读出表情。
