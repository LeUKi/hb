# 07 其他页面（第三步初版）

状态：定稿。

代码：页面在 `apps/web/src/components/views/`，共用的页面框架在 `components/page/page.tsx`，表单控件在 `components/ui/field.tsx`。

## 1 共用规则

- **页面框架**（`Page`）：窗口玻璃上一列内容，最宽 44rem（发红包、编辑这样的表单也是）；只有红包广场的卡片网格和网站管理的“列表 + 详情”用 64rem。上边距 24px（宽窗口 40px），左右 16px（宽窗口 32px）。
- **标题行**（`PageHeader`）：22px 半粗标题，下面一行 14px 说明；主操作放在右侧，窄窗口换到下一行。
- **分组**（`PageSection`）：16px 半粗小标题，可带一句说明和右侧操作。
- **面板**（`Panel`）：列表、表单分组、数据格都放在面板里（材质见 [04](04-visual.md) 第 3 节）。
- **状态标签**（`StatusChip`）：浅底同色字，可带圆点；列表里高 24px，单独站着时（我的结果的发放状态）高 28px。颜色：进行中 / 已发放 / 已领取 / 已中奖为绿，处理中 / 开奖中为琥珀，异常待处理为红，草稿 / 已结束 / 未中奖为灰，“你发的”和“已报名”为金，“需登录”为朱红。
  - 红包的状态全站一个写法（`statusOf`：列表、结果页、📝 和网站管理共用）：草稿、进行中、开奖中、已归档，或结束原因（已领完、已过期、已开奖、无人报名、已提前结束）。
  - **开奖中算进行中**（用户决定，2026-10-15）：结果还没出来，所以红包广场、红包记录、网站管理的筛选都把它放在“进行中”。
- **表单控件**（`components/ui/field.tsx`）：
  - 输入框：高 44px；聚焦时内侧朱红描边（超椭圆会裁掉外描边，所以描边画在里面）；单位（LDC、份、人）写在框内右侧；
  - 开关：胶囊轨道（这个高度的超椭圆本来就是胶囊）和圆形旋钮，打开为朱红渐变；
  - 分段选择（`Segmented`，`components/ui/segmented.tsx`）：页签和筛选共用一个组件，浅灰底、选中项白色浮起，可带数量。换选项时白色超椭圆滑过去（02 第 12 节），数量变化时逐位滚动；网站管理的页签是它的链接版（`SegmentedNav`）。页面的第一层选择（页签，或页面上唯一的筛选）用常规大小；页签下面的筛选用小号（网站管理各列表的筛选也在页签下面）；
  - 选项卡片（`ChoiceCards`）：有含义的选择都用它（玩法、领取方式、分法、发放顺序、截止时间的定法、数量展示），每张一句说明，选中时朱红内描边；分段选择只用于页签、筛选、单位、原文 / 预览这类切换；
  - 只读的值（例如原订单 Client ID）：平的浅灰底，仍可聚焦（选中复制），聚焦时照样有朱红内描边；
  - 字段下方那一行（出错时是错误，否则是提示）是这个控件的描述（`aria-describedby`），聚焦时读屏会念出原因。
- **红包缩略**：列表里用小红包图标（`MiniEnvelope`，进行中朱红、已结束灰褐、草稿只有描边）；卡片里用小红包皮（`HongbaoCard`：红色封面、金边封口、小印章，下面是奖励、余量和状态）。
- **资料行**（`InfoList`）：面板里一行一项，左边标签、右边值，发丝线分隔；宽窗口标签固定 8.5rem 宽，窄窗口标签在值上方。行尾可以放小按钮（复制）。
- **提示条**（`Callout`）：一个图标、一句标题、一两句说明（颜色的含义见 [04](04-visual.md) 第 3 节）。
- **资料卡**（`PersonName`，生产的 user-identity 弹出卡）：红包皮上发红包的人、名单里每个人的名字、付款详情的收款人、我的结果里附言的署名都可以点，弹出一张小卡：头像、昵称、@用户名和“在 LINUX DO 查看”（新标签页打开论坛主页）。卡片画在窗口层上，弹窗和滚动列表不会把它裁掉。点别处、焦点移走或任何滚动都会收起；Esc 只在焦点在卡片（或名字）上时收起它；用 Esc 或滚动收起时焦点回到名字。整行本身就是按钮的地方（红包记录、广场卡片、管理列表）不放。
- **复制按钮**（`CopyButton`）：32px 的幽灵图标按钮，复制后图标变成绿色对勾并显示“已复制”1.4 秒；浏览器不让复制时显示“请手动复制”。图标交叉淡化，提示从 0 宽长出、再收回，旁边的文字跟着平滑让位。
- **会换字的按钮**：见 [04](04-visual.md) 第 4 节。
- **页面里的弹窗**（`WindowDialog`，外框见 [04](04-visual.md) 第 3 节）：盖住整个窗口，其余部分不可操作；但不占历史记录——它属于当前这一步操作，后退仍然离开页面。Esc 或点压暗层取消（保存中不能取消），关闭后焦点回到原来的按钮。从弹窗里再打开的弹窗叠在上面，有自己的压暗层，下面那个暂时不可操作；Esc 和点外面只关上面这一层。
  - **确认弹窗**都是一个版式（`ConfirmDialog`，`components/shell/confirm-dialog.tsx`）：标题、会发生什么、需要掂量的内容（数字表、提醒）、上一次没成功的原因（`role="alert"`），最后是按钮：返回的在前，动作在后。用在离开确认、删除草稿、提前结束、谨慎更换商户配置、清空最近输入。
- **标签上的说明**（`HoverNote`）：一句补充挂在小标签下面（玻璃小气泡），悬停、键盘聚焦或轻点时出现，同时是标签的 `aria-describedby`。
- **去别的页面的链接**（`ButtonLink`、`MoreLink`，`components/ui/button-link.tsx`）：“红包记录 ›”“付款记录 ›”“打开红包 ›”“去更新 ›”“去配置 ›”“管理 ›”“查看 ›”“操作记录 ›”都是同一个 32px 幽灵链接按钮，后面带 ›。都是真链接，按住修饰键点击在新标签打开。站外链接（论坛帖子、LINUX DO 主页）带 ↗ 图标，在新标签打开。
- **列表懒加载**（用户决定，2026-10-15）：列表一次 20 条，快滚到底时（离底还有 600px）自动加载下一批，不用按钮。
  - 加载时末尾一行“正在加载…”；失败时写“后续记录读取失败，可重试加载。”和“重试加载”（生产文案）；到底写“共 N 个 / 条 / 笔 / 人”（按这个列表数的东西）。一次就能放下的短列表没有这一行。
  - 加载了多少按历史记录记住：后退回来条数和滚动位置都还原；换筛选从 20 条重新开始；“刷新”保留已加载的条数。
  - 列表出现以后，轮询带来的新行、删掉的行在原处展开和收起；列表刚出现时已有的行不动。
  - 付款记录的几组（按红包）合成一条连续的流，一组被两批拆开时接着往下排；尝试统计把“每个口令领取了多少”放到列表上面，列表在页面最后。
  - 用在付款记录、尝试统计、网站管理的三个列表和名单弹窗；红包记录、红包广场、结果页和操作记录也一样。
- **返回时还是离开时的样子**：列表的页签和筛选写在地址里（红包记录 `?tab=joined&filter=draft`、广场和付款记录 `?filter=`、网站管理的 `?status=` 等，用替换写入，不多占一条历史记录），刷新也保留；每条历史记录记住页面滚到了哪里，后退回来停在原处（红包页和起始页除外：红包页的大小红包皮由滚动位置决定）。数据还在路上时，等内容够高再滚过去，最多等 4 秒，用户自己一滚就不再等。
- **页面数据的三种状态**（`components/page/page-state.tsx`，生产每个页面都从接口读数据）：
  - **加载中**：页面框架里的灰色骨架（标题两条、两个面板里各几行）；读屏只念“正在读取…”。数据到了以后内容淡入，不硬切。整页骨架只在页面第一次加载时出现。
  - **换页签、换筛选**（2026-10-18 起）：页面显示过以后，标题、页签和筛选一直在，只有结果区自己加载（`ResultLoad`）：同一种列表换筛选，旧结果变淡留着，新结果到了淡入；换成另一种列表或第一次读，结果区里是灰色的行（广场是灰色的卡片）；读取失败就在结果区里写“读取失败”和“重试”。名单弹窗第一批到之前也是灰色的行，不先说“还没有人领取”。
  - **读取失败**（第一次就没读到，没有内容可显示）：居中的云朵图标、“读取失败”“网络或服务暂时出了问题，稍后再试。”和主按钮“重试”。
  - **刷新失败**（后台刷新没成功，旧内容还在）：标题下方一条琥珀色提示“刷新失败，当前内容已保留。下面可能不是最新的。”，右边“重试”。沿用生产的说法。
  - 两种“重试”成功后按钮都不在了：焦点移到页面标题，从头读起；刷新成功时读屏念“已刷新”。读取失败后重试，加载期间焦点停在“正在读取…”上；刷新失败后重试，按钮在原处变成“正在刷新…”。焦点已经被移到别处（比如打开了指令框）时不抢回来。
  - **刷新**（生产五种刷新按钮合成一个）：红包记录、红包广场、付款记录、商户配置和网站管理的四个列表，标题右侧一个“刷新”（手机只有图标）；按下后变成“正在刷新…”，完成后读屏念“已刷新”，焦点留在按钮上。网站管理概览的刷新也一样，另外每 30 秒自动刷新。
  - 红包页也一样：加载中是红包皮的红色加奶油色的骨架（发红包的人、标题、标签、三格数据的位置），和真正的红包皮一样大（参与过的是小红包皮），下面一条灰色的提示位置。数据到了，红色不闪：高度从骨架接着变到实际高度，只有红包皮上的内容和下面的正文淡入。读取失败同上；刷新失败的提示在正文最上面（口令区上方）。两个结果页（`/🔑/`、`/💬/`）也有这三种状态。
- **空状态**：没有内容时是一个居中的面板，一句标题、一句接下来怎么做，必要时带一个去做下一步的主按钮：红包记录“还没有发过红包”带“发红包”，“还没有参与过红包”带“逛红包广场”，付款记录“还没有付款”带“发红包”；商户页直接是“配置商户”的表单。筛选后没有内容时，第二句一律是“换个筛选看看。”。
- **提示页**（未找到、没有权限、结果已失效）：居中的图标、标题和一句话，下面是“回到起始页”；需要时前面多一个按钮（“登录”“重新检查”“回到红包”）。例如别人打开 📝 📊 🧾：“只有发这个红包的人能打开这一页。”加“回到红包”；游客打开：“登录后可以管理你发的红包。”加“登录”。
- **离开确认**（`LeaveGuard`）：发红包 / 编辑、商户配置（含第一次配置商户）、更新原订单密钥、网站设置有没保存的修改时，换页之前先问“还有没保存的修改”（继续编辑 / 放弃修改并离开），用窗口内的确认弹窗。只有换页才问：打开指令框、用户卡片或弹窗不算。关闭或刷新标签页时由浏览器自己提示。
  - **保存中离开**不问：请求已经发出，保存照常完成（和生产一样），只是不再跳到保存后的页面、不再显示“已保存”。
- **提交没成功**（沿用生产的处理）：
  - 发红包 / 编辑：没收到保存结果（网络断了或服务出错）时提示“尚未确认保存结果，请重试原提交，避免重复提交。”，按下的那个按钮变成“重试原提交”，表单锁住、另一个按钮暂停（和生产一样，重试发的就是原来那次），不会建出第二个红包；保存并开放时草稿存好了、开放失败，进入它的 📝 页，提示“开放失败：草稿已保存，开放没有完成，可以再试一次。”；编辑时版本冲突，保留输入，提示刚在别处改过，再保存一次。
  - 删除草稿、提前结束：在确认弹窗里说明没有完成，按钮变成“再试一次”；商户配置、配置商户、更新原订单密钥：在按钮上方说明没有完成，输入保留。
  - 网站设置的版本冲突：换成另一位管理员刚存的版本（写明第几版和数值），改过的那一项保留、没改的跟着新版本，确认后再保存。
  - 太频繁（429）一律是“尝试过于频繁，请稍后重试。”
  - 领取和报名的这几种情况在红包页，见 [05](05-hongbao.md) 第 10 节。
- **表单的错误怎么说**：
  - 发红包 / 编辑：按“下一步”或保存时才检查那一步（保存查全部）；有问题时读屏念一次“还有 N 处要改。第一处：……”，之后边改边消失的错误不再打断；错误清单里每一条都能跳到对应的字段（在更多设置里的就打开面板）。更多设置里的字段边改边查（第 5 节）。
  - 短表单（商户配置、配置商户、网站设置）：边输入边检查，这些在框下写明并礼貌地念出来（`aria-live="polite"`）：Client ID 有不能用的字符、改了 Client ID 没填密钥、商户名称被清空、间隔不是 1–3600 的整数（留空也算）；其余没填的项不提示，只是保存按钮变灰。
- **焦点不被挡住**：窄窗口发红包的吸底操作条在时，用 Tab 走到的字段停在操作条上方（内容区的 scroll-padding 加上整个字段的“就近显示”），不会藏在条下面（WCAG 2.4.11）。
- **焦点跟着按钮走**：
  - 正在处理或暂时没事可做的按钮仍可聚焦（`aria-disabled`，不用 `disabled`）：商户配置、网站设置、原订单密钥的保存，谨慎更换里的“确认更换”，刷新失败提示里的“重试”，删除草稿；
  - 按完就消失的按钮，把焦点交给下一个合理的地方：撤销修改 → 保存按钮；口令旁的“优化” → 这个口令的输入框；删除口令 → 上面一个口令（删的是第一个就是新的第一个）；“重试加载”加载时还在（变成“正在加载…”），读完后焦点落到列表末尾那一行；配置商户成功 → 新商户的名称。
- **不只靠颜色**：网站管理概览里不为零的数字带图标（红的三角、琥珀的时钟）和读屏文字（“需要处理”“需要留意”）；付款“经过”的当前一步标 `aria-current`。
- **播报**：结果怎么念见 [02](02-shell.md) 第 13 节。

## 2 红包广场 `/square`

- 发红包时选了“加入红包广场”的红包，按开放时间从新到旧排列；游客也能看。
- 标题行右侧是筛选：进行中 / 已结束 / 全部，各带数量。
- 卡片网格（每张至少 15rem 宽，自动排列）：
  - 上半是小红包皮：发红包的人、标题（最多两行），封口上一枚小印章（开 / 报，结束后灰色“完”）；
  - 下半写奖励规则、余量（和红包皮上的数量格同一个说法）、截止或开奖时间，再是状态和参与方式两个标签；登录后，自己发的标“你发的”（金），参与过的标结果（已领取、已中奖绿，已报名金，开奖中琥珀，未中奖灰）；
  - 点卡片打开红包。
- 草稿和没选“加入红包广场”的红包不出现；结束 72 小时后（已归档）也不再列出，和生产一致。

## 3 红包记录 `/history`

- 两个页签：**我发的**、**我参与的**，各带数量。标题下一行是“已发 3 个，发出 11.00 LDC · 参与过 3 个，领到 3.54 LDC”（金额的算法同第 4 节）。
- **我发的**：
  - 页签下面单独一行筛选：全部 / 进行中 / 草稿 / 已结束（已结束含已归档）。只有“我发的”有，换页签时这一行在原处展开和收起（2026-10-18 起，任何宽度都是单独一行）。
  - 每行：小红包图标、标题和状态标签（草稿 / 进行中 / 开奖中 / 已领完 / 已过期 / 已开奖 / 无人报名 / 已提前结束 / 已归档）、奖励规则和余量、开放与截止时间（已结束的只写开放时间）；草稿写“还没开放，只有你能看到”。
  - 行尾是这个红包的 📝 📊 🧾 入口（第 6 节）。
  - 点行：打开红包；草稿直接进 📝 编辑。
- **我参与的**：
  - 每行：发红包的人和参与方式（“用口令 xxx 领取”，进行中的红包只写“用口令领取”，见 [05](05-hongbao.md) 第 9 节；“直接报名”）、参与时间；右侧是到账金额（绿色 +0.66 LDC）或结果标签（已报名 / 开奖中 / 未中奖），下面是发放状态（待发放 / 发送中 / 核对中 / 等待恢复 / 已发放 / 异常待处理）。
  - 点行打开红包，“我的结果”在红包页上，不另开页（[03](03-commands-routes.md) 第 7 节）。
- 都按时间从新到旧。空的时候说明怎么开始：我发的“发一个试试：填好奖励和口令，开放后把链接发到帖子里。”和“发红包”按钮；我参与的“在起始页输入口令，或打开别人分享的红包链接；红包广场里也有公开的红包。”和“逛红包广场”按钮。

## 4 账号资料 `/me`

## 5 发红包 `/new` 与编辑 `/🧧/<码>/📝`

用户决定（2026-10-15）：一页长表单心智压力太大，改成线性的四步，一步一问；低优先级的项不删，收进二级的“更多设置”；不要总览页，也不要红包预览卡（红包有好几种画法，预览对不上别处）；不要“飞来飞去”的动画。

**样子**（一列）

- 标题“发红包”，下面是进度条：和启动界面同款，右边“2 / 4”（材质见 [04](04-visual.md) 第 3 节）。
- 四步叠成一摞卡：答过的收成一条（高 56px），只露编号、步骤名、答案和“改 ›”，后一张压住前一张底下 8px；当前一步完整展开在最前面。点前面的一条回到那一步。

**四步**

1. **玩法**：两张大卡，拼手气（默认，“总额随机分成几份”）和限时开奖（“先报名，到时抽奖”）；一行“更多玩法”展开固定均分和自定义金额。点了卡片稍停 120ms 自动进入下一步，“下一步”按钮也在。
2. **发多少**：
   - 最上面是“从哪发”（[🐟额设计](../balance-design.md) 第 14 节，2026-10-20 起取代表单顶上的商户提醒）：
     - 🐟额红包开着、而且这个人有🐟额入口时，两张卡：LDC 商户（“每有人领取，从你的集市应用直接付给他”；没配置时变灰写“还没有配置商户”，凭证未通过时写“商户凭证未通过，开放前要更新”）/ 🐟额（“可用 x 🐟，领到的进领取人的🐟额”；没有可用时变灰写“🐟额里没有可用”）。用不了的那张下面给入口“去配置商户 ›”“去更新密钥 ›”“去🐟额 ›”。新红包没有商户、有🐟额时默认选🐟额。
     - 否则没有卡片，只在商户有问题时一行琥珀字“还没有配置 LDC 商户，配置好才能保存和开放。”或“商户凭证未通过，开放前要更新密钥。”和入口。
     - 选🐟额后不显示付款商户和分发费、每日上限两句，规则那行换成“领到的直接存进领取人的🐟额。”，总额超过可用时一行琥珀字“可用只有 x 🐟，不够发这个红包。”（草稿照样能存）。收起时答案后面加“· 从🐟额发”。开放后不能改。
   - 拼手气是总额和份数，限时开奖是奖池和获奖名额，固定均分是每份金额和份数，自定义金额是一行一份（等宽字，右上角数出份数）。金额框里写 LDC，份数写“份”，名额写“人”。
   - 下面一行合计（“总额 10.00 LDC · 10 份 · 每份 1.00 LDC”），一行规则：最多 1,000 份、每份至少 0.01、最多两位小数；填的是每份发出的金额，领取的人到账时 Credit 按你的 Credit 等级扣分发费（4%–15%）；你不能领自己的红包。总额超过 800 LDC 时再加一行琥珀色的提示：Credit 每天最多能发 800–2000 LDC（按你的 Credit 等级），超出的部分可能顺延到第二天发放。
   - 一行灰字“分法：微信同款 · 改”（自定义金额是发放顺序，限时开奖是奖金怎么分），点了打开更多设置；固定均分没有这一行。
3. **怎么领**：
   - 两张卡：口令（知道口令的人才能领，口令可以藏在帖子里）、无需口令（打开红包页就能领，限时开奖是报名）。
   - 口令列表：每行一个输入框，框内右侧 n / 32；口令长了框跟着变高、换行显示全文（最多 3 行，再多在框里滚动），回车仍是下一步，不会插入换行；整句粘贴进来带着标点也收得下（最多 64 个字符），由“优化”去掉；有全角字母数字或不能用的字符时行尾出现“优化”（和指令框的一键优化同名；这时的错误写“有 N 个不能用的字符，点「优化」去掉”）；多于一行时能删；下面“再加一个”（最多 5 个）和规则：6–32 个字：汉字、英文字母或数字，区分大小写；几个口令共用同一个红包，每人只能领一次。
   - 一行灰字“开放后 24 小时截止 · 改”（限时开奖“开放后 180 秒内开奖 · 报名不限”），点了打开更多设置的时间组。
4. **起个标题**：
   - 标题选填，灰字占位就是默认标题（见下），下面一行“选填，不填就用灰字的标题。”和 n / 100。卡片标题已经是“起个标题”，输入框上不再写“标题”（只给读屏）。
   - 一行“加一段红包说明”，点了就地展开说明编辑（写在红包皮上，所有人可见）。
   - 一行“更多设置”，下面一行写现状（“附言未填 · 不关联帖子 · 不加入广场 · 精确数量”：广场开放后不能撤回，所以写明；开了人机验证时末尾加“领取需人机验证”）。
   - 按钮“存草稿”“保存并开放”只在这一步：生产的草稿也要整份有效。下面一句：开放后奖励、参与方式、口令和时间都不能再改。

**默认标题**：不填就用，提交时补上（生产接口仍要求 1–100 字）；份数无效时去掉后半截。不用“某某的红包”：红包皮上标题上面已经写着。

| 玩法 | 默认标题 |
| --- | --- |
| 拼手气 | 拼手气红包 · N 份 |
| 限时开奖 | 限时开奖 · N 个名额 |
| 固定均分 | 均分红包 · N 份 |
| 自定义金额 | 红包 · N 份 |

**更多设置**（二级面板）

- 和页面里的弹窗同一外框（第 1 节；宽窗口最宽 32rem），但占一条历史记录：后退、Esc、点压暗层都能关，关上后焦点回到打开它的那一行。
- 一项设置只写一次名字，有含义的选择一律是卡片（同第 1 节的选项卡片），设置之间用发丝线隔开。不适用的不显示：
  - **分法**（限时开奖是**奖金怎么分**）：两张卡，“微信同款”（小字：二倍均值，每份在 0.01 和剩下金额平均值的两倍之间随机，金额差距较大）和“支付宝同款”（小字：均值上下 50%，每份在平均值上下 50% 之间随机，金额比较接近）；选支付宝同款时，下面按填的金额写每份的范围（二倍均值每份从剩下的金额里抽，没有固定范围；只有一份时都写“就是全部 x LDC”）。限时开奖另有“人数不足时发完奖池”开关。
  - **发放顺序**（自定义金额）：按顺序（第 1 个领的拿第 1 行）/ 随机（每次领取随机抽走一行）。
  - **截止时间**（限时开奖是**最晚开奖时间**）：两张卡“开放后多久截止 / 指定截止时间”，下面是对应的输入：数字加单位（分钟 / 小时 / 天；限时开奖多一个“秒”，默认 180 秒），或系统的日期时间选择（按这台设备的时区）。草稿预览的时间格写设定的时长，限时开奖也是（“开放后 180 秒”）。限时开奖另有**报名上限**（选填，报满立即开奖）。
  - **统计口令尝试**（开关）：记下大家提交过的口令，在 📊 里按口令汇总；开启后只能在红包页输入口令，起始页的指令框查不到它。
  - **领取前人机验证**（开关，默认关）：领取和报名前先过 Cloudflare 人机验证（规则见[业务规格](../business-spec-v1.md)“领取前人机验证”）。说明里写明它挡什么、代价是什么：中国大陆网络、广告拦截插件或部分隐私浏览器可能加载不出验证，这些人会领不了。不分组，开放后也在。
  - **领取后附言**、**结束说明**：各占一行（第一句或“未填写”，“编辑 ›”），点了打开一个完整的编辑弹窗，叠在更多设置上面：Esc、点外面、“完成”都只关它，回到更多设置，原来滚到的位置不变，焦点回到那一行。说明类的文字都支持 Markdown（链接、加粗、列表，不支持图片和 HTML），各自有“原文 / 预览”切换，预览按生产 SafeMarkdown 的规则渲染。
  - **关联帖子**：按生产的 `normalizeTopicLink` 识别，离开输入框时整理成 `https://linux.do/t/<帖子>/<楼>`。
  - **加入红包广场**（开关）：开放时开着的就不能再撤回。
  - **数量展示**：精确（显示总数、已领和剩余）/ 模糊（只显示“充足 / 有限 / 少量”）；下面一句“领取名单一律公开：昵称、领取时间和金额”。
  - **付款商户**：当前商户和凭证状态，“管理 ›”；不用预先付款，每次有人领取本站从这个集市应用直接付给领取人。
- 从一行灰字打开时，面板滚到对应的设置，它的名字短暂变成朱红，焦点在那里（不弹键盘）。
- 面板里的字段边改边查，错误礼貌地念出来；有问题时，步骤上通往它的那行灰字变红并写出第一处问题；在第 3 步按下一步会被拦住，焦点落到那行。

**走动**

- “下一步”只检查这一步：错误写在字段下，焦点到第一处，读屏念一次“这一步还有 N 处要改。第一处：……”。回车等于下一步（输入法组字时不算）；最后一步没有下一步，回车不提交，开放要按按钮。
- 每一步是一条历史记录：后退、前进就是上一步、下一步，不会问“还有没保存的修改”（只在离开页面时问）。点前面的一条回到那一步，后面的卡收起，答案保留，再按下一步时已经填好。换了玩法，后面的步骤要重新确认一遍（内容保留）。
- 每次进入 `/new` 都从第 1 步开始：刷新或从新红包页后退回来时，留在历史里的步骤一次退回第 1 步。
- 动效：没有东西飞，也不缩放。卡片的高度从当前值动到新内容的高度（340ms），下面的卡跟着移动；卡里的内容和条上的答案原地交叉淡入淡出；新的一步淡入并压上前一张。减少动态效果时只保留淡入淡出。
- 换到新的一步时，焦点落在它的标题上；标题不在屏幕里时滚过去，前一条也留在视野里。

**按钮**

- 进度写在按下的那个按钮上：保存并开放依次显示“正在保存…”“正在检查商户凭证…”“正在开放…”，成功后打开新红包的页面；存草稿显示“正在保存…”，新红包保存后进入它的 📝 页，显示“草稿已保存。开放前只有你能看到它。”
- 没有商户或凭证未通过时不开放，提示可以先存草稿。凭证还在检查时会等它查完；一直查不完（生产等一分钟），先存成草稿并提示“凭证检查仍未完成。草稿已保存，可以稍后继续开放。”
- 窄于 960px 的窗口：按钮放进**吸底操作条**（玻璃浮层，贴窗口底部 12px；安全区见 [02](02-shell.md) 第 11 节）。左边是合计（还没填金额时只写玩法），点过保存还有问题时换成红色“N 处要改 ›”，保存后的提示也只显示在这里（宽窗口显示在按钮上方）；右边是“下一步”，或“存草稿”“保存并开放”。Tab 走到的字段停在操作条上方。

**编辑页 `/🧧/<码>/📝`**

- 标题行：小字“编辑红包”、红包标题、右侧状态标签和“预览红包页 / 查看红包页”。现在能改什么写在状态标签上：悬停、键盘聚焦或轻点标签时，下面浮出一句（草稿“开放前只有你能看到，什么都能改。”；已开放“开放后还能改标题、关联帖子、加入红包广场、说明、数量展示和领取前人机验证。”），读屏把它当作标签的说明念出来。
- 四步都收成条，就是“藏起来的总览”；点一条就地展开，其他收起（手风琴，不占历史记录）。下面一行“更多设置”，再下面是操作。
- **开放后能改的**：标题、关联帖子、加入红包广场（只能从关到开）、三段说明、数量展示、领取前人机验证。**不能改的**：玩法、金额、份数、分法、顺序、付款商户、参与方式、口令、尝试统计、截止 / 开奖时间。前三步的条带锁，展开能看不能改（平的浅灰底、带锁的“开放后不能修改”）；灰字行变成纯文字（实际截止时间、分法）；更多设置里只剩人机验证、文字和公开，加只读的“开放时用的商户”（可能已是历史商户，“查看 ›”）。操作只有“保存修改”（没改动时不可按）。
- **草稿**什么都能改：存草稿、保存并开放、删除草稿（确认弹窗：“删除后不能恢复”；删除后替换到红包记录）。
- 保存时有问题：对应的条写“N 处要改”，展开第一处所在的一步并跳到字段。
- **提前结束**：只在进行中、还没有人领取或报名时出现（生产规则），单独一组：说明 + 红色“提前结束”按钮 + 确认弹窗。结束后这一组变成绿色提示“红包已提前结束”（焦点移到这里），状态是“已提前结束”。放在编辑页：它是改变红包本身的操作；红包页工具条上的“编辑”就是入口。

## 6 红包页的作者视角

- 发红包的人打开自己的红包：
  - 印章变淡、不能点，下面写“这是你发的红包，你不能领取”（限时开奖是“报名”）；指令框里用口令领也会被拒绝：“这是你发的红包，你不能领取。”
  - 口令区列出全部口令，标注“你设置的”（进行中先隐藏，见 [05](05-hongbao.md) 第 9 节）。
  - 提示下面一条“你发的红包”工具条，放这个红包的 📝 📊 🧾 入口。
  - **这组入口**在红包页和红包记录的每一行是同一个（`SenderLinks`，`components/hongbao/sender-links.tsx`）：编辑 / 尝试统计 / 付款记录；尝试统计只在开了统计的红包上有，草稿只有编辑（红包页上是主按钮“继续编辑”）。三个页面入口都是真链接。
  - **红包记录的每一行**在付款记录前多一个“名单”：点了在红包记录页上直接打开这个红包的名单弹窗，不跳转（红包页上名单入口在红包皮上，不重复）；草稿没有。宽窗口都是 36px 的图标按钮，读作“编辑红包「标题」”“名单「标题」”等；窄窗口是 32px 的带字按钮，排在红包下面，放不下时折行。
  - **图标全站统一**：编辑是笔，尝试统计是柱状图，名单是人像，付款记录是收据（命令里账号的付款记录也用收据，原来是银行卡）。
  - **名单弹窗里多一行**：作者打开自己红包的名单，每人名字下面多一行小字——用的口令（口令红包，进行中先隐藏）和付款状态（绿 / 琥珀 / 红点加状态名）；点付款状态直接进那一笔的付款详情（替换掉弹窗那条历史记录，后退回到红包页）。弹窗顶部注明“你发的红包：每行多一行口令和付款状态，只有你能看到”。
- **草稿预览**：只有作者能打开（别人打开是“未找到红包”，标签页标题和地址条也不显示草稿的标题）；印章是“预”，提示“草稿预览，开放后才能领取”；时间格写设定（“开放后 7 天”，下面一行“从开放时算起”），不倒计时，草稿也不会因为时间到了而结束；没有“分享”按钮；工具条上方一条琥珀色提示“只有你能看到这一页。开放后大家才能领取，链接也才能分享”。
- 草稿不会被口令、帖子链接或红包广场找到；开了尝试统计的红包也不能在起始页用口令找到（生产规则）。

## 7 尝试统计 `/🧧/<码>/📊`

- 只给开了“统计口令尝试”的口令红包；其他红包打开这一页说明原因（草稿：“红包开放之后才有人提交口令”；没开：“统计要在发红包时开启，开放后不能改”）。
- 顶部四个数：提交次数、提交的人、成功领取（限时开奖是报名）、猜中的比例（按次数算）。
- **提交的内容**：按次数从多到少，每行是提交的原文（等宽字）、“是口令”绿色标签、“7 次 · 5 人”，下面一条按次数比例的横条（猜中的是绿色，其余灰色），右侧“领取 3 人”或“未命中 7 次”。一次 20 条。
- **每个口令领取了多少**：每个口令一行，右边份数（限时开奖是人数）。
- 只有汇总，不显示谁提交了什么（生产规则：提交内容加密保存，只给作者看汇总）。

## 8 付款记录 `/payments`、`/payments/<编号>`、`/🧧/<码>/🧾`

**付款记录**列出你的红包付给领取人的每一笔；每一笔有自己的详情页。

- **`/payments`**：
  - 顶部三个数：已发放（金额和笔数）、未完成（金额和笔数，下面“系统会继续处理”；有暂停的写“N 笔，其中 M 笔已暂停”）、异常待处理（发送已暂停的笔数）。
  - 有发送暂停的付款时，下面一条红色提示：“这类付款不会自动重发，也不会重复付款。点开可以看到原因和经过。”
  - 筛选：全部 / 未完成 / 已发放。
  - 按红包分组，最近有付款的红包在前：组头是小红包图标、标题、余量和“已发放 x LDC”、右侧“打开红包 ›”；下面是这个红包的付款，一行一笔：头像、昵称 @用户名、领取时间（未完成的写原因）、金额、状态标签。
- **`/🧧/<码>/🧾`**：同一个列表，只看这个红包，不分组；标题上方是红包标题。
- **自动刷新**（两个列表都是）：还有付款在路上（未完成、又不是异常待处理）时每 15 秒刷新一次，没有就每 60 秒一次，新的领取最多晚一分钟出现；页面在后台时不刷新。理由见 [06](06-production.md) 第 12 节。
- **`/payments/<编号>` 付款详情**：
  - 标题“付给 某某”，下面是红包标题和领取时间。
  - 头部面板：收款人（头像、昵称、@用户名）、大字金额、状态标签，下面一条按状态的提示：
    - 已发放：绿色，“几点几分查单确认到账”；
    - 核对中：琥珀，“付款结果尚未明确，正在核对原订单。查清之前不会重新发送，不会重复付款；下次核对约在 …”；
    - 等待恢复：琥珀，原因（如“商户资金不足，等待补足后恢复。”）+“条件满足后自动继续，下次尝试约在 …。不需要在这里操作。”；原因是当前商户的凭证失效时，改为“到 LDC 商户配置更新密钥，检查通过后自动继续”和“去更新 ›”（管理员看到的是“要等发红包的人更新商户密钥”）；
    - 异常待处理：红色，原因 + “这笔付款不会自动重发，也不会重复付款”。
  - **经过**：竖向时间线，每一步一个圆点（完成绿、当前琥珀带光圈、出错琥珀或红），标题、精确到秒的时间、一句说明。例如：领取成功，创建付款 → 发给 LDC（LDC 已建单）→ 已发放（查单确认到账）。
  - **订单**（资料行）：红包（可点）、来源（领取 / 中奖）、本站业务号（可复制）、上游交易号（可复制，没有时“尚未收到”）、创建时间、确认发放（没有时“尚未确认”）、付款商户（名称和当时的 Client ID）。上方一句“询问这笔付款时，提供本站业务号即可”。
  - **处理记录**：本站每次向 LDC 发出的请求和查单：时间、操作（分发请求 / 订单查询）、结果（已收到有效响应 / 请求未通过 / 结果尚未明确）、说明。
- **没有“重试”按钮**：重试和查单都是系统自己做的，而且不会重复付款（生产规则）。
- **更新原订单密钥**：唯一需要作者动手的情况——付款没确认、订单用的是商户更换前的 Client ID、而那个旧应用的密钥被拒（生产的 `canRepairCredentials`）。
  - 付款详情头部的琥珀提示写明原因：“这笔付款用的是更换前的集市应用，它的密钥失效了。在下面‘更新原订单密钥’填写它现在的密钥后继续。”
  - 下面单独一组“更新原订单密钥”（只用于这笔付款原来的应用，不会改动当前商户）：原订单 Client ID（只读）、原订单商户密钥（密码框）、“保存原订单密钥”。保存后这一组消失，状态变成核对中，经过里多两步“更新原订单密钥”“核对原订单”；焦点移到头部的新状态上，读屏从那里念起。
  - 管理员在 `/admin/payments` 看到同一笔付款时，提示改成“要等发红包的人在付款详情里更新原订单密钥后继续”（管理员不能代填），付款商户一行写原订单的 Client ID 并注明“更换前的应用”。
  - 订单资料里的付款商户显示订单用的 Client ID，下面注明“订单用的是更换前的 Client ID；商户现在是 …”。
  - `/payments` 上有这种付款时，顶部一条琥珀提示“有 N 笔付款等你更新原订单密钥”和“去更新 ›”。
- 只有红包的作者能看自己的付款；管理员在 `/admin/payments` 看全部。

## 9 LDC 商户配置 `/merchant`、`/merchant/<编号>`

- 标题下一句：“LDC 红包由你的集市应用直接付给领取人，不经过本站。”
- **当前商户**面板：
  - 金色钥匙图标、名称、“当前商户”标签；Client ID（等宽字，可复制）；凭证状态标签（凭证检查通过 / 正在检查凭证 / 凭证未通过 / 凭证未检查）和旁边一句说明（检查通过时：“几点几分 检查通过；开放新红包时会自动再查一次”——生产要求最近 10 分钟内检查通过才能开放，开放时自动检查；历史商户只写检查通过的时间）。
  - 凭证未通过：红色提示条，原因（例如“凭证认证未通过，请核对 Client ID 和密钥”）+“新红包暂时不能开放；已开放红包的付款会等新凭证通过后继续”。
  - 付款暂停：琥珀提示条，标题写明原因（如“付款已暂停：商户资金不足”），正文“在 LDC 补足资金后自动继续，不需要在这里操作。领取不受影响。”每日额度用完时标题是“付款已暂停：今日 Credit 发放额度已用完”，正文写什么时候继续、几笔在排队（“明天 0 点后自动继续，2 笔在排队，不需要在这里操作。领取不受影响。”）；领取人的结果卡写“发红包的人今天在 Credit 的发放额度用完了，明天 0 点后自动继续发放。”
  - 三个数：用它付款的红包（进行中几个）、未完成的付款（笔数和金额）、已发放；右下“付款记录 ›”。
- **配置**：商户名称、Client ID（提示“在 LDC 的集市应用里查看。改 Client ID 时要同时填写它的密钥”）、商户密钥（密码框，“留空保留现有密钥”，“保存后自动检查；密钥不会显示出来”）。改了 Client ID 没填密钥时，密钥框下红字提示。保存配置（没有改动时不可点）、撤销修改；保存后“已保存”，凭证状态变成“正在检查”，再变成结果。
- **怎么填**：“配置商户”和“配置”两组标题右侧各一个“怎么填”（问号图标），打开窗口内的弹窗“在 LDC 创建集市应用”，分两步，各配一张 LDC 的截图：
  - 第 1 步创建集市应用（LDC 的叫法，页面上都这么叫）：先是“打开 credit.linux.do/merchant ↗”按钮（新标签页打开 LDC 的集市应用页），点右上角的“创建应用”；应用名称随意填写；应用主页 URL 和通知 URL 都填建议值 `http://localhost:3000/`（旁边可复制，并说明本站不用这两个地址），其余几项留空；
  - 第 2 步复制 API 配置：Client ID 填到“Client ID”，Client Secret 填到“商户密钥”。

  截图按原始大小显示、不放大，高出窗口时在弹窗里滚动；截图里的 Client ID 已遮住，LDC 的订单列表已裁掉。底部“知道了”，关闭后焦点回到“怎么填”。
- **谨慎更换商户配置**（确认弹窗）：换 Client ID 或密钥、而这个商户还有进行中的红包、未完成的开奖，或待发放 / 发送中 / 核对中的付款时出现（等待恢复、异常待处理不算）。一格数字：进行中的红包、未完成的开奖、待发放、发送中、核对中；一条琥珀提示说明影响（能安全续付的用新配置继续；已建单或结果未知的继续核对原订单，期间可能暂停这个商户的新发送）；一句“原付款的业务号、收款人、金额和记录都保留。确认更换不会绕过付款保护”。按钮：返回修改 / 确认更换。
- **历史商户**：以前用过的商户（每个账号只有一个当前商户），一行一个：名称、Client ID、“几个红包用它付款”，点进 `/merchant/<编号>`。历史商户的页面和当前商户一样，多一条说明：“历史商户不能用来开放新红包。已开放的红包继续用它付款；如果它的密钥变了，可以在这里更新。”
- **还没有商户**：只有“配置商户”一组（名称默认“默认商户”、Client ID、商户密钥，三项必填；有历史商户时下面照样列出）。保存后换成当前商户面板，凭证状态从“正在检查”变成结果；之后开放的红包都记在这个商户名下（三个数和“谨慎更换”的影响跟着变）。保存中离开不问，配置照常完成。
- **规则**沿用生产（`createMerchantSchema`）：名称 1–100 个字；Client ID 最多 200 个字符，只能有字母、数字、下划线和短横线，填错时框下红字提示。检查结果记在商户上，商户页和发红包页看到的是同一个。

## 10 网站管理 `/admin`

红包、用户、付款三页**只读**：没有任何修改操作，页面上也写明“只能查看”。能改的只有网站设置和🐟额（2026-10-19 起，[🐟额设计](../balance-design.md) 第 7 节）：🐟额设置和平台应用、转入的查单和确认到账、给某个人调整🐟额。

- **框架**：标题“网站管理”，下面一排页签（和分段选择同一画法，窄窗口可以横向滑动）：概览 `/admin`、红包 `/admin/activities`、用户 `/admin/users`、付款 `/admin/payments`、🐟额 `/admin/balance`、网站设置 `/admin/settings`、操作记录 `/admin/audit`。只有管理员能进（别人看到什么见 [03](03-commands-routes.md) 第 2 节）。子页的标签页标题写“网站管理 · 付款”这样，和自己的付款记录分开。
  - 标题、说明、“刷新”和页签在各页之间常驻（2026-10-18 起，`AdminArea`），切页签时高亮滑过去，只有下面的内容原地替换，各页在自己的位置加载；每页记住自己的滚动位置。
- **列表 + 详情**（红包、用户、付款三页）：窗口宽 960px 以上左边列表、右边吸顶的详情栏（22rem，比窗口高时自己滚动）；更窄时点一行在弹窗里看详情（标题“红包详情 / 用户详情 / 付款详情”，右上角 × 关闭）。选中的行变白。一次 20 条，滚到底自动加载（第 1 节）。
- **筛选在地址里**（`?status=`、`?state=`、`?mode=`、`?anomaly=`、`?author=`、`?activity=`、`?recipient=`；搜索词 `?q=` 只在打开时读一次）：概览的卡片、用户详情的按钮都能直接打开筛好的列表；从别处带来的筛选显示成可以删掉的标签（“发红包的人：小满 ×”；地址里的编号不完整时写“编号无效”，不参与筛选）。操作记录的搜索和日期不进地址。
- **搜索由服务器做**（和生产一样）：输入停顿 0.3 秒后查，新结果到之前旧的变淡留着；标题、用户名和昵称按包含匹配，编号和链接要完整才匹配。

**概览**

- 标题下一行：上次读取的时间 · 生产环境 · 每 30 秒自动刷新；右侧“刷新”（第 1 节）。
- **需要留意**：八张卡片（宽窗口一行四张），数字为零时是灰色，不为零时变红（结果未知、异常待处理、维护失败）或琥珀（其余）并带图标（第 1 节“不只靠颜色”），可以点，打开对应的筛选列表。前六项沿用生产的阈值：付款结果未知、付款异常待处理、付款等待超过一小时、开奖等待超过十分钟、任务未投递超过十分钟、维护失败或超过十五分钟未更新；后两项是🐟额的：卡住的转出、要看一下的转入（打开🐟额页签的待处理）。上面一句“N 项不为零”。
- **总量**：用户、红包（含草稿数）、付款（未确认几笔）。
- **运行许可**：真实红包开放、真实领取、真实付款、限时开奖，各自“允许 / 不允许”和不允许的原因（生产的环境变量名写成中文，如“付款发送已暂停”）；本站待投递任务；队列积压（“未接入”，和生产一样）。
- **未确认的付款**：按状态一行（模拟付款标“模拟”），笔数和最久等了多久。
- **维护任务**：四个定时任务最近一次的状态、开始时间和用时；失败写“执行出错”，超过十五分钟没更新也写明，没跑过写“暂无运行记录”。

**红包**

- 搜索：标题、红包 ID、表情码、红包链接（它的 📝 📊 🧾 页也行）或帖子链接；“开奖异常”开关（开奖等待超过十分钟，和概览那张卡片一样）；状态：全部 / 草稿 / 进行中 / 已结束 / 已归档。
- 每行：小红包图标、标题、状态、发红包的人、参与 x / y（限时开奖写“报名 N 人”）、创建时间。
- 详情：标题和规则，红包 ID（可复制）、表情码地址、参与方式（口令几个，只给个数）、份数或报名、状态、开奖状态（中文：等待开奖 / 开奖中 / 已开奖 / 无人报名，生产显示英文枚举）、关联帖子、付款（几笔 · 未确认 · 异常待处理）、开放和截止时间（草稿按时长截止的写“开放后开始计时”）；“打开红包”“看它的付款”（有付款才显示）。

**用户**

- 搜索：用户名、昵称、本站 ID 或 LINUX DO ID；状态：全部 / 可用 / 停用。
- 每行：头像、昵称 @用户名、管理员 / 停用标签、LINUX DO ID、最近登录。
- 详情：本站 ID（可复制）、LINUX DO ID、状态（停用写明“LINUX DO 账号已停用”：状态在每次登录时跟随论坛）、身份、注册、最近登录、发出的红包、领取和报名次数、收到的付款笔数、商户数；“查看发出的红包”“查看收到的付款”（有才显示）。没有停用 / 启用 / 设管理员的按钮：生产没有这些操作，管理员来自部署配置。
- 详情最下面是**🐟额**：可用（有转出中时加一行）、转入资格（“@邀请人 邀请，… 接受”或“没有”）、最近 5 条明细，和“调整🐟额”。调整是叠层弹窗：先选补加或扣回，再填数量和原因；原因这个人能在自己的明细里看到；只能追加，不能改或删；扣回可以让可用变成负数。管理员不能调整自己，看自己时没有这个按钮。

**付款**

- 搜索：本站业务号、任务 ID、上游交易号、红包或商户 ID；状态：全部 / 待发放 / 发送中 / 核对中 / 等待恢复 / 异常待处理 / 已发放 / 未发出（写在地址里，概览的“付款异常待处理”就是打开这个筛选）；模式：全部模式 / 真实 / 模拟；异常：结果未知 / 等待超过一小时 / 未投递超过十分钟（单选，可取消；异常待处理本身就是一种状态，不在这里重复）。
- 每行：收款人头像和昵称、红包标题、业务号前几位、创建时间、金额、状态。
- 详情：金额和状态、状态说明（和作者看到的一样）、收款人（含 LINUX DO ID）、订单用户名（领取时的快照，改了名写“现在是 @…”）、红包、付款商户（订单用的是更换前的应用时注明）、付款模式、本站业务号（可复制）、任务 ID、上游交易号、订单证据、结果未知、下一步（核对原订单 / 等待按计划发送 / 无待执行操作）、下次处理、发送 / 查单次数、创建和确认时间；下面是“经过”时间线和处理记录（一项一行，带每次请求的 HTTP 状态，超过 20 条时只列最近 20 条）；“查看这个红包”。
- 没有任何操作：重试和查单是系统自己做的；生产的原单恢复授权只在命令行工具里。
- **🐟额转出**也是付款（平台应用付给本人的 Credit 账户）：行里写“🐟额转出”，没有作者视角，详情最上面说明以🐟额里的那笔转出为准，带“在🐟额里看 ›”。“未发出”只出现在转出上（Credit 明确拒绝、没有生成订单），是终态，不算未确认，也不计入等待超过一小时。

**🐟额**

- 上面一块汇总，宽窗口一行三项：代存合计（小字“Credit 账户里至少要留这么多”）、可用为负（人数和合计，负数不抵别人的）、今天到账（笔数）、还没到账（笔数，小字“N 笔要看一下”或“都正常”）、转出中（数量和笔数）、今天转出（已发放的数量和笔数）。还没有平台应用、或凭证没通过时，最上面一条琥珀提示和“网站设置 ›”。账目自己对不上时（明细、锁定和转出之间，正常是 0），红色提示“账目有 N 处对不上”，先关掉转入和转出再查。
- 分段右边一个“邀请”按钮，点开是模态框，顶上分“受邀的人 / 邀请记录 / 通用链接”，每次打开先是受邀的人。列表一次 20 条，滚到底再加载。
  - **受邀的人**：所有能转入的人，每人写昵称和 @用户名、谁邀请的、哪天接受、他又邀请了几个人，右边是🐟额可用；点一行去“用户”，搜到这个人；末尾“共 N 人”。
  - **邀请记录**：每条写谁邀请了谁（接受后是那个人现在的用户名）、发出和接受的时间、状态（待接受 / 已接受 / 已过期）。
  - **通用链接**：一句“不写用户名，谁拿到都能接受，适合发到群里。”，“最多几个人用”（1–1000 人）和有效期“1 天 / 7 天”，“生成链接”。生成后换成链接和复制按钮，写明“链接只显示这一次，关掉弹窗前先复制好。”和“再生成一条”；切到别的页再回来链接还在，关掉弹窗就没了。下面“生成过的链接”：每条写已用几人 / 共几人、谁生成、什么时候、什么时候到期（停用的写谁、什么时候停用）和状态（有效 / 已用完 / 已过期 / 已停用）；有效的有“停用”，叠层确认“停用这条链接？”，说明已经接受的人不受影响。
  - 通过通用链接加入的人，在受邀的人和用户详情里写“@管理员 的通用链接邀请”。
- 分段切换写在地址里（`?status=`）：待处理（带个数）/ 转入 / 转出 / 调整。列表 + 详情，和上面三页同一套。
  - **待处理**：转入和转出混在一个列表里，按时间排。转入是订单信息不符、到账后查单不再成功（“查单不再成功”），以及最近一次查单凭证被拒的；转出是发放中、而付款在等额度、等平台账户、等凭证、结果不明、Credit 回复对不上，或者申请超过半小时还没发完的。
  - 转入每行：头像、昵称、时间（有标记时跟着标记）、到账数量、状态。
  - **转入详情**：标记的说明（怎么去 Credit 后台核对、退款后怎么扣回）；用户、Credit 扣除、流转费、到账、本站业务号（可复制）、Credit 订单号、平台应用（Client ID · 凭证第 N 版）、邀请人、下单和到账时间（管理员确认的写明是谁、原因）；“查单”，没到账时还有“确认到账”；下面是查单记录（谁触发、结果、HTTP 状态）。
  - **确认到账**：叠层弹窗，写明把多少 🐟 记进谁的🐟额，原因必填，记在这笔转入上；和自动到账走同一条路，不会重复到账。
  - 转出每行：头像、昵称、“转出 · 时间”（发放中时跟着在等什么：排队 / 等额度 / 等平台账户 / 等凭证 / 核对中 / 对不上）、扣除数量、状态（发放中 / 已发放 / 未发出）。
  - **转出详情**：只看，没有操作（发放和查单是付款队列自己做的）。在等的时候，最上面一条琥珀提示写明原因和该怎么办（额度几点后自动继续；平台账户补足 LDC；凭证去网站设置；对不上去 Credit 后台核对，这期间 🐟 一直锁着、不会重发）。下面是用户、收款账户（@用户名 · 社区 ID）、扣除、分发费、预计到账、本站业务号（可复制）、Credit 订单号、平台应用、申请时间、发放时间或未发出的原因；发放记录（每次发送和查单的结果、原因、HTTP 状态）；“在付款里看 ›”。
  - **调整**：所有人的调整，每行是谁、补加或扣回、原因、操作者和时间。

**网站设置**

三组，各自保存、各有版本号：

- **口令尝试间隔**：起始页（默认 5 秒）、红包页（默认 2 秒），1–3600 的整数；说明“同一个人两次提交口令之间至少隔多久。起始页查口令和红包页领取分开计算；无需口令的红包按红包页的间隔”。
- **🐟额**：转入开关（关掉后不能新建，已建的照常查单到账）、转出开关（关掉后不能新申请，已申请的照常发放）、🐟额红包开关（关掉后不能新建、开放🐟额红包，已经开放的照常能领、照常退回；[🐟额设计](../balance-design.md) 第 14 节）、流转费率和分发费率（0–50 的整数，要和平台账户在 Credit 的等级一致）、单笔转出上限（1.00–2000.00 🐟，要低于平台账户每天能付出的 LDC）。谁能转入不在这里管，靠邀请（第 14 节）。
- **平台应用**：名称、Client ID、密钥（不显示，留空就保留），凭证状态和“重新检查”；保存后自动检查。说明写明它是 Credit 里单独新建的集市应用，回调地址填 `http://localhost/`，关闭测试模式。还有转出在发放中时不能换 Client ID（“还有转出没发完，发完再换 Client ID”），换密钥可以。
- 保存（没有改动时不可点）、撤销修改；保存后“已保存，立即生效”。前两组下面一行“第 N 版 · 什么时候由谁修改 · 操作记录 ›”。

**操作记录**

- 搜索操作者（昵称或本站 ID），开始和结束日期。
- 每条：时间（精确到秒）、类型标签、改了什么（只列变化的项，生产直接打印英文键名）、“第 3 版 → 第 4 版”、操作者。
- 两种：“尝试间隔”（“起始页 8 秒 → 5 秒”）和“🐟额设置”（“转入 关 → 开”“流转费率 12% → 10%”以前的记录里还有“白名单 开 → 关”“白名单人数 1 人 → 3 人”，名单本身不列出）。两种的版本号各自计数。
- 记录一直保留。只有两种，不做类型筛选。平台应用的改动、调整和确认到账不在这里：调整在🐟额页签的“调整”里，确认到账写在那笔转入上。

## 11 结果页 `/🔑/`、`/💬/`

口令在指令框里匹配到多个红包、帖子关联了多个红包时打开（地址见 [03](03-commands-routes.md) 第 6 节），和别的列表页同一套框架（第 1 节）。

- **标题**：口令多匹配是“选择红包”，下面一行“口令 xxx 匹配到 N 个红包”；帖子是“帖子里的红包”，下面一行“帖子 N · M 楼，共 N 个红包”和一句“每个红包都写明了发红包的人；和帖子关联不代表楼主认可。”（生产的说法），右侧“查看社区帖子 ↗”。

- **结果只给查的人看**：别的账号打开，或结果已经读不到，显示“查找结果已失效”“请重新输入口令。”。
- **帖子只关联一个红包**：直接替换到那个红包，不论是从指令框来还是直接打开地址；一个都没有时显示“未匹配到红包”“这个帖子里还没有红包。”。
