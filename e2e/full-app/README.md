# 完整应用端到端测试

运行 `bun run test:e2e:full-app`。该命令与通常的界面测试分开运行，不拦截任何 `/api` 业务请求。

浏览器请求经过实际 Web Worker、Service Binding、Hono API、独立本地 D1，以及实际 SQLite ActivityDO / MerchantDO 和 Queue。所有数据库迁移在新的临时数据库中执行。用户、会话、商户、活动、库存、领取和付款任务由正常应用流程创建，不直接插入测试业务记录。测试只初始化平台运行控制。

测试运行器从实际 Worker 入口构建独立产物，读取显式提供的虚拟配置，不加载 `.env`、`.dev.vars`、部署配置或现有 `.wrangler/state`。`127.0.0.1:4193` 提供应用，`4194` 是测试进程内的只读就绪和状态观察接口；两者均随测试停止。所有临时构建及持久数据位于系统临时目录，结束后清理。

OAuth 授权页面在浏览器中模拟，回调、一次性 state 校验、服务端 token/profile 请求、D1 用户持久化及会话 Cookie 由正常代码执行。测试使用作者账号 ID `730001`、三个参与账号 ID `730002` / `730003` / `730004` 和虚拟 Connect 凭证；改名情形保持 `730002` 不变，通过再次正常登录同步新用户名。LDC 分发与查单仅替换 Worker 的上游 HTTP 传输：真实协议编码、凭证检查、领取事务、Outbox、Queue、发送占用、查单核对和付款记录均保持实际实现。未列入测试协议的任何 Worker 外部请求被拒绝，测试不会访问真实 OAuth 或 LDC 服务。

普通真实模式活动使用生产运行策略和当前商户规则，不注入活动或付款绕过许可。浏览器创建固定金额活动，领取者通过正常接口获得 `0.10` 的付款任务，运行器的虚拟上游确认该订单。观察接口核对任务身份、收款账号、固定金额、发送次数、Outbox 投递与上游订单一致。模拟结果不能作为真实分发、线上幂等或结算能力的证明。

测试覆盖登录和退出、CSRF/来源拒绝、OAuth 回调重放、文本创建/开放/错误口令/成功领取、私有历史、跨账号权限、隐藏信息、幂等重复领取，以及普通真实模式领取到异步付款确认、作者自领拒绝和窄屏页面。

定时抽奖使用同一独立运行环境，显式开启定时开奖能力，并从浏览器表单创建活动。验收覆盖 M 大于、等于和小于中奖名额 N、无人数上限的倒计时、无人报名结束，以及人数不足 N 时奖池全部发完或保留未中签份额。报名阶段核对一人一份资格、继续解出其他口令、提交重放、我的参与历史，并确认零领取、零付款任务与零 Outbox；开奖后核对赢家和未中奖记录、实际付款人数、金额总和、Outbox 投递、固定订单号，以及报名后改名时使用最新同步的收款用户名。

倒计时情形在报名后离开活动页面，只通过 `4194/state` 读取数据库状态，验证真实 ActivityDO Alarm 能独立触发开奖和正常付款链路；运行器没有创建业务记录、触发开奖或修改活动状态的控制接口。人数达到 M 的情形通过最后一名参与者的正常报名触发。随机赢家和金额不预先固定，断言围绕资格唯一性、赢家人数、最小金额、奖池总和与重放后的持久结果。

本测试使用本地 HTTP，因此验证 HttpOnly、SameSite、会话摘要及 Cookie 转交；生产 HTTPS 的 Secure Cookie 仍由后端测试及部署验收覆盖。虚拟 LDC 订单保存在测试进程内存，不能用于证明进程重启后的上游持久性；DO 重启、网络故障、重复队列与订单恢复另有 D1/DO 测试。不要将这些测试文件导入应用 Worker 或部署包。
